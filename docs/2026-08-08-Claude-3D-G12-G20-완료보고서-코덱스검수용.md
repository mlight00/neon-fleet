## 2. 특히 검수받고 싶은 지점

### 2.1 §G-19 — `chase3dEnabled` 기본값을 뒤집었다 (영향 범위가 가장 넓음)

```js
// before: ?chase3d=1 이 있어야 ON
return new URLSearchParams(search).get('chase3d') === '1';
// after: 기본 ON, ?chase3d=0 만 해제
return new URLSearchParams(search).get('chase3d') !== '0';
```

- **배경**: 배포판(포털)은 `index.html` 을 쿼리 없이 연다 → 조건이 영영 성립하지 않아 3D 가 한 번도 안 켜졌다. GLB 20MB 를 넣고도 배포판은 2D 로만 돌았다.
- **검수 요청 2**: 이 뒤집기로 인해 **의도치 않게 켜지는 경로**가 없는지 봐 주십시오. 특히
  - Prolific/플레이테스트 측정 모드, `coreLoop`/`campaign25` 하네스, `fleetlab`/`bosslab`
  - 검사실(`chase3dLab`)·검증장면(`chase3dTest`)은 여전히 `chase3d=1` **명시**를 요구하도록 남겼는데, 그 게이트가 실제로 유효한지
  - 저사양·WebGL 미지원 환경에서 폴백이 확실한지(§3.3)

### 2.2 §G-16 — 모델 준비 게이트 (개체가 사라질 수 있는 지점)

```js
// main.js put3D
if (chase3d && chase3d.swarmReady && !chase3d.swarmReady(key)) return null;
// renderer
ctl.swarmReady = (k) => !!(eswarm[k] && eswarm[k].meshes && eswarm[k].meshes.length);
```

- **배경**: 3D 로 올렸다고 표시(`_in3dMap` 스탬프)하면 2D 가 그 개체를 스킵한다. 모델이 아직 없으면 **어디에도 안 그려져 개체가 사라진다.**
- **검수 요청 3**: GLB 가 **비동기**로 로드되는 동안(수 프레임~수 초) 개체가 깜빡이거나 사라지는 창이 없는지, 로드 실패 시 영구적으로 2D 로 남는지 확인해 주십시오.

### 2.3 §G-13/§G-20 — 발사체 배치 수학

```js
// placeShots: 화면 위치는 2.5D 투영(o.sx/o.sy) 역투영, 깊이·자세는 월드
const depth = Math.min(80, Math.max(3.5, (sqy - o.wy) * SCALE_Z + CAMERA.chase.dist));
_sEul.set(0, Math.PI - (o.wob || 0), 0);
const mul = o.mul || 1;
const k2 = minPx > 0 ? Math.max(1, (minPx * depth) / (fpx * len * mul)) : 1;
```

- 설계 근거: 화면 위치를 월드로 따로 계산하면 가로 퍼짐이 1.5배가 돼(실측 396px vs 270px) 탄이 적을 빗나가 보인다. 그래서 **위치는 화면 정합, 깊이·자세만 월드**.
- `Math.PI - wob` 인 이유: 절차 발사체 지오의 노즈가 −z 이고(`loftProjectile` 주석), 추적 카메라 기준 3D +X 가 화면 왼쪽이라 진행각 부호를 뒤집어야 한다.
- **검수 요청 4**: 부호·축 규약이 맞는지, `depth` 클램프(3.5~80)가 근/원거리에서 파탄나지 않는지, `k2` 하한이 위계를 뒤집지 않는지 봐 주십시오.
