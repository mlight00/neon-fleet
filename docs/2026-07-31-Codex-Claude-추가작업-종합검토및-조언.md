# Claude 추가 작업 종합 검토 및 다음 조언

- 검토일: 2026-07-31
- 대상: `claude/neon-fleet-analytics-stage1` 작업 트리
- 주요 범위: AURORA 절차적 3D, B1/B2/B4 3D 적, 투사체·픽업 3D, 워프 배경, 4단계 줌, 부분 추종 카메라
- 검토 원칙: 게임 소스·배포 상태는 바꾸지 않고 완료보고서, 실제 소스, 자동 테스트, 빌드, 로컬 Chrome을 대조했다.

## 1. 최종 판정

**기술 수직 시제품으로는 조건부 합격이다.**

처음의 기본 도형 조립식 3D보다 AURORA의 함선 정체성, 재질, 후면 원근감이 크게 좋아졌다. 실제 게임 경로에서 220% 전환, B1 스웜 표시, WebGL 장애 후 2D 복귀도 정상 동작했다.

그러나 지금은 새로운 모델을 더 만드는 단계가 아니다. Claude가 승인 전 확장 금지 범위를 넘어 B1·B2·B4·탄환·픽업까지 한꺼번에 확장했고, 최종 통합 상태의 성능·모바일·포털 검증과 Git 정리가 뒤따르지 못했다. **여기서 기능 확대를 멈추고 현재 수직 시제품을 하나의 검증 가능한 변경 묶음으로 정리해야 한다.**

공개 기본 URL은 여전히 `?chase3d=1` 없이 3D를 켜지 않으므로, 이번 판정은 “출시 승인”이 아니라 “기술 방향 보존 승인”이다.

## 3. 잘한 점

1. **AURORA의 품질은 분명히 개선됐다.** 원본 평면 실루엣을 수치화하고 loft 선체, 절차적 PBR 텍스처, IBL, LOD를 결합한 접근은 이전 기본 도형 조립보다 훨씬 설득력 있다.
2. **게임 판정은 계속 2D가 담당한다.** Three.js가 충돌·스폰·보상·RNG를 소유하지 않아 3D 실패가 게임 진행 실패로 번지지 않는다.
3. **실패 복귀가 실제로 작동한다.** 렌더러가 0을 반환하면 2D 스킵 게이트가 해제되어 기함과 적이 다시 2D로 표시된다.
4. **반복 적을 InstancedMesh로 묶었다.** B1/B2/B4의 마리 수에 비례해 draw call이 폭증하지 않는 구조다.
5. **기본 공개 경로는 아직 안전하다.** 3D는 쿼리 플래그 뒤에 있어 현재 공개판에 자동 노출되지 않는다.

## 4. 중요 발견사항

### P1 — 작업물이 Git에 사실상 저장되지 않았다

현재 브랜치 HEAD는 `origin/master`와 같은 `3e178bc`다. 검토 시작 시 그 뒤 작업은 **추적 파일 15개 수정 + untracked 상태 항목 105개**로 남아 있었다. 루트에는 `scratch_b1_probe.mjs`, `scratch_capsrv2.mjs`, `scratch_geo_probe.mjs`, `scratch_nocache_srv.mjs`도 남았다.

기능보다 먼저 해야 할 일은 작업 유실 방지다. 임시 파일을 정리하고, 문서·테스트·런타임 파일을 분류한 뒤 전용 브랜치에 작은 체크포인트 커밋으로 나눠야 한다. 지금 상태에서 다른 대형 작업을 시작하면 되돌리기와 원인 추적이 매우 어렵다.

### P1 — “3D 검증 장면”이 최신 3D를 검증하지 않는다

`js/main.js`는 `chase3dTest=1`일 때 `hero: !CHASE3D_TEST`를 전달한다. 결과적으로 이 모드는 최신 AURORA/B1/B2/B4가 아니라 `createLegacy3D()`의 예전 조립식 장면을 띄운다.

실제 Chrome에서도 `?chase3d=1&chase3dTest=1`은 분홍 구체와 기본 도형 함선이 있는 구형 화면이었다. 이름과 UI는 최신 3D의 결정적 검증 장면처럼 보이므로 Claude나 사람이 잘못된 장면을 기준으로 QA할 수 있다.

권장:

- 최신 경로용 `chase3dHeroTest=1` 결정 장면을 별도로 만든다.
- 구형 장면은 `chase3dLegacy=1`처럼 명시적으로 이름을 바꾼다.
- 최신 결정 장면에서 AURORA+B1+B2+B4+소품, context loss, 100/150/200/220%, 좌·중·우 이동을 한 화면에서 재현한다.

### P1 — 최종 통합본의 출시 검증이 아직 없다

완료보고서는 스스로 다음을 미검증으로 적었다.

- 실제 rAF 지속 FPS
- 진짜 모바일 기기
- CrazyGames `dist`에서 hero 런타임

게다가 보고서의 programs 3, geometries 16, textures 19는 AURORA 단독 시점 수치다. 최신 통합 경로는 로컬 관측상 6/33/28이다. B1/B2/B4/소품을 모두 넣은 뒤의 최종 900프레임 p50/p95/p99, shader 증가, 메모리 왕복, 실제 모바일 FPS를 다시 측정해야 한다.

849개 테스트는 가치가 있지만, 3D 배선 테스트 상당수는 소스 문자열·정규식과 지오메트리 수학을 검사한다. 849개의 실제 플레이 상황을 검증했다는 뜻은 아니다.

### P2 — 완료보고서가 현재 상태와 모순된다

동일 보고서 앞부분은 다음과 같이 적혀 있다.

- 817/817 테스트
- programs 3 / geometries 16 / textures 19
- B1/B4/B8 신규 제작 안 함
- 승인되면 B1 한 종을 다음에 제작

하지만 부록에는 이미 B1·B2·B4·소품 실전 투입과 849/849가 이어진다. 이 문서는 시간순 작업 일지로는 쓸 수 있어도 “최종 완료보고서”로는 신뢰하기 어렵다.

권장:

- 부록을 계속 붙이지 말고 최종 통합 보고서를 새로 만든다.
- “현재 적용”, “개발 전용”, “미검증”, “출시 전 필수” 네 구역으로 분리한다.
- 자동 측정, 실제 브라우저 측정, 육안 평가, 추론을 명확히 표기한다.

### P2 — 렌더 상태가 원본 게임 객체에 기록된다

`js/chase3d-renderer.js`는 “게임 상태를 읽기만 한다”고 선언하지만, `js/main.js`의 수집 단계는 적·픽업·탄환 원본 객체에 `_in3d` 프레임 스탬프를 쓴다.

현재 구현은 `t3d=0`이면 2D 스킵을 해제하므로 즉각적인 게임 규칙 버그는 확인되지 않았다. 그래도 렌더 전용 상태가 게임 객체 안으로 들어가면 저장·복제·디버깅·향후 직렬화와 결합될 가능성이 있다.

권장:

- 재사용 가능한 sidecar `Set`/맵 또는 렌더 수집 버퍼에서 3D 포함 여부를 관리한다.
- `_in3d`가 충돌, 저장, RNG, 업데이트 결과에 절대 나타나지 않는 회귀 테스트를 추가한다.

### P2 — 진단 정보가 확장 범위를 따라가지 못했다

`chase3d.info()`는 `b1Count`, `b2Count`만 내보낸다. B4와 8종 소품의 count가 빠져 있어 “모델은 만들어졌지만 실제 배선이 안 된” 문제를 오버레이에서 바로 확인할 수 없다.

`b4Count`와 소품별 활성 수, 전체 3D 교체 수, 2D 폴백 수, cap 초과 수를 표시해야 실제 전투 QA가 쉬워진다.

## 5. 화면 품질 조언

### AURORA

현재 AURORA는 보존 가치가 있다. 함선으로 읽히고, 흰 장갑·금색 척추·청록 엔진의 계층도 명확하다.

다만 후미 화면에서 금색 원형 반응로가 선체보다 먼저 보일 정도로 크다. 반응로 지름을 약 10~20% 줄이고, 상판의 검은 패널 대비와 반복 무늬를 완화하면 “거대한 원형 장치가 붙은 배”보다 “하나의 기함”으로 더 잘 읽힐 가능성이 높다.

### B1/B2/B4

개별 모델은 이전 기본 도형보다 훨씬 낫다. 하지만 B1 여섯 기가 근접했을 때 화면의 절반 이상을 덮어 회피 공간과 탄환 판독을 압박했다. 적이 클수록 위협감은 커지지만, 탄막 게임에서는 크기 자체가 판정 크기로 오해되기 쉽다.

권장:

- 한 화면 4기 초과 시 표시 크기를 단계적으로 낮추거나 근접 상한을 완화한다.
- 큰 3D 외형과 실제 피격 범위가 다르면 바닥 링·코어·위험 윤곽으로 판정 중심을 명확히 한다.
- B2/B4까지 더 확대하기 전에 B1 다수전의 가독성을 먼저 통과시킨다.

### 투사체·픽업

현재 실제 크기에서는 3D 탄환과 픽업이 대부분 청록 캡슐·노란 마름모처럼 보인다. 깊이감의 이득은 작고, 워프 선·적 모델과 함께 화면 정보량만 늘어난다.

**모든 것을 3D로 만드는 것이 최선은 아니다.** 기함과 핵심 적은 3D, 작은 탄환·픽업·레이저·위험 표시는 선명한 2D HUD/스트릭으로 두는 하이브리드가 이 게임에는 더 적합하다. 소품 3D는 A/B 토글로 가독성 우위를 증명하지 못하면 2D로 되돌리는 편이 낫다.
