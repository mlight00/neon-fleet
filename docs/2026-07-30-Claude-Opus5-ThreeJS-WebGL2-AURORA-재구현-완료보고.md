## 5. AURORA geometry 구조 (§6)

- **단일 진실 = A4 알파 디지타이즈**: 96행×반폭 런(함미 3분할 포함) 모듈 내장(`A4_ROWS`, 출처 주석). 실루엣은 설계상 보장 후 실측 검증.
- **주 선체**: 상(armorTop)/측(armorSide)/하(under) 3스트립 **다단 cross-section loft**(indexed BufferGeometry, station 128) — 데크 에지 챔퍼 루프·융기 내갑판 스텝·킬 V. 크리스=스트립 경계 정점 분리(하드 노멀). `BoxGeometry` 주선체 사용 없음(§0.6).
- **주익**: 원본 외곽 폴리곤(노치 실측 포함) → beveled Extrude + 루트→팁 두께 테이퍼. **꼬리붐 쌍**: 실측 둘째 런 추적 육각 loft. **금색 척추**: 노즈 다트→반응로→함미 팁 연속 오각 loft. **반응로**: 환형 링 스택(구멍 있는 lathe)+기어치+방사 스포크 24+최상단 백색 코어·금 림(§6.4 허용부). **함몰 8각 패널 8**(프레임+함몰면+청록 틱, 실표면 안착). 엔진: 이중 벨 lathe 쌍발+베르니어 3(함미 하부 수납). 그리블 90(시드·회피영역).
- **재질 버킷 병합** → **AURORA 전체 draw calls 8** 〔브라우저〕. 명명 노드(엔진L/R·베르니어·반응로·선수/선미).

## 6. PBR 맵 생성 방식 (§7)

- **CPU TextureForge(순수 typed-array)** — 브라우저·Node 동일 결과, `Math.random` 0회〔자동 AM-07〕. 시드 mulberry32.
- 맵: albedo(sRGB)+normal(높이→Sobel)+**ORM 패킹**(r=AO/g=rough/b=metal 한 장)+emissive. armorTop 512²(모바일 256²), 나머지 256². **Nyquist 상한**(최소 파장 6texel).
- plan 공간 UV 통일 → A4 배치 그대로 플레이트 벽돌 그리드·실루엣 비례 다크 프레임 밴드·어깨 경계선 도장. A4 는 팔레트·배치 근거+IoU 정답으로만 사용(전면 스트레치 데칼 없음, §7.2).
- 색관리(§7.3): `SRGBColorSpace` 출력+`ACESFilmicToneMapping`(노출 1.06~1.12), albedo/emissive 만 sRGB. **절차적 equirect(64×32)→PMREM IBL**(금속 흑사 방지) + key(웜)/fill(쿨)/rim/hemi+**함미 보조광**. 후처리 파이프라인 없음 — 발광은 emissive 로 형태 유지(§7.4), bloom 미구현(한계 §14).

## 14. 하이브리드·수명주기 (§9·§10.4) 〔브라우저+자동〕

- 3D 레이어=AURORA 만. 적·보스·게이트·픽업·총알·경고·**드론** 전 구간 RC2. HUD 2D.
- **기함 하드 컷(겹침 0·공백 0, 부록 B-1 최종형)**: 2D 기함 본체는 t<0.5 에서 α=1, 3D 캔버스는 t≥0.5 에서 완전 불투명 — 중간 페이드 자체가 없어 **어떤 t 에서도 "정확히 한 척"**(HW-02 가 a2+a3=1 을 전 구간 증명). 스왑 순간은 워프 플래시가 은폐. 피격핵·판정·입력은 기존 유지(§9.3, 입력에서 3D 개입 제거〔자동 HW-04〕).
- **부분 추종(이사)**: 추적 시점 기준점을 "화면 중앙 + 기함 이탈×0.42"로 — 기함이 화면 안에서 실제로 좌우 이동해 보이고, 3D 카메라도 같은 화면 픽셀만큼 트럭 이동(HW-09)해 2D 피격핵·드론과 정합. followFrac=0 이면 이전(기함 화면 고정)과 동일.

## 15. 남은 한계 / 검증하지 못한 항목

1. **rAF 지속 FPS 미측정**(pane 비표시 → rAF 정지) — 프레임 비용 분포로 대체, 검사실 오버레이로 실기기 확인 가능.
2. **bloom 미구현** — 발광은 emissive+ACES 로 처리(§7.4 "후처리 없이도 형태" 충족). 승인 후 선택 검토.
3. 원본 A4 의 **미세 데칼 밀도**(작은 문양·경고선)는 절차 텍스처가 단순화 — 참고사례도 자인한 절차 생성의 천장.
4. 척추 세그먼트 조인트가 하이라이트에서 약한 구슬감(원본도 분절 척추라 정체성 훼손은 아님).
5. **스왑 지점(t=0.5, 정확히 180%)** 에서 2D→3D 형태가 한 프레임에 교체됨 — crossfade·페이드를 전부 없앤 대가로, "두 척 동시 표시 절대 불가 + 함선 소멸 구간 불가"(이사 3회 지적)를 우선한 의도적 트레이드오프. 교체 순간은 0.3초 워프 플래시(청백 섬광 링)로 연출해 팝을 가린다. reduced-motion 환경은 플래시 없이 즉시 컷.
6. 실기기(진짜 모바일 하드웨어) 미검증 — 데스크톱 GPU 의 뷰포트 시뮬레이션임.
7. 검증 못한 항목: 실 rAF FPS(1), 실기기(6), CrazyGames 빌드의 hero 실행(포털 dist 로컬 서빙 미실행 — 빌드 검사·크기만 확인).

## 부록 A — 사용자 실브라우저 검증에서 발견·수정한 결함 2건 (2026-07-31)

사용자 실측("배경과 BGM만 보임") 제보 → **사용자의 실제 Chrome 에 직접 접속해 픽셀 단위로 재현·수정·재검증**:

1. **타이틀 메뉴 전체 가림(치명)** — `#stage` 가 flex 라 **flex 자식은 `position:static` 이어도 z-index 가 적용**됨. 3D 계층 부트스트랩이 `#game` 에 z-index:1 을 주면서 불투명 게임 캔버스가 `#overlay`(z auto) 메뉴를 통째로 덮었다. `elementsFromPoint` 로 확정 → **#overlay z-index:5** 로 수정. 재발 방지 테스트 HW-08.
   *교훈: 이전 QA 는 캔버스를 수동 합성해 캡처했기 때문에 실제 DOM 합성의 z 순서 문제가 보이지 않았다. DOM 겹침 검증은 실브라우저 `elementsFromPoint`/실스크린샷이 필수.*
2. **검사실 캔버스 60fps 숨김 충돌** — 메인 게임 rAF 의 draw() 가 lab 모드에서도 `#game3d` 를 매 프레임 숨김(검증 환경은 rAF 정지라 미발현). draw 의 3D 캔버스 관리에 `!CHASE3D_LAB` 가드 추가.
