## 2. 원인 — 길이가 아니라 **방향** 문제였다

3D 차지 빔은 기함 앞쪽(+z)으로만 뻗는 원통이었습니다. 그런데 원근에서 +z 방향 직선은
**소실점으로 수렴**합니다. 소실점은 화면 상단이 아니라 그보다 한참 아래에 있습니다.

480×800 · 추적 시점(t=1) 실측:

| 지점 | 화면 y (0 = 상단) |
|------|------|
| 기함 노즈 (빔 시작) | 561 |
| 빔 끝 — 기존 길이 110 | 227 |
| 빔 끝 — 길이를 400으로 늘려도 | 197 |
| **소실점 (길이 무한대)** | **184** |
| 발사체가 도달하는 곳 | **0** |

- 빔 이동거리 334px ÷ 발사체 561px = **0.60** — 이사님이 보신 "2/3"의 정체입니다.
- **길이를 4배 가까이 늘려도 30px밖에 안 올라갑니다.** 소실점(184)이 구조적 상한이라
  어떤 길이로도 화면 상단에 닿을 수 없었습니다.

발사체는 왜 화면 상단까지 가느냐 — 발사체는 2.5D 화면 좌표를 재현해 배치되기 때문입니다.
그 3D 좌표는 `(0, 23.8, 77.4)`로 **y가 위로 올라간 곳**입니다. 추적 카메라가 아래를 내려다보니,
멀리 있으면서 화면 위쪽에 보이려면 실제로 높이 떠 있어야 합니다.

## 3. 조치

빔도 발사체와 **같은 광선 수학**을 쓰게 했습니다.

- 시작 = 기함 기수
- 끝 = `placeOnRay(camera, 기수의 화면 x, 화면 최상단, 깊이 80)`
  — 발사체가 화면 상단에 놓이는 바로 그 3D 지점
- 원통을 두 점 사이에 배치(위치=중점, 회전=두 점 방향, 길이=거리)

깊이 상수는 발사체와 **공유**합니다(`SHOT_DEPTH_MAX = 80`). 두 값이 갈라지면 같은 문제가 재발합니다.

곁가지 두 가지가 따라왔습니다.

- 빔을 기함 리그(`flagRig`)에서 빼내 **씬 직속**으로 옮겼습니다 — 월드 좌표로 직접 배치해야 하기 때문입니다.
  발사된 빔은 기함 피격 흔들림을 따라가지 않는 편이 자연스럽기도 합니다.
- 집속 연출(`chargeRig`)과 빔의 표시 조건을 분리했습니다 — 이전엔 `chg > 0 || _lanceT > 0` 하나로 묶여 있었습니다.
- dispose에 차지 연출 메시(집속 코어·헤일로·빔) 정리를 추가했습니다. 스웜이 아니라 개별 Mesh라
  기존 `disposeSw`가 닿지 않던 자리입니다.

## 4. 검증

### 자동 테스트

```
893 pass / 0 fail   (892 → 893, G25-LANCE 1건 추가)
```

`G25-LANCE`가 회귀를 막습니다 — 실제 게임 카메라를 만들어

1. 옛 방식은 길이를 늘려도 소실점을 못 넘는다
2. 새 방식은 빔 끝이 화면 최상단(오차 1px 미만)에 닿는다
3. 도달점은 기수보다 확실히 위 — 순수 +z로는 갈 수 없는 자리다
4. 사거리 비율: 옛 방식 < 70%, 새 방식 > 99%
5. 배선: 빔이 씬 직속이고, 깊이 상수를 발사체와 공유한다
