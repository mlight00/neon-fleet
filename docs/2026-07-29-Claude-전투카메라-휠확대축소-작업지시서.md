## 0. 목표

플레이어가 RPG 게임처럼 마우스 휠로 전투 화면을 확대·축소하여 기함·드론·순양함의 성장과 외형 변화를 직접 자세히 볼 수 있게 한다.

이 기능은 게임 규칙의 크기를 바꾸는 기능이 아니라 **시각적 전투 카메라**다.

- 휠 위: 확대
- 휠 아래: 축소
- 함선·적·탄환·아이템·전투 이펙트는 같은 비율로 확대·축소
- HUD·일시정지·드래프트·결과창·컷신은 고정
- 충돌 범위·속도·스폰·피해량·난이도는 변경하지 않음

사용자가 이 기능을 원하는 핵심 이유는 단순한 시야 조절보다 다음에 있다.

> 기함 승급, 드론 증가, 순양함 편대, 무기 진화 등 자신의 함대가 성장한 모습을 더 크게 보고 소유감과 성장 만족을 느끼기 위해서다.

## 3. UX 사양

## 3.1 배율

| 항목 | 값 |
|---|---:|
| 기본 | 100% |
| 최소 | 85% |
| 최대 | 130% |
| 휠 1단계 | 5% |
| 키보드 축소 | `-` |
| 키보드 확대 | `+` 또는 `=` |
| 초기화 | `0` |
| 부드러운 전환 | 150~250ms |

상수는 한 파일에서만 정의한다.

```js
DEFAULT_ZOOM = 1.00
MIN_ZOOM = 0.85
MAX_ZOOM = 1.30
ZOOM_STEP = 0.05
```

부동소수점 누적 오차로 99.999% 같은 값이 생기지 않도록 5% 단위로 정규화한다.

## 3.2 휠 이벤트

마우스 휠은 다음 조건을 모두 만족할 때만 게임 카메라를 바꾼다.

- 포인터가 게임 캔버스 위에 있음
- 실제 전투 상태 `state === 'play'`
- 일시정지·드래프트·항로 선택·수리·결과 화면이 아님
- `Ctrl`·`Cmd` 키를 누르지 않음

구현 기준:

- `wheel` 리스너는 `{ passive: false }`
- 위 조건일 때만 `event.preventDefault()`
- `Ctrl/Cmd+휠`은 브라우저 접근성 확대이므로 절대 가로채지 않음
- 전투가 아닐 때는 페이지/오버레이의 정상 스크롤을 막지 않음
- 휠 한 번에 중복 리스너가 실행되지 않게 부팅·재시작 시 리스너 수를 확인

## 3.3 키보드와 접근성

마우스가 없는 사용자도 동일 기능을 사용할 수 있어야 한다.

- `-`: 5% 축소
- `+`, `=`: 5% 확대
- `0`: 100% 초기화
- 숫자 입력창이나 텍스트 입력에 포커스가 있다면 가로채지 않음
- `Ctrl/Cmd` 조합은 가로채지 않음
- `event.repeat`은 과도한 연속 변경이 발생하지 않게 안전하게 처리

일시정지 패널에 카메라 배율 행을 추가한다.

```text
Camera / 카메라
[ − ] [ 100% ] [ + ]
```

- 가운데 100% 버튼은 현재 퍼센트를 표시하며 누르면 초기화
- 세 버튼 모두 최소 44×44px
- 버튼 사이 간격 최소 8px
- 한국어·영어 문구 모두 지원
- 각 버튼에 명확한 `aria-label`
- 키보드 포커스 링 표시
- 모바일에서도 누를 수 있지만 핀치 제스처는 구현하지 않음

## 3.4 배율 표시

휠·키보드·버튼으로 배율이 바뀌면 화면 하단의 안전한 위치에 다음과 같은 작은 상태 표시를 700~900ms 노출한다.

```text
Zoom 115%
확대 115%
```

- 전투 HUD를 가리지 않음
- `pointer-events: none`
- 레이아웃을 밀지 않음
- 기존 네온 UI와 동일한 색·글꼴 사용
- 빠르게 휠을 돌릴 때 타이머가 중복 쌓이지 않고 마지막 값만 표시

## 3.5 모션 감소

`prefers-reduced-motion: reduce` 사용자는 확대 전환을 부드럽게 보간하지 않고 목표 배율로 즉시 이동시킨다.

그 외 사용자는 150~250ms 정도의 ease-out 느낌으로 전환한다. 매 프레임 고정 비율 보간이 아니라 `dt` 기반으로 처리해 주사율에 따라 속도가 달라지지 않게 한다.

## 4. 권장 구조

## P0-1. 순수 카메라 모듈

권장 신규 파일:

```text
js/camera-zoom.js
tests/camera-zoom.test.mjs
```

모듈은 DOM·게임 전역에 직접 의존하지 않는 순수 로직 중심으로 작성한다.

권장 책임:

```js
clampZoom(value)
normalizeZoom(value)
stepZoom(value, direction)
advanceZoom(current, target, dt, reducedMotion)
worldToScreenPoint(point, camera)
screenToWorldPoint(point, camera)
visibleWorldBounds(camera, viewport)
```

함수명은 코드 스타일에 맞게 조정해도 된다.

카메라 상태 예시:

```js
{
  current: 1,
  target: 1,
  min: 0.85,
  max: 1.30,
  anchorX: squad.x,
  anchorY: squad.y
}
```

현재 뷰포트용 `scale` 변수와 카메라 배율을 혼용하지 않는다.

- 기존 `scale`: 브라우저 픽셀 ↔ 논리 캔버스 크기
- 신규 `camera.current`: 논리 게임 세계의 시각적 확대 배율

가능하면 기존 `scale`을 `viewportScale`로 명확히 바꾸되, 변경 범위와 회귀 위험이 커진다면 이름을 유지하고 주석·테스트로 구분한다.

## P0-2. 카메라 기준점

확대 중심은 현재 함대 위치를 사용한다.

```text
anchorX = run.squad.x
anchorY = run.squad.y
```

이 방식의 의도:

- 확대해도 플레이어 함대의 화면상 위치는 유지
- 함선 자체가 중심에서 커지므로 성장 외형을 보기 쉬움
- 적·탄환·아이템은 플레이어와의 화면상 거리가 배율에 비례
- 기함이 갑자기 화면 중앙으로 순간 이동하는 느낌을 만들지 않음

매 프레임 카메라 배율을 갱신한 뒤 해당 프레임의 함대 위치를 기준점으로 사용한다.

런이 없거나 전투 상태가 아니면 카메라 변환을 적용하지 않는다.

## 5. 렌더 단계 분리

현재 `main.js`의 `draw()`는 뷰포트 변환 아래에서 배경·전투 세계·HUD를 연속으로 그린다. 월드 카메라를 적용하려면 다음 순서로 분리한다.

```text
1. 뷰포트 픽셀 배율 적용
2. 화면 고정 배경
3. 카메라 변환 시작
4. 전투 세계 렌더
5. 카메라 변환 종료
6. 화면 고정 이펙트·시네마 띠
7. HUD
8. DOM 오버레이
```

## 5.1 화면 고정 요소

다음은 카메라 배율을 적용하지 않는다.

- zone backdrop
- starfield
- 컷신과 섹터 클리어 일러스트
- 상하 시네마 띠
- 진행 바·보스 HP·기함/함대 HUD
- 무기·공명·내구도 HUD
- 일시정지·드래프트·수리·항로·결과 DOM
- 모바일 일시정지·차지 버튼
- 카메라 배율 표시
- 전체 화면 흰색 플래시

배경을 고정하면 85% 축소 시 월드 가장자리에 검은 공백이 생기지 않는다.

## 5.2 월드 카메라 적용 요소

다음은 같은 카메라 변환 안에서 그린다.

- 플레이어 기함·드론·순양함
- 캠페인 전투기 편대
- 일반 적·정예·보스
- 플레이어 탄환·적 탄환
- 크리스탈·코인·수송선·모듈·캡슐·게이트 등 전투 월드 개체
- 폭발 파티클
- 총구 섬광
- 진화 후광·링
- 월드 좌표에 뜨는 획득·승급·피해 텍스트

변환 순서:

```js
ctx.save();
ctx.translate(anchorX, anchorY);
ctx.scale(camera.current, camera.current);
ctx.translate(-anchorX, -anchorY);
drawWorld();
ctx.restore();
```

화면 픽셀 배율용 `ctx.setTransform(viewportScale, ...)` 뒤에서 위 변환을 중첩한다.

## 5.3 이펙트 분리 필수

현재 `createEffects().draw()`에는 월드 파티클·텍스트와 전체 화면 `flashV`가 함께 있다.

전체 `effects.draw()`를 카메라 안에 넣으면 흰색 플래시가 확대되거나 85%에서 화면을 다 덮지 못한다.

다음과 같이 역할을 분리한다.

```text
effects.drawWorld(ctx)
effects.drawScreen(ctx, logicalW, logicalH)
```

- `drawWorld`: parts, texts, rings, muzzle, halo
- `drawScreen`: `flashV` 전체 화면 플래시

기존 호출·테스트 호환이 필요하면 `draw()` 래퍼를 유지해도 된다. 월드 이펙트를 두 번 그리거나 플래시를 빠뜨리지 않는다.

## 6. 입력 좌표 역변환

현재 `input.js`는 캔버스에서 받은 `clientX`를 `0~logicalW`로 바로 변환한다. 카메라 확대 후 이 값을 그대로 쓰면 함선이 마우스와 어긋난다.

카메라 변환:

```text
screenX = anchorX + (worldX - anchorX) × zoom
```

역변환:

```text
worldX = anchorX + (screenX - anchorX) ÷ zoom
```

### 요구사항

1. `createInput()`에 카메라 모듈을 직접 import해 결합하지 않는다.
2. `getViewTransform()` 또는 `screenToWorldX()` 콜백을 주입한다.
3. 마우스·터치 `clientX`를 먼저 캔버스 논리 화면 X로 바꾼 뒤 카메라 역변환한다.
4. 결과는 유효한 월드 X 범위로 clamp한다.
5. 마지막 마우스 위치를 기억하고, 카메라가 부드럽게 변하는 중에도 매 프레임 목표 X를 다시 계산한다.
6. 휠을 돌렸을 때 마우스를 움직이지 않아도 함선 목표점이 잘못 튀지 않아야 한다.
7. 키보드 이동은 기존 속도와 월드 경계를 그대로 사용한다.
8. 터치 드래그는 기존 조작을 유지하며 확대 배율만 역변환한다.

정방향·역방향 왕복 오차는 테스트에서 0.01 논리 픽셀 이하로 확인한다.

## 7. 저장

카메라 배율은 게임 진행도가 아니라 사용자 보기 설정이다.

권장 저장 구조:

```js
view: {
  zoom: 1
}
```

요구사항:

- 기존 저장에 `view`가 없어도 100%로 안전 백필
- NaN, Infinity, 문자열, 0.1, 9 같은 손상 값은 100% 또는 clamp된 안전값으로 복구
- 휠 연속 입력 때마다 localStorage를 쓰지 않고 250~400ms debounce 후 목표값 저장
- 새로고침 후 마지막 목표 배율 복원
- 전체 진행 초기화 시에도 사운드 설정처럼 카메라 배율은 유지
- 기존 저장 버전과 진행도·코인·해금·사운드 손실 없음

단순 기본값 백필로 충분하면 불필요하게 `SAVE_VERSION`을 올리지 않는다. 버전을 올려야 한다면 이유와 마이그레이션을 완료보고에 명시한다.

## 9. 게임 규칙 불변

카메라 배율이 다음 값에 영향을 주면 실패다.

- 기함·드론·순양함 실제 좌표
- 적·보스 실제 좌표
- 탄환 실제 좌표
- 충돌 반경
- 이동 속도
- 발사 속도
- 스폰 위치·스폰 수
- 자석 범위
- 피격·회피 판정
- 시간·디렉터 진행
- 보상·코인
- 난이도

동일한 seed와 동일 입력을 사용한 시뮬레이션에서 85%, 100%, 130%의 월드 상태 결과가 같아야 한다. 화면 픽셀 결과만 달라야 한다.
