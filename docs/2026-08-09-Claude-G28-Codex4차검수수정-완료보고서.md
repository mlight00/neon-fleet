## 3. 절대 계약 불변 증거

- **게임 좌표**: `G28-WING-LASER/VULCAN/HOMING/SLOT` 이 실제 `_spawnWeaponShots()` 를 고정 RNG로 실행해
  탄 x가 `기함x + 22 + 마운트x`(미사일은 `+22`)임을 확인. main/wing 두 슬롯 차이 **정확히 22.0px**.
- **RNG 순서**: 발칸 테스트가 `Math.random` 호출 수 ≥ 탄 수임을 확인(퍼짐각 소비 순서 회귀 감지).
- **렌더 전용 보정**: `G28-ORIGIN` 이 보간 중에도 `bullet.x` 가 불변임을 단정. `G28-ORIGIN-DRAW` 는
  기록 캔버스로 **실제 `draw()` 가 22px 옮겨 그리는지**를 측정하고 게임 x는 그대로임을 재확인.
- **sidecar만 사용**: `SHOT_ORIGIN`·`ART_LOCK` 둘 다 `WeakMap`. 게임 객체에 필드 추가 없음.
- **충돌 계약**: 판정은 계속 원. P1-1은 그림 크기 조정 + 링 표시로만 해결(타원·알파 판정 도입 없음).

## 9-B. 추가 수정 §G-29 — 차지 빔 방향 되돌림 (이사 실기 재지적)

> "함미모드에서 차지샷이 다시 직선으로 나가는데?"

**§G-25 에서 제가 방향을 잘못 바꿨습니다.** "다른 발사체의 2/3 까지밖에 안 나간다"는 지적을 받고
빔을 **화면 최상단**으로 향하게 했는데, 그러면 포구의 화면 x 와 끝점의 화면 x 가 같아져
**기함이 어디 있든 빔이 화면에서 수직 직선**이 됩니다. 이는 §G-23 에서 이사님이 판정하신
"함미 시점에서는 소실점으로 뻗는 3D 쪽이 맞다"를 정면으로 어깁니다.

부족했던 것은 **길이**였지 방향이 아니었습니다. 그래서

- 방향을 **기함 전방(+z)** 으로 되돌렸습니다(`flagRig` 회전을 받아 피격 롤에 빔도 함께 기웁니다).
- 길이를 300 → **380** 으로 늘렸습니다(카메라 `far=400` 안쪽 최대치).
- 원통을 **원뿔**로 바꿨습니다 — 균일 두께는 끝이 뭉툭하게 잘려 "여기서 멈췄다"로 읽혔습니다.
  앞으로 갈수록 가늘어지니 소실점으로 사라지는 그림이 됩니다.

### 원근이 살아있는지 실측

## 9-C. §G-30 — 차지빔 사거리 + 레이저 가시 전장 (이사 실기 3지적)

> "챠지샷이 너무 짧아. 그리고 같은 원리로 레이저도 직선으로 나가고 있네. 소실점으로 향해야하지 않아?"

### 차지빔 — 한계는 카메라 `far` 였다

380까지 늘려도 끝이 화면 y≈198 에서 멎었습니다. 원인은 길이가 아니라 **카메라 far=400** 이었습니다.
씬의 실제 개체는 깊이 80 이내라 far 를 늘려도 가려짐 순서는 그대로입니다.

| | far | 빔 길이 | 끝 화면 Y | 소실점(184.3)까지 |
|---|---|---|---|---|
| 이전 | 400 | 380 | 197.73 | 13.4px |
| **지금** | **1600** | **1400** | **188.02** | **3.7px** |

포구에서 **372.7px** 뻗고, 끝이 소실점에 거의 붙어 "무한히 나간다"로 읽힙니다.
기함을 화면 좌우로 옮겨도 끝점은 같은 한 점(188.02)으로 모입니다 — 원근 유지.

### 레이저 — 방향은 이미 맞았고, 짧아서 안 보였다

실측해 보니 **3D 레이저는 이미 소실점을 향하고 있었습니다.** 월드 +z 로 놓으면 원근 투영이
자동으로 소실점에 모읍니다(탄이 화면 왼쪽이면 빔이 오른쪽 위로 기웁니다).

문제는 **화면 전장**이었습니다. 최소 26px 이라 "점"으로 보였고 그래서 기울기가 읽히지 않았습니다.

| 40px | — | 140.0 px | 36.3 px |

⚠️**전장을 늘리면 폭도 같이 커집니다** — `shotScale` 의 폭 = `전장 × SHOT_W`. 처음에 전장만 3.20 으로

### 곁가지 — 취약한 테스트 3건을 값 기반으로 교체

`SHOT_LEN`·`SHOT_W`·`SHOT_MIN_PX` 를 정규식으로 대조하던 자리(HW-17·HW-19·G22-SIZE)가

## 9-D. §G-31 — 차지 랜스 관통 범위 표시 (이사 A안 선택)

> "함미모드에서 챠지샷이 높이가 낮아서인지 같은 라인에 있는 원거리 적에 적중이 되지 않는다"

**판정은 되고 있었습니다.** `fireLance` 의 조건은 거리 제한이 없습니다.

```js
if (e.y < this.y && Math.abs(e.x - this.x) <= halfW + (e.r || 0))
```

문제는 **보이지 않는 것**이었습니다. 3D 직선은 원근상 소실점(화면 y≈188)보다 위로 갈 수 없어,
화면 상단 영역의 적은 맞고 있는데도 빔이 닿지 않아 보였습니다.
빔을 화면 상단까지 억지로 보내면 수직 직선이 되어 원근이 깨집니다(§G-29 에서 되돌린 그 문제).

### 이사 A안 — 원근은 빔이 지키고, 그 너머는 잔광이 잇는다

⚠️처음엔 **3D 빔을 그대로 연장**했는데 틀렸습니다. 소실점을 지난 직선은 **반대편으로 꺾입니다**
(실측: 기함이 오른쪽일 때 빔 끝 x 241.5 → 상단 x 167.6). 원근에서 전방 직선은 소실점에 *수렴*할 뿐 넘지 않습니다.

→ 잔광을 **빔의 연장이 아니라 판정 컬럼**으로 다시 만들었습니다.
판정은 월드 x 기준 ±`halfW` 띠이고 추적 투영에서 그 띠는 화면에서도 수직이므로,
기함 x 에 **판정 폭 그대로(63px)** 옅은 수직 띠 + 중앙 심을 얹습니다.

빔(원근·사선)과 띠(판정·수직)는 **뜻이 다릅니다** — 하나는 발사체, 하나는 사거리입니다. 겹쳐도 모순이 아닙니다.

| 기함 위치 | 3D 빔 | 판정 컬럼 |
|---|---|---|
| 중앙 | 240,561 → 240,188 (수직) | x 240, 폭 63px, y 0~188 |
| 오른쪽(+180) | 388,561 → **241.5**,188 (왼쪽 위로 기욺) | x 420, 폭 63px, y 0~188 |

렌더러는 빔 끝 화면 y 만 넘기고(`ctl.lanceScreen`), 띠는 실제 `ChargeLance` 엔티티의 `halfW`·`stage`·수명을 읽어
HUD 에 그립니다 — **판정에 쓰는 그 값**이라 표시와 실제가 어긋날 수 없습니다.
프레임 중 할당을 피하려고 그라디언트 대신 알파를 낮춘 사각 4장으로 그립니다.
