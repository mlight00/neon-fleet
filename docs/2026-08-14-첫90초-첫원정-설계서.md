## 0. 세 줄 요약

1. **8분짜리 완결 구조가 이미 만들어져 있다.** `BAL.gate1.timeline` — 30초 성장부터
   480초 결과 화면까지 9개 지점이 다 짜여 있다. 다만 **개발용 주소로만 열린다.**
2. **공개 원정은 약 28분이다**(계산). 제안서가 권하는 8~10분의 **세 배**다.
   처음 온 사람에게 한 세션에 "시작–성장–빌드–보스–결과"를 보여줄 수가 없다.
3. ⚠️**첫 90초에는 구조적 충돌이 하나 있다.** 초보를 보호하려고 만든 규칙이,
   제안서가 요구하는 학습을 **막고 있다**(§2-3). 이건 수치 조정이 아니라 판단이 필요하다.

## 1. 지금 무엇이 있나 — 실측

### 1-1. 공개 원정 길이 (계산값)

밸런스 상수에서 직접 계산했다.

```
전투 노드 = (7청크 × 900px + 15초×220px) ÷ 220px/초 = 43.6초
짧은 노드 = (4청크 × 900px + 15초×220px) ÷ 220px/초 = 31.4초   (위험·보급·보스)
섹터 = 노드 5개 + 보스 1개                             ≈ 4.6분
전체 = 6섹터                                          ≈ 28분
```

⚠️**카드 선택 화면·사망·재시도는 빼고 계산한 값**이다. 실제로는 더 길다.
실측이 아니라 상수에서 나온 계산이므로, 3인 관찰 테스트에서 실제 시간을 재야 확정된다.

### 1-2. ⚠️8분 구조가 이미 있다 — `BAL.gate1.timeline`

|---:|---|---|

| 210초 | 공명 예고 | ✅ |

제안서도 "기존 개발용 8분 코어 루프의 검증 자산을 설계 참고로 쓰라"고 했다.
**참고 수준이 아니라 그대로 쓸 수 있다.** 다만 §3-2의 세 가지가 빠져 있다.

진입 주소: `?coreLoopTest=1` — **개발용이다. 이대로 공개하면 안 된다**(§3-3).

### 1-3. 첫 노드는 "튜토리얼 안전" 구간이다

`js/main.js:1049`

```js
r.tutorial = r.sector === 1 && node.col === 0;   // 첫 원정 첫 노드만
```

이 구간에서는 이런 것들이 **아예 안 나온다**(`js/chunks.js:64`):

- 나쁜 게이트(**−**, **÷**) · 감염 게이트
- 중형·대형 적, 사격형·대응형 적
- 기뢰 · 잔해 · 돌진병 · 유성

즉 **크리스탈·보급·소형 생물·좋은 게이트(+, ×)만** 나온다.

## 2. 첫 90초 — 지금 vs 제안서

### 2-1. 대조표

| 시간 | 제안서가 요구하는 것 | 지금 실제 | 판정 |
|---:|---|---|---|
| 0~10초 | **한 번의 선택**으로 즉시 이동·자동 사격 | 무기 선택 카드 → **안내 패널** → 시작 = **화면 2장** | ⚠️미달 |
| 10~25초 | 안전한 크리스탈로 편대가 눈에 띄게 증가 | ✅첫 노드가 정확히 이 설계 | ✅ |
| 25~45초 | **청록 성장 / 자홍 손실** 게이트를 행동으로 학습 | ⚠️**첫 노드에 자홍 게이트가 없다** | ❌**구조적 충돌** |
| 45~65초 | 차지 랜스로 단단한 적·탄열 관통 | 차지는 처음부터 되지만 **쓸 이유를 주는 장면이 없다** | ⚠️미달 |
| 65~90초 | 첫 기함 등급 변화 또는 미니 절정 + 3D 제안 | 승급이 **성장에 따라 유기적**이라 시점이 정해져 있지 않다 | ⚠️불확정 |

### 2-2. 시작 화면이 두 장이다

지금 순서: **출격하기 → 무기 3장 중 선택 → 안내 패널 읽기 → "시작 ▶" → 첫 노드**

제안서는 *"긴 설명창 대신 화면 위 손짓·아이콘·짧은 문장"*, *"첫 안내는 건너뛸 수 있게"*,
*"플레이어가 행동하면 안내가 즉시 사라짐"*을 요구한다.
현재 안내는 **읽고 버튼을 눌러야 넘어가는 정적 패널 1장**이다.

### 2-3. ⚠️구조적 충돌 — 보호 규칙이 학습을 막는다

**첫 노드에서 나쁜 게이트를 빼는 것**은 초보 보호로는 옳다.
그런데 제안서는 **25~45초에 "성장/손실 게이트를 시각 행동으로 학습"**하라고 한다.

**첫 노드 길이가 43.6초다.** 즉 25~45초는 **전부 첫 노드 안**이고,
거기엔 손실 게이트가 **구조적으로 존재하지 않는다.**

플레이어는 첫 노드 내내 **"게이트는 좋은 것"**이라고 배운다.
그리고 두 번째 노드에서 처음으로 자홍 게이트를 만난다 — **아무 예고 없이.**

⚠️**이건 수치 조정으로 못 고친다. 셋 중 하나를 골라야 한다.**

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A** | 첫 노드 **후반부에만** 손실 게이트 1쌍 허용 | 제안서 타이밍을 그대로 맞춘다 | 초보 보호 규칙이 약해진다 |
| **B** | 첫 노드는 그대로 두고, **두 번째 노드 첫 게이트에 안내 표시** | 보호를 유지하면서 예고를 준다 | 학습이 45초 뒤로 밀린다 |
| **C** | 첫 노드에 **무해한 손실 게이트 시연** (지나가지 않아도 되는 위치에 배치) | 보호도 학습도 챙긴다 | 새 배치 규칙이 필요하다 |

**제 권고는 C입니다.** "봤지만 손해는 안 봤다"가 가장 안전한 학습입니다.
다만 새 배치 규칙이 필요해 A·B보다 손이 더 갑니다.
⚠️**게이트 배치는 게임 규칙 변경이라 이사님 승인 사항입니다.**

## 3. 설계안

### 3-1. 첫 90초 개선안

| 시간 | 설계 | 지금과 무엇이 다른가 |
|---:|---|---|
| 0~5초 | 무기 3장 선택 **한 장면만**. 고르는 즉시 전투 시작 | 안내 패널을 **없앤다** |
| 5~20초 | 화면 위 **짧은 손짓 안내** — "좌우로 움직이세요". **움직이면 즉시 사라짐** | 정적 패널 → 행동형 안내 |
| 10~25초 | 크리스탈 밀집 배치. 편대가 눈에 띄게 증가 | 지금과 같음 (✅유지) |
| 25~45초 | **손실 게이트 시연**(§2-3 C안) + 청록/자홍 색 안내 1줄 | 새로 넣음 |
| 45~65초 | **차지가 필요한 장면**을 배치 — 한 발로 못 뚫는 대상 | 차지를 쓸 이유를 만든다 |
| 65~90초 | **첫 기함 승급을 이 구간에 보장** + 승급 직후 **3D 한 번 체험 버튼** | 승급 시점을 확정. 3D 제안 신설 |

**안내 원칙** (제안서 그대로):

- 긴 설명창 대신 화면 위 짧은 문장·아이콘
- 건너뛸 수 있게
- 행동하면 즉시 사라짐
- **3D는 자동 전환하지 않는다.** "한 번 체험" 버튼으로만 제안
- 첫 90초에 **성장·위험 선택·강력한 공격·외형 변화 중 최소 3가지**

**3D를 승급 직후에 제안하는 이유**(제안서 논리 그대로): 타이틀에서 3D를 설명하면
조작 정보만 늘어난다. 반면 **"내 함선이 방금 달라졌다"** 직후라면
가까이 보고 싶은 동기가 이미 생겨 있다.

⚠️현재 3D 관련 UI는 **진입한 뒤 "함미 추적 시점"이라고 알려 주는 표시**뿐이다(`main.js:570`).
**들어가 보라고 권하는 장치는 없다.** 그래서 §6-1(현황 문서)의 "3D를 스스로 발견하는가"가
관찰 항목으로 들어가 있는 것이다.

### 3-2. 8~10분 첫 원정 — `gate1` 타임라인을 공개용으로

**새로 만들지 않는다.** 이미 있는 480초 타임라인을 공개 진입으로 연다.

제안서 요구 대비 채워야 할 것:

| 제안서 요구 | gate1 현재 | 할 일 |
|---|---|---|
| 8~10분 | ✅480초 = 8분 | 그대로 |
| 주·보조 무기 공명 완성 | ✅270초 | 그대로 |
| 대표 보스 1종 | ✅430초 | 그대로 |
| 완결된 결과 화면 | ✅480초 | **개발용 측정 요약을 일반 결과 화면으로 교체** |
| **3개의 짧은 전투 구간** | ❌시간 연속 구조라 구간 구분이 없다 | 구간 표시 3개 추가 |
| **1번의 항로 선택** | ❌없다 (25분 캠페인엔 5회 있다) | 25분 쪽 `pathChoices` **1쌍을 가져온다** |
| **기함 등급 상승 1~2회** | ⚠️1회(135초) | 2회로 할지 판단 필요 |
| **완료 후 6섹터 원정·격납고 해금** | ❌없다 | 해금 처리 추가 |

⚠️**135초 → 65~90초로 당기는 문제**: §3-1은 첫 승급을 65~90초에 보장하자고 한다.
gate1은 135초다. **이건 페이싱 수치 변경이라 이사님 승인 사항**이다.
당기면 첫인상이 좋아지고, 그만큼 뒤가 밋밋해질 위험이 있다.

### 3-3. ⚠️개발용 화면을 공개하지 않는다 (제안서 §10-5 명시)

`?coreLoopTest=1` 에는 공개하면 안 되는 것이 붙어 있다.

| 항목 | 위치 | 처리 |
|---|---|---|
| 8분 **측정 요약 패널** | `main.js:1584` "하네스 종료: 8분 결과 요약 + 측정 확정" | 일반 결과 화면으로 교체 |
| `window.__nfRunMetrics` 노출 | 같은 곳 | 공개 진입에서는 노출 안 함 |
| 고정 시드 4빌드 | `core-loop.js` `CORE_LOOP_BUILDS` | 플레이어 선택으로 대체 |
| 자동 조종 측정 모드 | `?coreLoopMeasure=1` | 공개 진입과 **주소를 분리**해 유지 |

**입구를 여닫는 선례가 이미 있다.** `main.js:136`

```js
const SHOW_CAMPAIGN25_ENTRY = false;
// ⚠️ 기능을 지운 게 아니라 '입구'만 닫았다 — 코드·데이터·테스트는 전부 그대로다.
```

25분 캠페인은 이 방식으로 입구만 닫혀 있다. **첫 원정도 같은 방식으로 열면 된다.**
개발용 측정 진입은 그대로 두고, 공개용 진입만 따로 만든다.

### 3-4. 첫 원정과 정규 원정의 관계

```
[처음 온 사람]  타이틀 → "첫 원정" (8분, 완결) → 결과 → 6섹터 원정·격납고 해금
[해 본 사람]    타이틀 → 6섹터 원정 / 격납고 (지금 그대로)
```

⚠️**정규 6섹터 원정은 건드리지 않는다.** 제안서도 "억지로 평균 플레이 시간을 늘리는 것이
목표가 아니라, 한 세션 안에 시작–성장–빌드–보스–결과를 완결하는 것"이라고 했다.

## 4. 건드리는 것 / 건드리지 않는 것

| 건드림 | 건드리지 않음 |
|---|---|
| 첫 원정 **진입 경로** 신설 | 정규 6섹터 원정 구조 |
| 첫 안내를 정적 패널 → 행동형으로 | 무기·공명·교리·키스톤의 **효과 수치** |
| 3D **체험 제안** 버튼 신설 | 3D 렌더 자체 (2D가 여전히 진실) |
| 결과 화면(측정용 → 일반용) | 판정·피해·보상·난수·스폰 **규칙** |

⚠️**아래 세 가지는 이사님 승인 없이는 손대지 않는다.**

1. 첫 승급 시점 135초 → 65~90초 (§3-2)
2. 첫 노드 게이트 배치 (§2-3 A·B·C 중 택일)
3. 첫 원정의 기함 승급 횟수 1회 → 2회

## 5. 어떻게 확인하나

| 무엇 | 방법 | 통과선 |
|---|---|---|
| 첫 90초에 3가지 이상 경험 | 3인 관찰 테스트 기록지 항목 3·4·5·7 | 3명 중 2명 이상 |

확인하지 않은 채로 재설계하면, 없는 문제를 고치고 있는 문제를 놓칠 수 있다.

## 6. 이 문서의 한계

- **28분은 계산값이지 실측이 아니다.** 상수에서 유도했고, 카드 화면·사망·재시도를 뺐다.
  실제 시간은 관찰 테스트에서 스톱워치로 재야 한다.
- **첫 90초를 직접 플레이해서 확인하지 못했다.** 개발 브라우저 창이 숨겨지면
  게임 루프가 멈춰(rAF 정지) 실제 진행을 관찰할 수 없다. 코드와 상수로만 재구성했다.
- **"기함 승급이 유기적"이라는 것까지는 확인했지만, 공개 런에서 평균 몇 초에
  일어나는지는 모른다**(`main.js:867` — 순양함 흡수로 오른다). 이것도 관찰 테스트 대상이다.
