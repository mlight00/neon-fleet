# 네온 함대 — 첫 90초 개선안 · 8~10분 첫 원정 설계

- **작성**: 2026-08-14
- **대응 과제**: 보완제안서 §10-5 · §6 P1 "첫 90초 재설계" · §6 P1 "첫 원정 8~10분"
- **상태**: **설계만. 코드·밸런스 수치는 건드리지 않았다** (제안서 §10-6)

## 0. 세 줄 요약

1. **8분짜리 완결 구조가 이미 만들어져 있다.** `BAL.gate1.timeline` — 30초 성장부터
   480초 결과 화면까지 9개 지점이 다 짜여 있다. 다만 **개발용 주소로만 열린다.**
2. **공개 원정은 약 28분이다**(계산). 제안서가 권하는 8~10분의 **세 배**다.
   처음 온 사람에게 한 세션에 "시작–성장–빌드–보스–결과"를 보여줄 수가 없다.
3. ⚠️**게이트 설명이 사라졌는데 게이트는 남아 있다.** 없앤 건 **무기 선택 게이트**이고
   **성장/손실 게이트(청록 ×2 / 자홍 ÷2)는 그대로**다. 그런데 무기 게이트를 없애며 안내문이
   다른 판으로 바뀌어, **청록/자홍 설명이 더는 안 뜬다.** 첫 노드 등장률 0%, 두 번째 노드부터
   **86%**(시드 400개 시뮬 실측) — 설명 못 들은 것을 갑자기 만난다(§2-3).

## 1. 지금 무엇이 있나 — 실측

### 1-1. 공개 원정 길이 (계산값)

밸런스 상수에서 직접 계산했다.

```
전투 노드 = (7청크 × 900px + 15초×220px) ÷ 220px/초 = 43.6초
짧은 노드 = (4청크 × 900px + 15초×220px) ÷ 220px/초 = 31.4초   (위험·보급·보스)
섹터 = 노드 5개 + 보스 1개                             ≈ 4.6분
전체 = 6섹터                                          ≈ 28분
```

⚠️**카드 선택 화면·사망·재시도는 빼고 계산한 값**이다. 실제로는 더 길다.
실측이 아니라 상수에서 나온 계산이므로, 3인 관찰 테스트에서 실제 시간을 재야 확정된다.

### 1-3. 첫 노드는 "튜토리얼 안전" 구간이다

`js/main.js:1049`

```js
r.tutorial = r.sector === 1 && node.col === 0;   // 첫 원정 첫 노드만
```

이 구간에서는 이런 것들이 **아예 안 나온다**(`js/chunks.js:64`):

- 나쁜 게이트(**−**, **÷**) · 감염 게이트
- 중형·대형 적, 사격형·대응형 적
- 기뢰 · 잔해 · 돌진병 · 유성

즉 **크리스탈·보급·소형 생물**만 나온다.
⚠️좋은 게이트(+·×)는 규칙상 허용되지만, **데이터에 있는 게이트 청크 6개가 전부 손실을 포함**해
실제로는 첫 노드에 게이트가 **하나도 안 나온다**(§2-3 실측 0%).

## 2. 첫 90초 — 지금 vs 제안서

### 2-1. 대조표

| 시간 | 제안서가 요구하는 것 | 지금 실제 | 판정 |
|---:|---|---|---|
| 0~10초 | **한 번의 선택**으로 즉시 이동·자동 사격 | 무기 선택 카드 → **안내 패널** → 시작 = **화면 2장** | ⚠️미달 |
| 10~25초 | 안전한 크리스탈로 편대가 눈에 띄게 증가 | ✅첫 노드가 정확히 이 설계 | ✅ |
| 25~45초 | **청록 성장 / 자홍 손실** 게이트를 행동으로 학습 | ⚠️첫 노드 등장률 **0%** · **안내문에 설명조차 없다** | ❌미달 (§2-3) |
| 45~65초 | 차지 랜스로 단단한 적·탄열 관통 | 차지는 처음부터 되지만 **쓸 이유를 주는 장면이 없다** | ⚠️미달 |
| 65~90초 | 첫 기함 등급 변화 또는 미니 절정 + 3D 제안 | 승급이 **성장에 따라 유기적**이라 시점이 정해져 있지 않다 | ⚠️불확정 → **100초로 확정 예정** |

### 2-2. 시작 화면이 두 장이다

지금 순서: **출격하기 → 무기 3장 중 선택 → 안내 패널 읽기 → "시작 ▶" → 첫 노드**

제안서는 *"긴 설명창 대신 화면 위 손짓·아이콘·짧은 문장"*, *"첫 안내는 건너뛸 수 있게"*,
*"플레이어가 행동하면 안내가 즉시 사라짐"*을 요구한다.
현재 안내는 **읽고 버튼을 눌러야 넘어가는 정적 패널 1장**이다.

### 2-3. ⚠️게이트 — 설명은 사라졌는데 물건은 남아 있다

**이사님 지적으로 바로잡음(2026-08-14).** 게이트는 **두 종류**이고, 없앤 건 한 종류뿐이다.

| 게이트 | 무엇 | 현재 |
|---|---|---|
| **무기 선택 게이트** (`weaponGate`) | 첫 노드에서 무기를 고르게 하던 막대 | ✅**제거됨.** `main.js:1086` — *"섹터 무기 조합(reson)이면 제거 (시작무기+POW로 충분, 이사: 무기선택 또 나옴)"* |
| **성장/손실 게이트** (`gatePair`) | 청록 ×2 / 자홍 ÷2 갈림길 | ⚠️**그대로 있다** |

**시드 400개로 청크 추첨을 실제 돌려 확인했다**(섹터 1 전투 노드, 실제 필터 그대로):

| 구간 | 성장/손실 게이트 등장률 |
|---|---:|
| 첫 노드 (튜토리얼 안전) | **0%** (400/400 전부 없음) |
| 두 번째 노드부터 | **86%** |

데이터에 남은 `gatePair` 청크는 6개이고 **전부 손실(−·÷)을 포함**한다.
튜토리얼 안전 조건을 통과하는 것은 **하나도 없다** → 그래서 첫 노드가 정확히 0%다.

#### ⚠️진짜 문제는 안내문이다

무기 게이트를 없애면서 **첫 출격 안내문이 통째로 다른 판으로 바뀌었다**(`ui.js:196~203`).

| 판 | 안내 내용 | 언제 뜨나 |
|---|---|---|
| **combo (지금 공개 플레이)** | POW · 크리스탈 · 중간 보스 | `squad.reson` 이 있으면 = **항상** |
| 구판 | *"청록은 성장, 자홍은 손실입니다"* | ⚠️**이제 안 뜬다** |

즉 지금 플레이어는

1. 안내문에서 **게이트 설명을 못 듣고**
2. 첫 노드 43.6초 동안 **게이트를 한 번도 못 보고**
3. 두 번째 노드에서 **86% 확률로 갑자기 만난다**

⚠️**영문 안내는 아직 게이트를 설명한다**(`ui.js:186` — *"Cyan routes help you grow; magenta routes cost you"*).
영어판이 한국어판보다 더 친절한 상태다. 영어 분기가 `combo` 를 무시하고 먼저 빠져나가기 때문이다.

#### 두 갈래 중 하나를 고르면 된다

| 안 | 내용 | 성격 | 손 |
|---|---|---|---|
| **가** | **게이트를 계속 쓴다** → 안내문에 청록/자홍 **한 줄을 되살린다** | **문구만.** 게임 규칙 불변 | 작음 |
| **나** | **성장/손실 게이트도 없앤다** → `gatePair` 청크 6개를 섹터 런에서 제외 | **게임 규칙 변경.** 성장 경로가 POW·크리스탈로 일원화 | 중간 |

**제 권고는 (가)입니다.** 게이트는 이 게임에서 **유일하게 "선택으로 손해를 볼 수 있는" 장치**입니다.
제안서가 첫 90초에 요구한 *"위험 선택"*이 여기서만 나옵니다. 없애면 그 요소가 통째로 사라집니다.
안내문 한 줄이면 해결되고, 규칙은 건드리지 않습니다.

⚠️**(나)를 고르시면** 게이트 제거는 게임 규칙 변경이라 별도 승인으로 진행합니다.

## 3. 설계안

### 3-1. 첫 90초 개선안

| 시간 | 설계 | 지금과 무엇이 다른가 |
|---:|---|---|
| 0~5초 | 무기 3장 선택 **한 장면만**. 고르는 즉시 전투 시작 | 안내 패널을 **없앤다** |
| 5~20초 | 화면 위 **짧은 손짓 안내** — "좌우로 움직이세요". **움직이면 즉시 사라짐** | 정적 패널 → 행동형 안내 |
| 10~25초 | 크리스탈 밀집 배치. 편대가 눈에 띄게 증가 | 지금과 같음 (✅유지) |
| 25~45초 | 안내문에 **청록/자홍 한 줄 복원**(§2-3 가안). 실제 게이트는 2번째 노드부터 | 사라진 설명을 되살린다 |
| 45~65초 | **차지가 필요한 장면**을 배치 — 한 발로 못 뚫는 대상 | 차지를 쓸 이유를 만든다 |
| **100초** | ✅**첫 기함 승급** (이사님 확정) + 승급 직후 **3D 한 번 체험 버튼** | 승급 시점을 확정. 3D 제안 신설 |

**안내 원칙** (제안서 그대로):

- 긴 설명창 대신 화면 위 짧은 문장·아이콘
- 건너뛸 수 있게
- 행동하면 즉시 사라짐
- **3D는 자동 전환하지 않는다.** "한 번 체험" 버튼으로만 제안
- 첫 90초에 **성장·위험 선택·강력한 공격·외형 변화 중 최소 3가지**

**3D를 승급 직후에 제안하는 이유**(제안서 논리 그대로): 타이틀에서 3D를 설명하면
조작 정보만 늘어난다. 반면 **"내 함선이 방금 달라졌다"** 직후라면
가까이 보고 싶은 동기가 이미 생겨 있다.

⚠️현재 3D 관련 UI는 **진입한 뒤 "함미 추적 시점"이라고 알려 주는 표시**뿐이다(`main.js:570`).
**들어가 보라고 권하는 장치는 없다.** 그래서 §6-1(현황 문서)의 "3D를 스스로 발견하는가"가
관찰 항목으로 들어가 있는 것이다.

### 3-2. 8~10분 첫 원정 — `gate1` 타임라인을 공개용으로

**새로 만들지 않는다.** 이미 있는 480초 타임라인을 공개 진입으로 연다.

제안서 요구 대비 채워야 할 것:

| 제안서 요구 | gate1 현재 | 할 일 |
|---|---|---|
| 8~10분 | ✅480초 = 8분 | 그대로 |
| 주·보조 무기 공명 완성 | ✅270초 | 그대로 |
| 대표 보스 1종 | ✅430초 | 그대로 |
| 완결된 결과 화면 | ✅480초 | **개발용 측정 요약을 일반 결과 화면으로 교체** |
| **3개의 짧은 전투 구간** | ❌시간 연속 구조라 구간 구분이 없다 | 구간 표시 3개 추가 |
| **1번의 항로 선택** | ❌없다 (25분 캠페인엔 5회 있다) | 25분 쪽 `pathChoices` **1쌍을 가져온다** |
| 기함 등급 상승 | 1회(135초) | ✅**1회 유지** (이사님 확정) · 시점만 **100초**로 |
| **완료 후 6섹터 원정·격납고 해금** | ❌없다 | 해금 처리 추가 |

#### ✅확정된 페이싱 (2026-08-14 이사님)

```
gate1.timeline.hullTier1 : 135초  →  100초
첫 원정 기함 승급 횟수    : 1회 (그대로)
```

**135초를 100초로 당긴다.** 제안서 권장(65~90초)보다는 뒤, 현재(135초)보다는 앞이다.
첫 90초 안에는 안 들어오지만, 첫 노드(43.6초) + 두 번째 노드 중반쯤이라
**"두 번째 구간에서 함선이 변한다"**는 리듬이 된다.

⚠️**승급을 1회로 유지하면 480초 중 100초 이후에는 외형 변화가 없다.**
그 공백은 **75초 두 번째 무기 · 270초 공명 완성 · 330초 프레임 선택**이 메운다 —
전부 함선의 무장·거동이 눈에 띄게 바뀌는 지점이라 밋밋해지지는 않는다.
관찰 테스트에서 "중반이 심심하다"는 말이 반복되면 그때 2회를 다시 검토한다.

### 3-3. ⚠️개발용 화면을 공개하지 않는다 (제안서 §10-5 명시)

`?coreLoopTest=1` 에는 공개하면 안 되는 것이 붙어 있다.

| 항목 | 위치 | 처리 |
|---|---|---|
| 8분 **측정 요약 패널** | `main.js:1584` "하네스 종료: 8분 결과 요약 + 측정 확정" | 일반 결과 화면으로 교체 |
| `window.__nfRunMetrics` 노출 | 같은 곳 | 공개 진입에서는 노출 안 함 |
| 고정 시드 4빌드 | `core-loop.js` `CORE_LOOP_BUILDS` | 플레이어 선택으로 대체 |
| 자동 조종 측정 모드 | `?coreLoopMeasure=1` | 공개 진입과 **주소를 분리**해 유지 |

**입구를 여닫는 선례가 이미 있다.** `main.js:136`

```js
const SHOW_CAMPAIGN25_ENTRY = false;
// ⚠️ 기능을 지운 게 아니라 '입구'만 닫았다 — 코드·데이터·테스트는 전부 그대로다.
```

25분 캠페인은 이 방식으로 입구만 닫혀 있다. **첫 원정도 같은 방식으로 열면 된다.**
개발용 측정 진입은 그대로 두고, 공개용 진입만 따로 만든다.

### 3-4. 첫 원정과 정규 원정의 관계

```
[처음 온 사람]  타이틀 → "첫 원정" (8분, 완결) → 결과 → 6섹터 원정·격납고 해금
[해 본 사람]    타이틀 → 6섹터 원정 / 격납고 (지금 그대로)
```

⚠️**정규 6섹터 원정은 건드리지 않는다.** 제안서도 "억지로 평균 플레이 시간을 늘리는 것이
목표가 아니라, 한 세션 안에 시작–성장–빌드–보스–결과를 완결하는 것"이라고 했다.
