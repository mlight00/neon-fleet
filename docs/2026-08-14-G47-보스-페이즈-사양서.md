# §G-47 — 보스 체력별 페이즈 사양서

- **작성**: 2026-08-14
- **요청(이사님)**: *"보스 체력별 페이즈 시스템을 적용하자. 너무 같은 패턴의 공격이 이루어져서 지루하다."*
- **상태**: 조사·설계. **코드 미착수** — 게임 규칙이라 이사님 승인 후 진행

---

## 0. 요약

1. **페이즈는 이미 있다.** 체력 50% 아래에서 "광폭화"로 넘어간다.
2. ⚠️**그런데 광폭화가 바꾸는 게 사실상 "속도"뿐이다.** 같은 공격을 빨리 할 뿐이라
   *다른 패턴*으로 느껴지지 않는다 — 이사님이 지루하다고 한 정확한 이유다.
3. 보스마다 **고유 패턴이 이미 하나씩 있다**(9종). 지금은 그 하나를 처음부터 끝까지 쓴다.
   **페이즈마다 다른 패턴을 쓰게 하면** 새 공격을 만들지 않고도 3배로 늘어난다.

---

## 1. 지금 어떻게 되어 있나 (실측)

### 1-1. 페이즈는 2단계, 임계는 체력 50%

`js/bosses.js:99`

```js
get enraged() { return this.variantAlwaysEnrage || this.hp <= this.maxHp * BAL.boss.enrageRatio; }
```

| 값 | 실측 |
|---|---:|
| 광폭 임계 `enrageRatio` | **0.5** (체력 50% 이하) |
| 광폭 발사 배수 `enrageRate` | **0.6** (간격 0.6배 = 1.67배 빨라짐) |
| 기본 탄 간격 | 1.8초 |
| 기본 수하 소환 간격 | 2.7초 |
| 보스 체력 | 3,500 |

### 1-2. ⚠️광폭화가 바꾸는 것 — 전부 4곳뿐

`grep enraged` 결과 전수:

| 위치 | 바뀌는 것 | 성격 |
|---|---|---|
| `bosses.js:100` | 발사 간격 ×0.6 | **속도** |
| `bosses.js:133` | 좌우 흔들림 폭 0.16 → 0.22 | 움직임 |
| `bosses.js:134` | 흔들림 빈도 0.7 → 1.1 | 움직임 |
| `bosses.js:248` | 위험 컬럼 +1 (B14 rain 전용) | 패턴 |

**공격의 *종류*는 그대로다.** 크레센트를 쏘던 보스는 광폭화해도 크레센트만 더 빨리 쏜다.
그래서 전투가 길어지면 "같은 걸 계속 본다"가 된다.

### 1-3. 보스별 고유 패턴은 이미 9종 있다

`BAL.bossPatterns` 실측:

| 보스 | 패턴 | 성격 |
|---|---|---|
| B7 | `brood` | 수하 다수 소환 |
| B8 | `crescent` | 7발 부채꼴 (15°) |
| B9 | `spiral` | 나선 훑기 (75° 스윕) |
| B10 | `pincer` | 좌우 협공 3쌍 |
| B11 | `ring` | 전방위 12발 |
| B12 | `cross` | 십자 4팔 회전 |
| B13 | `wave` | 파형 7열 |
| B14 | `rain` | 컬럼 예고 후 낙하 |
| B15 | `laserSweep` | 레이저 3단 훑기 |

**자산은 이미 충분하다.** 새 공격을 만들 필요가 없다 — **조합과 전환**이 없을 뿐이다.

---

## 2. 설계

### 2-1. 핵심 — 페이즈마다 *다른 패턴*을 쓴다

지금: `보스 = 패턴 1개 × (보통 / 빠름)`
바꿀 것: `보스 = 페이즈별 패턴 × 페이즈별 속도`

```
페이즈 1 (체력 100~66%)  고유 패턴          — "이 보스는 이런 놈이다"를 배운다
페이즈 2 (체력 66~33%)   고유 + 보조 패턴   — 배운 대응이 부족해진다
페이즈 3 (체력 33~0%)    광폭 + 절정 패턴   — 마지막 압박
```

⚠️**보조 패턴은 새로 만들지 않는다.** 다른 보스의 패턴을 빌려 쓴다.
예: B8(크레센트)의 2페이즈에 `ring`을 섞으면, 부채꼴만 피하던 대응이 안 통한다.

### 2-2. 페이즈 전환을 **보이게** 한다

⚠️지금 광폭화는 아무 신호가 없다. 어느 순간 빨라져 있을 뿐이라 **변화를 인지하지 못한다.**
바뀐 걸 못 느끼면 바꾼 의미가 없다.

| 요소 | 내용 |
|---|---|
| 전환 순간 | 짧은 무적 + 전신 발광 + 화면 흔들림(약) |
| 예고 | 전환 직전 0.5초 정지 — "무언가 온다" |
| 소리 | 페이즈 전환음 1종 (이미 있는 효과음 재사용) |
| 3D | 파편 방출(§G-46 리그 재사용) — 껍질이 벗겨지는 느낌 |

### 2-3. 데이터로 정의한다 — 코드 분기가 아니라

`BAL.bossPatterns` 옆에 페이즈 표를 둔다. 보스를 추가할 때 코드를 안 고치게.

```js
bossPhases: {
  B8: [
    { at: 1.00, kind: 'crescent' },                    // 고유
    { at: 0.66, kind: 'crescent', add: 'ring' },       // + 전방위
    { at: 0.33, kind: 'ring', add: 'spiral', rate: 0.6 },  // 절정
  ],
  // 표에 없는 보스는 지금 동작 그대로(2단계 광폭화) — 점진 적용이 가능하다
}
```

⚠️**표에 없으면 현행 유지**가 중요하다. 10종을 한 번에 손대지 않고 하나씩 검증할 수 있다.

---

## 3. ⚠️이건 게임 규칙 변경이다

지금까지 §G-45·§G-46 은 전부 **표시 계층**이었다 — 판정·피해·보상에 손대지 않았다.
이 작업은 다르다.

| 바뀌는 것 | 영향 |
|---|---|
| 보스 공격 빈도·종류 | **난이도** |
| 페이즈 임계 | 전투 길이·체감 |
| 전환 시 무적 | **판정** |

**그래서 수치는 이사님이 정하셔야 한다.** 제가 제안할 수는 있지만 확정은 못 한다.

### 정해 주셔야 할 것

| # | 안건 | 제 제안 |
|---|---|---|
| 1 | 페이즈 수 | **3단계** (2는 지금과 같고, 4 이상은 보스전이 길어진다) |
| 2 | 임계 체력 | **66% / 33%** |
| 3 | 전환 시 짧은 무적 | **넣는다** (0.4초). 전환을 인지시키려면 순간 정지가 필요 |
| 4 | 적용 범위 | **B8 하나로 먼저** 검증 → 좋으면 확대 |
| 5 | 보스전 총 길이 | 지금 유지 / 늘림 / 줄임 |

⚠️4번을 권한다. 10종을 한꺼번에 바꾸면 **무엇이 좋아지고 나빠졌는지 분리가 안 된다.**

## 4. 작업 단계

| # | 내용 | 성격 |
|---|---|---|
| 1 | `bossPhases` 데이터 표 + 조회 함수 (순수) | 안전 |
| 2 | `Boss` 가 현재 페이즈를 계산 (기존 `enraged` 는 유지) | 규칙 |
| 3 | 페이즈별 패턴 전환 배선 | 규칙 |
| 4 | 전환 연출 (발광·정지·파편·소리) | 표시 |
| 5 | B8 만 표에 등록해 실기 확인 | — |
| 6 | 이사님 판정 후 나머지 9종 확대 | 규칙 |
| 7 | 테스트: 임계 경계·표 없는 보스 현행유지·전환 1회성 | 안전 |

**1·4·7 은 규칙을 안 건드린다.** 승인 전에도 진행할 수 있다.
2·3·6 은 승인 후.

---

## 5. 이 문서의 한계

- ⚠️**전투 체감은 제가 판단할 수 없다.** 개발 브라우저는 창이 숨겨지면 게임 루프가 멈춰
  보스전을 직접 해볼 수 없다. "지루한가 / 나아졌는가"는 이사님 실기가 유일한 근거다.
- 패턴을 섞었을 때 **탄이 과밀해지는지**는 실측이 필요하다. 표 위에서는 안전해 보여도
  두 패턴이 같은 구간에 몰리면 피할 공간이 사라질 수 있다.
- 보스 체력 3,500 은 그대로 두는 전제다. 페이즈를 3단계로 나눠도 총 전투 시간은 같다.
