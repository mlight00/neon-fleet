## 0. 가장 중요한 목표

플레이어가 마우스 휠을 위로 돌릴수록 성장한 기함·드론·순양함을 더 크게 보다가, 일정 배율을 넘으면 RPG의 근접 카메라처럼 **기함 뒤에서 전방을 바라보는 2.5D 함미 추적 시점**으로 자연스럽게 전환되게 한다.

이 기능의 핵심 목적:

> 플레이어가 성장한 기함의 함체·무기·지휘 프레임·편대를 크게 보며 “내 함대가 이렇게 강해졌다”는 소유감과 성장 만족을 얻는다.

진짜 3D/FPS를 만드는 작업이 아니다.

- 기존 2D 상면 스프라이트를 재사용한다.
- 기존 X/Y 월드 좌표와 게임 규칙을 유지한다.
- 전투 개체의 **화면 위치·크기만 원근감 있게 투영**한다.
- 충돌·스폰·사거리·피해·속도·보상·난이도는 바꾸지 않는다.
- UI에서는 `1인칭`이라고 부르지 않고 `함미 추적 시점 / Pursuit View`라고 부른다.

## 1. 왜 기존 축소를 제거하는가

85% 축소는 게임 세계를 넓히지 않는다.

- 적·무기·충돌·스폰 범위는 기존 `0~logicalW`, `0~logicalH`에 고정
- 배경만 더 많이 보임
- 무기와 적은 새로 드러난 바깥 여백에 도달하지 않음
- 결과적으로 플레이 공간이 넓어진 것처럼 보이지만 실제 상호작용은 없음

따라서 이번 작업에서:

```text
최소 배율: 85% → 100%
최대 배율: 130% → 220%
단계: 5% → 10%
```

100% 아래로 축소하지 않는다. 기존 저장값이 85~95%면 안전하게 100%로 올린다.

## 3. 사용자 경험 계약

## 3.1 배율과 전환 구간

권장 상수:

```js
DEFAULT_ZOOM = 1.00
MIN_ZOOM = 1.00
MAX_ZOOM = 2.20
ZOOM_STEP = 0.10

CHASE_START_ZOOM = 1.60
CHASE_FULL_ZOOM = 2.00
```

시점 변화:

| 목표 배율 | 화면 |
|---:|---|
| 100~150% | 기존 전술 시점을 기함 중심으로 확대 |
| 160% | 함미 추적 전환 시작 |
| 160~200% | 전술 시점과 추적 시점을 연속 보간 |
| 200~220% | 완전한 함미 추적 시점, 추가 근접 확대 |

160%와 200% 사이에서 카메라가 순간적으로 튀거나 화면이 한 프레임 바뀌면 실패다.

`chaseBlend`는 `0~1` 연속값으로 계산한다.

```js
chaseBlend = smoothstep(CHASE_START_ZOOM, CHASE_FULL_ZOOM, zoom)
```

이진 `tactical/chase` 스위치로 갑자기 전환하지 않는다.

## 3.2 함미 추적 시점의 모습

완전 전환 시:

- 기함과 편대가 화면 하단 중앙에 머문다.
- 기함 함체 높이는 화면 높이의 약 **14~22%**가 목표다.
- 드론·순양함 포함 편대 폭은 화면 폭의 약 **45~70%**를 넘지 않는다.
- 먼 적·아이템·탄환은 화면 상단의 소실점 부근에서 작게 보인다.
- 플레이어 가까이 접근할수록 크기와 좌우 간격이 커진다.
- 배경에는 약한 소실선·별빛 속도선을 더해 전진감을 준다.
- HUD·일시정지·선택창·결과창은 크기와 위치가 변하지 않는다.

기함이 HUD를 가리거나 화면 아래로 잘리면 실패다.

## 3.3 전환 감각

- 기존 확대 보간은 유지한다.
- `chaseBlend`는 350~500ms 정도의 ease-out으로 별도 보간한다.
- `prefers-reduced-motion: reduce`에서는 원근 이동 애니메이션 없이 즉시 전환하거나 100ms 이하의 단순 페이드만 사용한다.
- 추적 시점에 처음 완전히 진입할 때 700~900ms 동안 표시:

```text
함미 추적 시점
Pursuit View
```

- 휠 아래로 내리면 동일한 경로를 역으로 따라 전술 시점으로 복귀한다.

## 4.1 `chase-camera.js`

DOM·게임 전역·랜덤·시간에 의존하지 않는 순수 함수 중심:

```js
smoothstep(min, max, value)
chaseBlendForZoom(zoom)
advanceChaseBlend(current, target, dt, reducedMotion)
createChaseProjection(options)
projectPoint(point, projection)
projectObject(point, kind, projection)
screenToWorldXAtPlayer(screenX, projection)
edgeIndicatorForPoint(point, viewport, projection)
```

필요하다면 이름은 조정해도 된다.

## 4.2 투영 기본 개념

현재 월드 좌표:

- `y=0`: 전방 먼 곳
- `y=squad.y`: 플레이어 가까운 곳

깊이값:

```js
depth = clamp((worldY - farWorldY) / (squadY - farWorldY), 0, 1)
```

- `depth=0`: 소실점, 작고 좁음
- `depth=1`: 기함 근처, 크고 넓음

권장 화면 기준:

```text
horizonY = logicalH의 16~24%
nearY    = logicalH의 80~86%
far lateral scale  = 0.30~0.45
near lateral scale = 1.15~1.35
far object scale   = 0.35~0.50
near object scale  = 1.35~1.70
```

깊이 곡선은 `pow(depth, 1.2~1.5)` 범위에서 조정한다.

중요:

- 숫자를 여기저기 하드코딩하지 않는다.
- 모든 투영 상수를 한 객체에서 관리한다.
- 100%에서는 기존 렌더와 픽셀 차이가 없어야 한다.
- 160% 전환 시작점에서도 기존 확대 위치와 연속이어야 한다.

## 4.3 전술 위치와 추적 위치를 보간

각 월드 점마다 다음 두 결과를 계산한다.

```text
A = 기존 함대 중심 확대 결과
B = 2.5D 추적 투영 결과
최종 = lerp(A, B, chaseBlend)
```

위치와 표시 크기를 모두 보간한다.

```js
screenX = lerp(tacticalX, chaseX, chaseBlend)
screenY = lerp(tacticalY, chaseY, chaseBlend)
scale   = lerp(tacticalScale, chaseScale, chaseBlend)
```

이렇게 해야 확대하다가 시점이 자연스럽게 굽으며 전환된다.

## 5. 렌더 구조

## 5.1 기존 경로 보존

`chaseBlend === 0`이면 현재 전술 카메라 경로를 그대로 사용한다.

```text
기존 global translate/scale
기존 draw 순서
기존 effects.drawWorld
```

100~160% 구간을 불필요하게 전부 다시 작성하지 않는다.

## 5.2 추적 전환 경로

`chaseBlend > 0`일 때 각 전투 개체를 개별 투영한다.

권장 헬퍼:

```js
drawProjected(ctx, object, projection, drawFn, kind)
```

개념:

```js
const p = projectObject({ x: object.x, y: object.y }, kind, projection);
ctx.save();
ctx.translate(p.x, p.y);
ctx.scale(p.scale, p.scale);
ctx.translate(-object.x, -object.y);
drawFn(ctx);
ctx.restore();
```

반드시 `save/restore`를 개체마다 균형 있게 유지한다.

투영 대상:

- 기함·드론·순양함 전체 편대
- 캠페인 전투기 편대
- 일반 적·정예·보스
- 플레이어 탄환
- 적 탄환
- 크리스탈·코인·수송선·캡슐·게이트·모듈·장애물
- 파티클·링·총구 섬광·후광·데미지 텍스트

화면 고정:

- HUD
- 전체 화면 플래시
- 컷신
- 시네마 띠
- DOM 오버레이
- pause·charge 버튼
- 배율/시점 안내 문구

## 5.3 종류별 가독성 보정

같은 깊이라도 다음 가독성 규칙을 적용한다.

- `enemyBullet`: 화면상 지름 또는 선 굵기 최소 3px
- `playerBullet`: 최소 2px, 무기 색 유지
- `pickup`: 너무 작아지지 않도록 표시 배율 최소 0.55~0.70
- `boss`: 가까워져도 화면 전체를 덮지 않도록 표시 배율 상한
- `gate`: 라벨·선택 레인이 읽히는 최소 폭 보장
- `damageText`: 먼 곳에서 너무 작으면 최소 글자 크기 10~11px
- `squad`: 기함 성장 외형이 보이되 전체 편대가 화면 폭 70%를 넘지 않게 상한

이 값들은 시각 표시용이며 실제 충돌 반경을 바꾸지 않는다.

## 5.4 긴 광선·게이트·범위 공격

긴 레이저·차지 랜스·게이트처럼 한 점이 아니라 넓은 경로를 차지하는 요소는 개체 중심 하나만 확대하면 끝점이 어긋날 수 있다.

필수 처리:

- 시작점과 끝점을 각각 `projectPoint()`로 투영한다.
- 긴 빔은 필요하면 8~12개 구간의 polyline/quad로 근사한다.
- 게이트의 좌우 끝점도 별도로 투영한다.
- 범위 링은 중심 깊이 배율을 사용하되 화면상 최소 선 굵기를 유지한다.
- 광선이 적·기함에서 분리되거나 허공에서 시작하면 실패다.

## 6. 편대와 기함 표현

현재 `Squad.draw()`는 드론·순양함·기함을 한 번에 그린다. 1차 구현에서는 편대 전체를 같은 근거리 투영으로 묶어도 된다.

단, 다음을 확인한다.

- 최대 드론 수에서도 편대가 좌우로 잘리지 않음
- 순양함이 기함을 완전히 가리지 않음
- 기함 함체·무기 리그·지휘 프레임·함체 승급 외형이 식별됨
- 피격 핵 표시가 보임
- 실제 피격 핵과 화면상 표시가 어긋나지 않음

편대 전체 확대 때문에 기함이 오히려 묻힌다면 렌더 전용으로 다음처럼 분리할 수 있다.

```text
Squad.drawEscorts(ctx)
Squad.drawFlagship(ctx)
```

이 리팩터는 그리기 책임만 나누며 업데이트·전투 로직을 건드리지 않는다.

## 7. 배경의 2.5D 전진감

기존 zone backdrop·starfield는 기본 배경으로 유지한다.

추적 시점에서만 알파로 겹치는 가벼운 화면 효과를 추가한다.

- 소실점에서 화면 하단으로 퍼지는 희미한 레인/항로선
- 전방 별빛의 짧은 속도선
- 기함 X 이동에 따른 아주 약한 좌우 패럴랙스
- 추적 전환 중 소실점 글로우

금지:

- 새 이미지·3D 라이브러리·WebGL 엔진 추가
- 화면 전체를 흔드는 강한 카메라 셰이크
- 반복 랜덤 객체를 매 프레임 새로 생성
- 배경 때문에 적 탄환 대비가 약해지는 것

효과 강도는 `chaseBlend`에 비례하며 최대에서도 전투 가독성을 우선한다.

## 8. 입력 좌표와 조작

## 8.1 마우스·터치

현재 게임은 주로 X축 이동이므로 추적 시점에서도 조작 규칙은 바꾸지 않는다.

마우스 화면 X를 **플레이어 근거리 평면**의 월드 X로 역변환한다.

```js
worldX = screenToWorldXAtPlayer(screenX, projection)
```

요구사항:

- 100~220% 모든 단계에서 화면 왼쪽·중앙·오른쪽 오차 ≤1 논리 px
- 전환 중 `chaseBlend`가 변해도 마우스를 멈춘 상태에서 목표점이 튀지 않음
- 함대가 화면 중앙에 고정돼 보이더라도 실제 월드 X는 정상 이동
- 키보드 좌우 이동 속도·경계는 기존 그대로
- 터치 드래그 정상
- 카메라가 게임 규칙의 `squad.x`를 직접 변경하지 않음

## 8.2 키보드와 모바일

기존:

- `+`, `=` 확대
- `-` 축소
- `0` 100% 초기화

추가:

- `C`: 100% ↔ 220% 함미 추적 시점 토글
- 입력창·Ctrl/Cmd·Alt·repeat 가드 유지

일시정지 패널:

- 기존 `− / 현재% / +` 유지
- 별도 44px 이상 버튼 추가:

```text
함미 추적 시점
Pursuit View
```

- 추적 시점이면 버튼 문구:

```text
전술 시점
Tactical View
```

- 모바일은 이 버튼으로 추적 시점에 진입·복귀
- 버튼 포커스 링·영어/한국어 `aria-label` 필수

## 9. 화면 밖 위험 경고

추적 시점은 좌우·후방 시야를 줄이므로 위험을 숨긴 채 기존 판정을 유지하면 불공정하다.

카메라 투영 밖의 위험만 화면 가장자리에 표시한다.

최소 요구:

- 화면 밖 보스: 방향 화살표 + 이름 또는 위험색
- 기함과 가까워지는 화면 밖 적 탄환: 좌/우 붉은 경고
- 화면 밖 충돌형 적: 주황 경고
- 한쪽에 최대 3개까지만 표시해 혼잡 방지
- HUD보다 아래, 월드보다 위에 그리기
- `pointer-events:none`
- 색만으로 구분하지 않고 모양도 다르게 함

경고는 시각 기능이며 적 위치·속도·충돌을 변경하지 않는다.

권장 순수 함수:

```js
edgeIndicatorForPoint(projectedPoint, viewport, kind)
```

## 10. 저장과 이전 값 마이그레이션

기존 `view.zoom`을 그대로 사용한다.

- 구 저장에 `view` 없음 → 1.0
- 저장값 0.85~0.95 → 1.0
- 1.0~2.2 → 10% 격자로 정규화
- 2.2 초과 → 2.2
- NaN/Infinity/문자열 손상 방어
- 새로고침·사망·재도전·진행 초기화 후 유지
- `SAVE_VERSION`은 단순 clamp/백필로 충분하면 올리지 않음

추적 시점 여부는 별도 불리언으로 저장하지 않는다. `view.zoom`으로 결정한다.

- 기함·드론·순양함 실제 좌표
- 적·보스 실제 좌표
- 탄환 실제 좌표와 궤적
- 충돌 반경·피격 판정
- 무기 사거리·발사 속도·피해량
- 적 스폰 위치·수·간격
- 자석·수집 범위
- 디렉터 시간
- 코인·보상
- 난이도
- RNG 호출 수·순서

동일 seed·동일 입력을 100%와 220%에서 실행한 월드 상태 스냅샷이 같아야 한다.

## 12. 성능 기준

2.5D 투영 때문에 매 프레임 대량의 객체·배열을 만들지 않는다.

- hot loop에서 `{}`·`[]` 생성 최소화
- 전체 월드 배열을 매 프레임 복사·정렬하지 않음
- 불필요한 `save/restore` 중첩 방지
- 추적 시점이 아니면 추가 투영 비용 거의 0
- 배경 효과의 랜덤 데이터는 초기화 시 한 번 생성 후 재사용

같은 스트레스 장면에서:

- 220% 추적 시점 평균 draw 비용이 100% 대비 20% 이상 증가하면 원인 분석
- 프레임 루프 중단 0
- NaN·Infinity·transform 누적 0
- 저사양에서도 최소 30fps 아래로 지속 하락하지 않음

정확한 장비 한계로 수치를 못 재면 동일 장면의 상대값과 측정 환경을 보고한다.
