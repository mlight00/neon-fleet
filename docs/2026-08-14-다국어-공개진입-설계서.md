## 0. 세 줄 요약

1. 지금 공개 주소는 **무조건 한국어**로 뜬다. 영어는 실험용·포털용 모드에서만 켜진다.
2. 그런데 그 영어도 **완성품이 아니다.** 실측 결과 **375개 문자열이 아직 한국어**다.
   공명·교리·키스톤·모듈·무기진화는 **영어 데이터가 아예 없다.**
3. 그래서 "언어 선택 버튼만 달면 된다"가 아니다. **번역 375개가 먼저**고,
   버튼은 그 다음이다.

## 1. 지금 어떻게 되어 있나

### 1-1. 언어가 "모드"에 붙어 있다

`js/main.js:82` 한 줄이 전부다.

```js
const EN = PLAYTEST || PORTAL_MODE;
```

읽으면 이렇다 — **"실험 참가자이거나 포털 방문자이면 영어"**.
즉 **언어가 신분에 종속**되어 있다. 일반 방문자는 영어를 고를 방법이 없다.

실제로 확인했다(2026-08-14, 공개 주소 실행):

| 주소 | 뜨는 화면 |
|---|---|
| `mlight00.github.io/neon-fleet/` | 타이틀 버튼 **"출격하기"** — 한국어 |
| `…/?playtest=prolific` | **"I agree and start the playtest"** — 영어. 단 **4분 실험 흐름** |

⚠️영어를 보려면 **연구 동의 화면을 거쳐 4분 제한 실험**에 들어가야 한다.
이건 게임을 즐기러 온 사람에게 줄 수 있는 경로가 아니다.

### 1-2. 영어가 코드에 흩뿌려져 있다

영어는 사전이 아니라 **삼항 분기**로 박혀 있다.

```js
_zoomIndEl.textContent = EN ? `Zoom ${pct}%` : `확대 ${pct}%`;
```

이런 자리가 `main.js` 38곳, `ui.js` 등 포함 총 100여 곳이다.
**한 곳이라도 빠뜨리면 영어 화면에 한국어가 튀어나온다.** 그리고 실제로 튀어나온다.

## 3. 설계 — 언어를 신분에서 떼어낸다

### 3-1. 핵심 한 줄

지금:

```js
const EN = PLAYTEST || PORTAL_MODE;      // 신분 → 언어
```

바꿀 모습:

```js
const LANG = resolveLang();              // 언어를 먼저 정하고
const EN   = (LANG === 'en');            // 영어 여부는 그 결과일 뿐
```

`resolveLang()` 의 우선순위:

| 순위 | 근거 | 비고 |
|---|---|---|
| 1 | **사용자가 고른 값** (`localStorage`) | 한 번 고르면 계속 유지 |
| 2 | `?lang=ko` / `?lang=en` 주소 | 링크로 특정 언어를 지정해 공유할 때 |
| 3 | **실험·포털 모드** | 실험은 조건을 통일해야 하므로 영어 고정 |
| 4 | 배포 플랫폼 locale | 포털이 알려 주는 경우 |
| 5 | 브라우저 언어 (`navigator.language`) | 한국어 사용자면 한국어 |
| 6 | **기본값 = 영어** | 제안서 요구. 세계 어디서 들어와도 최소한 읽힌다 |

⚠️**실험 흐름은 그대로 분리 유지된다.** `PLAYTEST` 는 여전히 4분 제한·동의 화면을 갖고,
단지 "영어를 쓰는 여러 경우 중 하나"가 될 뿐이다. 일반 방문자가 실험 UI를 볼 일은 없다.

### 3-2. 어디서 고르나

두 자리를 둔다.

1. **타이틀 화면 우상단** — `한국어 / English` 토글. 첫 방문자가 바로 본다.
2. **사운드 설정 패널 안** — 이미 있는 설정 창이라 추가 UI가 늘지 않는다.

고른 값은 `localStorage` 에 저장하고, 다음 방문에 그대로 적용한다.

⚠️언어를 바꾸면 **타이틀 화면으로 되돌린다.** 전투 중에 라벨만 바뀌면 어색하고,
캔버스에 이미 그려진 글자는 즉시 안 바뀐다.

## 4. 번역을 어디에 담나 — 세 안 비교

| 안 | 방식 | 장점 | 단점 | 판정 |
|---|---|---|---|---|
| A | 지금처럼 삼항 분기를 375개 더 | 새 구조 불필요 | **코드가 읽기 불가능해진다.** 누락을 못 잡는다 | ✗ |
| **B** | **데이터에 영어 형제 필드 추가** (`name`/`nameEn`) | **보스가 이미 이 방식**이다. 자동 검사 쉬움 | 필드가 두 배 | **✅데이터 196개는 이걸로** |
| C | 별도 사전 파일 + `t('키')` | 정석. 언어 추가가 쉬움 | 375곳을 키로 바꾸는 큰 공사 | 지금은 과함 |

**권장: B + 기존 헬퍼 재사용.**

- 데이터 196개 → `nameEn` / `descEn` 형제 필드. **보스에서 검증된 방식**이라 새 위험이 없다.
- 코드 179개 → `main.js:84` 에 **이미 있는** `tx(en, ko)` 헬퍼를 쓴다. 새 도구가 필요 없다.

```js
const tx = (en, ko) => (EN ? en : ko);   // 이미 존재한다
```

### 4-1. 다시는 새지 않게 하는 장치

번역은 한 번 하고 끝나지 않는다. **새 기능을 넣을 때마다 다시 샌다.**
그래서 자동 검사를 함께 만든다.

| 검사 | 하는 일 | 실패 조건 |
|---|---|---|
| 데이터 짝 검사 | 모든 데이터 모듈을 import 해서 한글 필드마다 영어 형제가 있는지 확인 | 하나라도 빠지면 실패 |
| 코드 맨문자열 검사 | `main.js`·`ui.js` 에서 `tx()` 밖의 한글 리터럴을 찾는다 | 새로 생기면 실패 |
| 화면 훑기 | 영어 모드로 실제 실행해 DOM + **캔버스 `fillText`** 에 한글이 그려지는지 감시 | 한 글자라도 나오면 실패 |

⚠️세 번째가 중요하다. 캔버스에 그린 글자는 **DOM 검사로 안 잡힌다.**
이번 조사에서 `fillText` 를 가로채는 방법을 만들어 뒀다 — 그대로 시험에 쓴다.

## 5. ⚠️번역 품질 — 여기서 이사님 판단이 필요합니다

**기계적으로 375개를 다 영어로 바꾸면 게임이 더 나빠질 수 있습니다.**

게임 고유명사는 뜻이 아니라 **느낌**으로 짓습니다.

| 한국어 | 직역하면 | 게임 이름답게 하면 |
|---|---|---|
| 군체 용광로 | Swarm Furnace | **Hive Crucible** |
| 레일 스톰 | Rail Storm | Rail Storm (그대로 좋음) |
| 폭풍 발칸 | Storm Vulcan | **Tempest Vulcan** |
| 드론 지휘 | Drone Command | Drone Doctrine / Swarm Command |

어색한 영어는 첫인상을 **한국어보다 더 크게** 해칩니다.
평가 커뮤니티에서 "번역기 돌린 게임"으로 읽히면 그 인상이 먼저 박힙니다.

**그래서 이렇게 나누기를 제안합니다.**

| 구분 | 개수(대략) | 누가 |
|---|---:|---|
| **고유명사** (무기·공명·교리·키스톤·모듈 **이름**) | 약 50 | ⚠️**이사님이 최종 확정.** 제가 후보 2~3개씩 뽑아 드립니다 |
| 설명문·안내문·UI 문구 | 약 325 | 제가 작성 → 이사님 훑어보기 |

## 7. 이 문서를 쓰며 확인한 것 · 확인하지 못한 것

**확인한 것** (전부 실행·실측):

- 공개 주소가 한국어로 뜬다 — 실제로 열어 타이틀 버튼 "출격하기" 확인
- `?playtest=prolific` 은 4분 실험 흐름이다 — 실제로 진입해 확인
- 실험 모드의 동의·무기선택 화면에는 한글이 **0개**다 — DOM 전수 검사
- 데이터 6종에 영어 필드가 없다 — 모듈을 import 해서 확인
- 미번역 375개 (데이터 196 + 코드 179)

**확인하지 못한 것**:

- ⚠️**실험 모드로 실제 전투에 들어간 뒤의 화면.** 개발 브라우저 창이 숨겨지면
  게임 루프가 멈춰(rAF 정지) 캔버스 글자를 관찰할 수 없었다.
  → §4-1의 세 번째 검사(화면 훑기)를 **이사님 실기에서** 돌려야 확정된다.
- 375개라는 수는 **정적 계수**다. 조건에 따라 안 뜨는 문자열이 섞여 있을 수 있어
  **실제 필요 수는 이보다 같거나 적다.**
