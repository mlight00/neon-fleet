## 2. 원인은 두 겹이었다

### (1) 2D 스프라이트가 옛 로켓 그림 그대로

3D는 이사님이 만드신 `v1_model.glb`(실사 총알)를 쓰는데, 2D는 예전 "로켓" 그림 3종이 남아 있었습니다.
같은 탄이 모드에 따라 다른 물체로 보였습니다.

### (2) 더 큰 원인 — 백열 심이 탄을 통째로 덮고 있었다

발칸탄은 화면에서 **폭 3~8px** 로 아주 작게 그려집니다(실측: 기본탄 lv1 = 6.4px, 니들 = 1.1px).
그런데 그 위에 항상 덧그리던 흰 백열 심이 **고정 2.8px 폭 × 탄 길이의 92%** 였습니다.

즉 심이 탄의 **40~100%** 를 덮어, 어떤 그림을 넣든 화면에는 **흰 막대**만 남았습니다.
새 그림으로 바꾸기만 했다면 이사님 눈에는 여전히 달라 보이지 않았을 것입니다.

## 3. 조치

### 3-1. 2D 스프라이트 3종 신규 제작

이사님이 v1 3D 모델 제작에 쓰신 **원본 렌더 이미지**를 그대로 세워 2D로 만들었습니다.
따라서 2D와 3D가 **같은 물체**가 됩니다.

제작 순서 (`E:\workspace\claude\neon-fleet-art\v1-2d\make_vulcan_2d.py`)

1. 검은 배경 → 투명 처리(청록 발광은 반투명으로 보존)
2. 시계방향 90° 회전 — 게임 규약(코가 위, 위로 날아감)
3. 진화 3종 변형 — **형상은 같고 굵기·발광색으로 정체성 구분**
4. 캔버스 긴 변 320px 고정 → 화면에서 차지하는 **길이는 기존과 동일**

| 진화 | 성격(밸런스) | 굵기 | 발광색 | 캔버스 |
|------|------|------|--------|--------|
| needle | 단일·초고속 관통 | 가늘다 | 시안 백열 | 83×320 |
| base | 기본 | 표준 | 청록(원본) | 142×320 |
| storm | 광역·2회 도탄 | 굵다 | 주황 황금 | 168×320 |

굵기는 **기존 스프라이트의 폭 비율을 목표로** 잡았습니다(기존 base 0.447 → 신규 0.444, storm 0.538 → 0.525).
실사 총알의 5.5:1 비율을 그대로 쓰면 폭이 4px가 되어 형태가 뭉개집니다.

### 3-2. 백열 심을 탄 폭에 비례시킴

`js/projectile-visual-spec.js`

```
이전:  { w: 2.8(고정), hRel: 0.92 }
이후:  { wRel: 0.24, wMin: 0.9, wMax: 2.8, hRel: 0.30, yRel: -0.10 }
```

- 폭 = 탄 화면 폭의 24% (최소 0.9px, 최대 2.8px — 옛 고정폭이 이제 상한)
- 길이 = 탄 길이의 30%, 탄두 쪽에 국한 → **팁의 진화색이 심 위에 남는다**

심의 목적은 "탄 위치를 잃지 않게 하는 백열점"이지 탄 자체가 아닙니다. 목적은 지키고 크기만 바로잡았습니다.

### 3-3. 3D도 같은 진화색으로 (이사 지시 "3d도 진화색 맞춰줘")

3D는 `v1_model.glb` 한 벌을 원색 그대로 써서 진화색 구분이 없었습니다. 이제 2D와 같은 색을 냅니다.

**왜 본체를 물들이지 않았나** — 실모델은 자기 텍스처(은색 몸체·황동 탄피)를 가집니다.
instanceColor로 틴트하면 금속이 통째로 물들어 탁해집니다(§G-2에서 이미 겪은 실패:
"원본 주황 탄두가 초록으로 왜곡"). 그래서 **작은 가산합성 발광체 하나만** 얹고 그 파트만 물들입니다.

**왜 탄두가 아니라 탄저인가** — 추적 카메라는 탄을 **뒤에서** 봅니다(탄이 소실점 쪽으로 날아가고,
`placeShots`의 yaw = π − wob로 노즈가 카메라 반대편을 향함). 탄두에 얹어 렌더해 보니
**3색 전부 몸체에 가려 하나도 안 보였습니다.** 탄저에 얹으면 황동 링 안쪽이 진화색으로 채워져 또렷합니다.
실제 예광탄도 탄저의 예광제가 타면서 뒤에서 빛나므로 물리적으로도 맞습니다.

치수는 V1 지오메트리 실측으로 잡았습니다.

| 항목 | 값 | 근거 |
|------|-----|------|
| 노즈 방향 | **−z** | z별 최대 반경 −0.5쪽 0.034 → +0.5쪽 0.094 (→ `rotY: 0`이 맞았음. **미결이던 앞뒤 확인 완료**) |
| 발광 반경 | 0.075 | 탄피 반경 0.094보다 작아 황동 테두리가 남음 (0.095로 키우면 링이 사라져 뭉툭) |
| 발광 z | 0.52 | 탄저면(0.5)을 살짝 넘겨 확실히 보임 (0.44는 탄 안에 묻혀 거의 안 보임) |
| z 눌림 | 0.55 | 탄저에 붙은 납작한 발광판 |

색은 **게임이 이미 쓰는 진화색**을 그대로 받습니다(`b.color` → `shotSpec().color`).
2D 스프라이트의 팁 색도 같은 값으로 다시 만들었으므로 두 모드가 어긋날 수 없습니다.

| 진화 | 색 | 출처 |
|------|-----|------|
| 기본 | `#3ff5e0` | `render.js` `WEAPON_COLORS.vulcan` |
| 니들 | `#5cc8ff` | `weapon-evolutions.js` `EVO_PROJECTILE_COLOR.vulcan_needle` |
| 폭풍 | `#ff8c1a` | `weapon-evolutions.js` `EVO_PROJECTILE_COLOR.vulcan_storm` |

덤으로 3D는 **초진화 색(템페스트 `#ffc23d`·랜스 `#ff5c2a`)까지 자동으로 표현**합니다 —
2D 스프라이트는 3종 고정이라 초진화에서도 같은 그림을 쓰는데, 3D는 색을 개체별로 받기 때문입니다.

드론 예광탄은 2D에 진화색도 백열심도 없으므로, 발광 파트를 `corePart`로 등록해 **예광탄에서는 숨깁니다**
(§G-22 §6과 같은 규칙). 실측으로 확인했습니다.

### 3-4. 곁가지 정합
