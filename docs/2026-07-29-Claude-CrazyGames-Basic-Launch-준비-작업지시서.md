## 0. 의사결정 배경

Neon Fleet의 사업 방향을 다음과 같이 변경한다.

> 큰 매출을 목표로 콘텐츠와 결제 시스템을 계속 확장하지 않는다.  
> 설치 없이 5~15분 정도 즐길 수 있는 무료 웹게임으로 공개하고, 실제 이용자가 생겼을 때 소규모 광고 수익을 기대한다.

## 1. 절대 준수사항

### 1.1 현재 변경 보존

이 worktree에는 Stage 1 분석과 Prolific 흐름을 구현한 미커밋 변경이 있다.

1. 시작 즉시 `git status --short --branch`와 `git diff --stat`을 기록한다.
2. 기존 변경을 사용자의 작업물로 간주한다.
3. `git reset --hard`, `git checkout --`, `git clean`, 강제 덮어쓰기, 기존 변경 되돌리기를 하지 않는다.
4. 일반 GitHub Pages 흐름과 기존 Prolific 흐름을 삭제하지 않는다.
5. 이번 작업과 무관한 밸런스·아트·전투 로직은 수정하지 않는다.

### 1.2 외부 작업 금지

다음 행위는 사용자의 별도 승인이 없으므로 금지한다.

- commit, push, merge, rebase
- `master` 또는 다른 브랜치로 전환
- GitHub Pages 배포
- CrazyGames/GameDistribution/itch.io 계정 생성
- 포털에 파일 업로드 또는 제출
- 광고 SDK·광고 네트워크·외부 분석 스크립트 실제 연결

### 1.3 광고를 아직 구현하지 말 것

Basic Launch에서는 광고와 수익화가 비활성화된다. 이번 단계에서 다음을 넣지 않는다.

- CrazyGames SDK 원격 스크립트

향후 Full Launch에 선정됐을 때 SDK를 붙일 수 있도록 작은 플랫폼 인터페이스를 둘 수는 있지만, 이번 결과물에서는 반드시 로컬 no-op이어야 한다.

### 1.4 자산 보호

- 원본 `assets/` 파일을 삭제하지 않는다.
- 원본 음악·이미지를 파괴적으로 재인코딩하거나 덮어쓰지 않는다.
- 용량 최적화본은 빌드 출력 폴더 안에 별도로 생성한다.

## 2. 공식 제출 기준과 이번 합격선

CrazyGames Basic Launch 기준을 다음과 같이 적용한다.

| 항목 | 공식 요구·참고값 | 이번 합격선 |
|---|---:|---:|
| 영어 | 필수 | 포털 모드에 보이는 한국어 0건 |
| 게임 진입 | Full Launch는 즉시 또는 최대 1클릭 | 포털 모드 최초 1클릭 후 2초 안에 실제 전투 |
| 초기/전체 파일 | SDK 없는 Basic 빌드 ≤ 50MB | ZIP 압축 전 런타임 파일 합계 **50MB 미만** |
| 권장 경량화 | 우수작·모바일 참고값 20MB | 20MB는 목표값이며, 화질·음질 훼손 시 50MB 미만을 우선 |
| 파일 수 | ≤ 1,500 | 1,500 미만 |
| 경로 | 상대경로 | ZIP 내부 절대경로 0건 |
| 브라우저 | Chrome·Edge | 최신 Chrome·Edge에서 정상 |
| 로딩 | 성공작 참고값 10초 미만 | 로컬 캐시 비운 첫 로딩 10초 미만 기록 |
| 평균 플레이 | 성공작 참고값 10분 이상 | 코드로 강제하지 말고, 빠른 재도전으로 2회 플레이를 유도 |
| D1 재방문 | 성공작 참고값 10~15% | 저장·최고기록·해금 유지로 재방문 기반 확보 |
| 플레이 전환 | 성공작 참고값 80% 이상 | 긴 인트로·강제 설명·다단계 선택 제거 |
| 콘텐츠 등급 | PEGI 12 수준 | 과도한 폭력·도박·유해 링크 없음 |

현재 소스 스냅샷은 `docs/`, `tests/`, `dev/`, `.git`을 제외해도 약 **290개 파일 / 92.2MB**다. 그대로 묶으면 SDK 없는 Basic Launch의 50MB 제한을 통과하지 못한다. 실제 참조 에셋만 포함하고 중복 오디오 형식을 정리한 전용 빌드가 필수다.

## 3. 모드 설계

일반 게임, Prolific, 개발 도구를 망가뜨리지 않기 위해 포털 모드를 명시적으로 분리한다.

### 3.1 권장 진입 규칙

로컬 QA용 진입:

```text
http://localhost:8321/?distribution=crazygames
```

실제 포털 자동 감지:

- `location.hostname === 'crazygames.com'`
- 또는 `location.hostname.endsWith('.crazygames.com')`

권장 순수 모듈:

```text
js/distribution-config.js
```

최소 공개 API 예시:

```js
detectDistribution({ hostname, search })
isPortalMode(...)
isCrazyGamesMode(...)
runtimeLanguage(...)
analyticsAllowedForDistribution(...)
```

함수명은 현재 코드 스타일에 맞게 조정해도 된다. 중요한 것은 URL·hostname 판정이 순수 함수여서 테스트 가능해야 한다는 점이다.

### 3.2 모드별 기대 동작

| 모드 | 기대 동작 |
|---|---|
| 일반 URL | 현재 한국어 게임과 기존 동의 기반 GA4 흐름 유지 |
| `?playtest=prolific` | 현재 영어 연구 동의→4분/첫 사망→설문→완료 흐름 유지 |
| 개발 URL | 현재 개발·QA 기능 및 외부 전송 차단 유지 |
| `?distribution=crazygames` | 영어·빠른 시작·일반 사망/재도전·GA4/동의/Prolific UI 없음 |
| CrazyGames hostname | 위 포털 모드와 동일 |

로컬 URL에 `distribution=crazygames`와 `playtest=prolific`가 동시에 있으면 **포털 모드를 우선**하고 Prolific 흐름을 비활성화한다. 이 우선순위를 코드와 테스트에 명시한다.

## 4. 구현 작업

## P0-1. 포털 런타임 분리

### 요구사항

1. `PORTAL_MODE` 또는 동등한 단일 런타임 플래그를 만든다.
2. 포털 모드에서는 `PLAYTEST`가 반드시 false가 되도록 한다.
3. 다음 Prolific 전용 동작을 포털 모드에서 실행하지 않는다.
   - 연구 동의 화면
   - 240초 타이머
   - 첫 사망 즉시 설문
   - 5문항 설문
   - 완료 URL·완료 코드 이동
4. 포털 모드 사망은 일반 게임의 사망·결과·성장·재도전 흐름으로 연결한다.
5. 기존 Prolific 모듈과 테스트 파일은 삭제하지 않는다.

### 분석·개인정보

포털 모드에서는 GA4와 개인정보 동의 UI를 모두 비활성화한다.

- `googletagmanager.com` 요청 0건
- `gtag` 스크립트 삽입 0건
- 분석 동의 배너·모달 0건
- Prolific ID·Study ID·Session ID 접근 0건
- 전체 URL·이메일·이름·기기 지문 전송 0건

CrazyGames Basic Launch의 자체 대시보드 지표를 사용한다. 일반 URL의 기존 동의 기반 GA4 흐름은 그대로 보존한다.

### 플랫폼 수명주기 인터페이스

향후 Full Launch SDK 연결을 쉽게 하기 위해 다음과 같은 작은 인터페이스를 둘 수 있다.

```text
platform.gameplayStart()
platform.gameplayStop()
platform.requestMidgameAd()
platform.requestRewardedAd()
```

이번 단계에서는 전부 no-op이며 외부 스크립트나 네트워크를 부르지 않아야 한다. 광고 요청 함수는 UI에서 호출하지 않는다.

## P0-3. 최초 1클릭 전투 진입

CrazyGames 포털 방문자는 설명을 읽으러 온 것이 아니라 즉시 플레이하러 온다.

### 합격 조건

1. 새 저장 데이터에서 포털 URL을 연다.
2. 최초 화면에서 사용자가 한 번 클릭하거나 탭한다.
3. 그 클릭이 오디오 컨텍스트를 활성화하고 시작 선택도 확정한다.
4. 2초 안에 적이 등장하고 조작 가능한 실제 전투 상태가 된다.
5. 전투 전에 두 번째 확인 버튼·컷신·전체화면 가이드·강제 설문이 나오지 않는다.

구현 방식은 현재 게임 구조를 분석한 뒤 가장 작은 변경으로 결정한다.

권장안:

- 첫 화면에 3개의 시작 무기를 보여준다.
- 무기 카드 클릭 자체가 `선택 + 출격`의 유일한 시작 클릭이 된다.
- 별도의 `START`, `NEXT`, `확인` 단계를 두지 않는다.
- 초보 추천 무기는 시각적으로 표시하되 강요하지 않는다.
- 이동·공격 안내는 전투 위에 비차단형으로 표시하고, 실제 입력 또는 8초 후 사라지게 한다.

첫 화면을 크게 다시 디자인하거나 새로운 스토리·컷신을 만들지 않는다.

## P0-4. 빠른 재도전과 저장 확인

광고형 웹게임에서 중요한 것은 첫 판을 길게 강제하는 것이 아니라 자연스럽게 두 번째 판을 시작하게 만드는 것이다.

### 사망·결과 화면

- 사망 후 1초 안에 결과 요약이 보인다.
- 가장 큰 기본 CTA는 `PLAY AGAIN` 또는 동등한 영어 문구다.
- 같은 무기로 한 번 클릭하면 페이지 새로고침 없이 즉시 다시 시작한다.
- `CHANGE WEAPON`은 보조 선택지로 둔다.
- 기존 성장·해금 보상은 잃지 않는다.
- 광고·보상 두 배·부활 광고 버튼은 아직 표시하지 않는다.

### 저장

기존 저장 시스템을 먼저 감사한다. 이미 만족하는 기능은 다시 만들지 않는다.

반드시 유지할 값:

- 최고 기록 또는 최고 진행
- 해금한 무기·모듈·성장 요소
- 사운드 설정
- 기존 저장 버전과 마이그레이션

새로운 로그인·서버 DB·클라우드 저장·일일 보상·푸시 알림은 만들지 않는다.

- 1077×606
- 1216×684
- 1280×720
- 1366×768
- 1536×864
- 1920×1080

모바일은 이번 제출의 필수 목표가 아니다. 기존 모바일 흐름을 깨뜨리지 않는 회귀 확인만 한다.

- 390×844
- 800×450

### 입력

- 현재 키보드·마우스·터치 구현을 먼저 조사한다.
- 포털 모드의 비차단 가이드에 실제 지원 키만 표시한다.
- 브라우저를 닫을 수 있는 `Ctrl/Cmd+W`를 게임 조작으로 쓰지 않는다.
- `Escape`는 포털 전체화면 종료와 충돌할 수 있으므로 필수 조작으로 강제하지 않는다.
- 방향키가 이미 동작한다면 WASD와 함께 표시한다.
- 방향키가 동작하지 않는다면 전투 로직을 크게 바꾸지 않는 범위에서 안전하게 추가하고 테스트한다.

### 성능

- 첫 실행에서 오류·무한 로딩·검은 화면이 없어야 한다.
- 60Hz와 고주사율에서 게임 속도가 달라지지 않아야 한다.
- 기존 프레임 `dt` 기반 로직을 유지한다.
- 브라우저 콘솔 오류 0건을 목표로 한다.

## P0-6. CrazyGames 전용 패키징

원본 저장소 전체를 ZIP으로 압축하지 않는다. 업로드 전용 빌드 과정을 만든다.

권장 결과:

```text
scripts/build-crazygames-basic.mjs
dist/crazygames-basic/
dist/neon-fleet-crazygames-basic.zip
```

`dist/`를 Git에 포함할지는 기존 `.gitignore` 정책을 먼저 확인한다. 대용량 결과물을 임의로 추적하지 않는다.

### 빌드 스크립트 요구사항

1. 출력 대상은 고정된 `dist/crazygames-basic`이어야 한다.
2. 정리 작업 전 절대경로를 검증해 저장소 바깥이나 저장소 루트를 삭제하지 않는다.
3. `index.html`이 ZIP 최상단에 오도록 한다.
4. 런타임에 필요한 HTML·CSS·JS·폰트·이미지·사운드만 복사한다.
5. `docs/`, `tests/`, `dev/`, `.git`, `tuner.html`, 개발 전용 자료는 제외한다.
6. 모든 런타임 참조는 상대경로여야 한다.
7. 존재하지 않는 파일 참조를 빌드 시 실패로 처리한다.
8. 빌드 완료 시 파일 수와 압축 전·후 용량을 출력한다.
9. 압축 전 런타임 합계가 50MB 이상이면 성공으로 보고하지 말고 빌드를 실패시킨다.
10. 가능하면 20MB에 접근하되, 이미지·음질이 눈에 띄게 깨지는 무리한 최적화는 하지 않는다.

### 용량 최적화 원칙

현재 `assets/sound`에는 MP3와 OGG가 함께 있어 중복 가능성이 크다.

- Chrome·Edge 포털 빌드에 실제 필요한 한 가지 오디오 형식만 포함할 수 있는지 로더를 분석한다.
- 소스의 MP3/OGG 원본은 삭제하지 않는다.
- 빌드 출력에 쓰이지 않는 포맷은 복사하지 않는다.
- 필요하면 포털 출력 전용 저용량 사운드를 생성하되 원본을 덮어쓰지 않는다.
- 이미지도 실제 참조되는 스타일·보스·브랜딩 파일만 포함한다.
- 문자열로 동적 생성되는 경로는 단순 정규식으로 누락하지 말고 명시적 매니페스트 또는 테스트로 보호한다.
- 패키지에서 빠진 에셋 때문에 후반 보스·섹터가 검은 화면이 되지 않도록 대표 후반 진입 QA를 한다.

빌드 ZIP에는 광고 SDK, GA4 측정 ID, Prolific 완료 URL, 비밀키가 없어야 한다.

## 5.2 실제 브라우저 QA

로컬 서버:

```powershell
python -m http.server 8321
```

검증 URL:

```text
http://localhost:8321/?distribution=crazygames
http://localhost:8321/
http://localhost:8321/?playtest=prolific&utm_content=pilot
http://localhost:8321/?distribution=crazygames&playtest=prolific
```

포털 신규 사용자 시나리오:

1. localStorage와 sessionStorage를 비운다.
2. 포털 URL을 연다.
3. 한국어·동의·설문이 없는지 확인한다.
4. 한 번 클릭한다.
5. 2초 안에 실제 전투가 시작되는지 확인한다.
6. 60초 이상 플레이하며 이동·공격·업그레이드를 확인한다.
7. 강제 240초 종료가 없는지 확인한다.
8. 사망 후 결과와 `PLAY AGAIN`을 확인한다.
9. 같은 무기로 페이지 새로고침 없이 재시작한다.
10. 저장값을 확인하고 새로고침 후 유지되는지 확인한다.

포털 네트워크 시나리오:

- 외부 GA4 요청 0
- Prolific 관련 요청 0
- 광고·SDK 요청 0
- 누락 에셋 404 0

회귀 시나리오:

- 일반 한국어 URL이 이전과 동일
- Prolific URL의 영어 동의·타이머·설문·완료 폴백이 이전과 동일
- 개발 URL의 전송 차단 유지
- 기존 모바일 조작 회귀 없음
- 후반 섹터·보스·BGM 대표 진입에서 패키지 에셋 누락 없음
