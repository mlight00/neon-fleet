# §G-46 — 적 피격·격파 3D 연출 사양서

- **작성**: 2026-08-14
- **요청(이사님)**: *"3d 모드에서 적이 피탄되면 빨갛게 번쩍이는데 그것만으로는 효과와 재미가 적다.
  파편이 튀는 3d 이미지 또는 단계별 파괴"* → 이어서 *"피탄될 때와 터질 때 두 군데 모두"*
- **상태**: 설계. **코드 미착수**

---

## 0. 요약

1. **파편 시스템은 이미 있다.** 기함이 맞을 때만 터진다 — 적에게도 붙인다.
2. ⚠️**일반 적은 죽는 즉시 배열에서 사라진다.** 3D가 "죽는 중"을 볼 프레임이 없어,
   격파 연출은 **킬 이벤트 통로**를 따로 놓아야 한다(§3-2).
3. ⚠️**오늘 고친 게 저FPS로 3D가 꺼지는 문제다.** 파티클을 늘리면 그 문제를 되살릴 수 있어,
   **오늘 만든 품질 사다리에 파편 밀도를 물린다**(§4).

---

## 1. 지금 있는 것 (실측)

### 1-1. 파편 리그 — `chase3d-renderer.js:493`

```js
const DEBRIS_MAX = 16;
const debris = new THREE.InstancedMesh(
  new THREE.BoxGeometry(0.30, 0.08, 0.44),
  new THREE.MeshStandardMaterial({ color: 0xe3e6ea, roughness: 0.55, metalness: 0.12 }),
  DEBRIS_MAX);
```

| 속성 | 값 |
|---|---|
| 드로우콜 | **1개** (InstancedMesh) |
| 난수 | **LCG 결정적** (`_rnd`) — `Math.random` 금지 계약 준수 |
| 적분 | 무중력 + 감속 0.985 + 수명 소멸 |
| 할당 | **프레임당 0** — 살아있는 것만 앞으로 압축 |
| 발동 | `squad.flash` 상승 에지 = **기함 전용** |

**이미 잘 만들어져 있다. 새로 만들 것이 아니라 확장할 것이다.**

### 1-2. 적이 받는 것 — 색 플래시뿐

`chase3d-collect.js:32` — `writeDamageColor(slot, hpFrac, readDamageFlash(e, now), boost)`

`hpFrac`(체력 비율)이 **이미 3D까지 흐른다.** 지금은 색에만 쓰인다.

### 1-3. ⚠️일반 적의 죽음 — `main.js:2078`

```js
w.notifyEnemyKilled?.(e); w.entities.splice(i, 1);   // 즉시 제거
```

- 일반 적: **죽는 프레임에 사라진다.** `dying` 상태 없음
- 보스만 `dying` 플래그를 갖는다(`bosses.js:89·300`)

→ 3D가 매 프레임 목록을 읽는 구조라, **일반 적의 격파는 관찰할 수 없다.**

### 1-4. 동시 표시 규모

`b1` 최대 28, 나머지 4~8종 × 8 → **최악 60기 이상**이 동시에 존재할 수 있다.

## 2. 하지 않을 것 — 단계별 파괴 모델

이사님이 "필요하면 단계별 파괴 이미지"를 언급하셨는데, **비용 대비 효과가 나쁘다.**

- 적 GLB는 전부 **1 mesh / 1 primitive** (6개 기함·적 모델 실측 확인) → **부위 분리 불가**
- 단계별로 하려면 모델을 2~3배 제작해야 한다
- 3D는 이미 배포물 최대 폴더 **18.67MB (37.7%)**

→ **§3-3 "누적 손상 표현"으로 대체한다.** 자산 0으로 "망가져 간다"를 표현한다.

## 3. 설계

### 3-1. 피격 파편 (A안)

`DEBRIS_MAX` **16 → 48**. 적 피격에도 같은 방출을 붙인다.

**신호**: 기함과 같은 **상승 에지** 패턴.
`readDamageFlash(e, now)` 가 이미 강도를 준다 — 적별 직전값을 들고 있다가 올라간 프레임에 방출.

```
방출량   3~5개 (품질 단계에 따라 — §4)
초기속도 피격 지점에서 바깥으로, 카메라 쪽으로 약간
크기     적 크기 비례 (대형이 큰 파편)
수명     0.5~0.9초
색       적 종류색 × 0.7 (기체 조각처럼)
```

⚠️**파편은 적 중심에서 낸다.** 실제 명중 지점이 더 좋지만, 그러려면 게임 계층이
탄 좌표를 넘겨줘야 한다 → **후속 과제**(§7-1).

### 3-2. ⚠️격파 연출 — 킬 이벤트 통로가 필요하다

일반 적은 죽는 즉시 사라지므로(§1-3) **3D가 스스로 알 방법이 없다.**

**채택 안**: `onEnemyKilled`(main.js:2389)이 **이미 중앙 킬 알림**이다.
여기서 표시용 링버퍼에 한 건 적고, 3D 렌더러가 매 프레임 비운다.

```js
// main.js — onEnemyKilled 안 (게임 규칙 불변, 알림만 추가)
killFx.push({ x: e.x, y: e.y, size: e.size, kind: e.spriteId, t: now });
```

```js
// chase3d-renderer.js — frame() 안
for (const k of world.killFx.drain()) burstDebris(k, /* 격파 = 피격보다 많게 */);
```

⚠️**대안(적 목록에서 사라진 것을 감지)은 쓰지 않는다.** 화면 밖 이탈·컬링과 구분이 안 돼
멀쩡한 적이 폭발한다.

**격파 연출 구성**:

| 요소 | 내용 |
|---|---|
| 파편 | 피격의 **2~3배** (8~12개), 더 빠르고 넓게 |
| 섬광 | 짧은 발광 구체 1개, 0.15초 (기존 `chargeHalo` 재질 재사용) |
| 잔해 회전 | 파편 각속도 ↑ |

보스는 이미 `dying` + `drawDying` 시퀀스가 있으므로 **이번 범위에서 제외**한다(§7-2).

### 3-3. 누적 손상 (D안) — 자산 0

`hpFrac`이 이미 흐르니, 색 계산에 얹는다.

```
hpFrac 1.0~0.6   변화 없음
hpFrac 0.6~0.3   점진적 그을림 (밝기 ↓, 채도 ↓)
hpFrac 0.3 이하  어두워짐 + 간헐 잔불 파편 (0.5초에 1개)
```

⚠️`instanceColor` 는 **곱셈**이다. 1 미만이면 어두워지고, 1 초과면 밝아진다(§G-39 실측).
그을림은 1 미만 쪽으로만 쓴다.

## 4. ⚠️성능 — 오늘 고친 문제를 되살리지 않는다

오늘 §G-45 로 **저FPS 시 3D가 영구히 꺼지던 문제**를 고쳤다.
파티클을 늘리는 이 작업은 **그 문제를 다시 만들 수 있다.**

→ **파편 밀도를 오늘 만든 품질 사다리에 물린다.**

| `qualityStep` | 피격 파편 | 격파 파편 | 잔불 |
|---:|---:|---:|---|
| 0 (정상) | 5 | 12 | 켬 |
| 1 | 3 | 8 | 끔 |
| 2 | 1 | 4 | 끔 |
| 3 이상 | **0** (색 플래시만) | 2 | 끔 |

**3D가 꺼지기 전에 버틸 단계가 하나 더 생긴다.** 프레임이 모자라면 파편이 먼저 줄고,
그래도 안 되면 해상도가 내려가고, 마지막에야 2D가 된다.

**추가 상한**: 한 프레임에 방출 가능한 파편 총량 12개. 60기가 동시에 맞아도 폭주하지 않는다.

## 5. 지켜야 할 계약

| 계약 | 이유 |
|---|---|
| **게임 규칙 불변** | 판정·피해·보상·스폰 어디도 건드리지 않는다. 2D가 진실, 3D는 읽기 전용 표시 |
| **`Math.random()` 금지** | 전역 난수는 치명타·탄 분산·스폰과 공유된다. 연출이 소비하면 **전투 결과가 바뀐다**(§G-39 계약). 렌더러의 LCG(`_rnd`)만 쓴다 |
| **프레임당 할당 0** | 기존 파편 루프의 압축 방식을 그대로 따른다 |
| **드로우콜 증가 최소** | 파편은 기존 InstancedMesh 재사용(+0). 격파 섬광만 +1 |
| **reduced-motion 존중** | 모션 최소화 설정이면 파편·흔들림 없음(`chase3d-renderer.js:50` 계약) |

## 7. 미결·후속

### 7-1. 명중 지점 정밀화

지금은 적 중심에서 파편이 난다. 실제 탄이 맞은 곳에서 나면 훨씬 좋다.
다만 `recordDamageFeedback(target, target.x, target.y, ...)` 가 **중심 좌표**를 쓰므로,
탄 좌표를 넘기려면 게임 계층 통로를 손봐야 한다. **효과를 본 뒤 판단.**

### 7-2. 보스 격파

보스는 이미 `dying` + `drawDying` 전용 시퀀스가 있다. 이번 범위 밖.
일반 적 연출이 자리 잡은 뒤 같은 언어로 맞추는 것이 낫다.

### 7-3. 검증의 한계

⚠️**개발 브라우저 창이 숨겨지면 게임 루프가 멈춰(rAF 정지) 파편이 실제로 어떻게 보이는지
제가 눈으로 확인할 수 없다.** 자동 테스트로는 "몇 개가 몇 초 살아있는가"까지만 보증된다.
**보기 좋은지는 이사님 실기 확인에 의존한다.**
