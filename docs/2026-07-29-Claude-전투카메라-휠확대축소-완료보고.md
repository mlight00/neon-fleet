## 4. 카메라 모듈 구조 (`js/camera-zoom.js`)

순수 함수만 노출한다. `Math`/상수 외 어떤 전역·DOM·시간도 참조하지 않아 단위 테스트가 결정적이다.

- 상수: `DEFAULT_ZOOM=1.00`, `MIN_ZOOM=0.85`, `MAX_ZOOM=1.30`, `ZOOM_STEP=0.05`, `STEPS_PER_UNIT=20`.
- `normalizeZoom(v)` = `Math.round(v*20)/20` → **정수 격자**로 부동소수 오차 제거(0.95000001 → 정확히 0.95).
- `clampZoom(v)` → 0.85~1.30 범위 강제.
- `safeZoom(v, fallback=1.0)` → `null`·`''`·`NaN`·`Infinity`·비격자 손상값을 안전값으로 복구.
- `stepZoom(v, dir)` → 방향(±1)으로 정확히 한 단계(5%).
- `advanceZoom(cur, tgt, dt, reduced)` → 지수 완화 보간, 시간상수 **τ=0.06s**(≈180ms에 목표 근접, §3.1의 150~250ms 대역), `reduced=true`면 즉시 목표.
- `createCamera(zoom)` → `{current, target, anchorX, anchorY}`.
- 좌표: `worldToScreenX/screenToWorldX`, `worldToScreenPoint/screenToWorldPoint`, `visibleWorldBounds`.

`main.js`는 모듈 상태로 `const camera = createCamera(save.get().view?.zoom)` 한 개만 두고, 렌더·입력이 이를 공유한다.

## 5. 렌더 단계 분리 (`draw()`)

`draw()`에서 카메라 변환은 **`state==='play'` 이고 `camera.current !== 1`일 때만** 적용한다(100%면 변환 자체를 건너뛰어 누적·성능 부담 0).

```
배경(zoneBackdrop·starfield)   ← 카메라 앞, 고정
if (state==='play') anchor = squad(x,y)
if (camActive) { save; translate(anchor); scale(z,z); translate(-anchor) }
  함선·적·탄환·아이템·월드 이펙트(effects.drawWorld)   ← 카메라 안, 확대
if (camActive) restore
전체 화면 플래시(effects.drawScreen)   ← 카메라 밖, 고정
HUD(drawHUD)·일시정지·드래프트·컷신   ← 카메라 밖, 고정
```

- 기준점 = **함대 위치(run.squad.x/y)** → 확대해도 플레이어가 화면에서 제자리.
- `save`/`restore`는 둘 다 `camActive` 게이트로 짝이 맞아 변환 누적이 없다.
- 매 프레임 `camera.current = advanceZoom(current, target, dt, prefersReducedMotion())`로 부드럽게 수렴.

## 6. 이펙트 월드/화면 분리 (`js/entities.js`)

`createEffects()`의 `draw()`를 둘로 쪼갰다.

- `drawWorld(ctx)` — 파편·데미지 텍스트·링·머즐·후광 등 **월드 좌표** 이펙트(카메라 안에서 함께 확대).
- `drawScreen(ctx, w, h)` — **전체 화면 플래시**(`fillRect(0,0,w,h)`) 등 화면 고정 이펙트(카메라 밖).
- `draw(ctx, w, h) { drawWorld(ctx); drawScreen(ctx, w, h); }` — 기존 호출 호환 래퍼.

효과: 피격 섬광이 확대 배율과 무관하게 항상 화면 전체를 덮어 번쩍임 강도가 배율에 따라 달라지지 않는다(테스트 CW-12로 `fillRect(0,0,logicalW,logicalH)`가 `drawScreen`에만 있음을 고정).

## 7. 입력 좌표 역변환 (`js/input.js`)

- `createInput(canvas, logicalW, opts)`에 `opts.screenToWorldX` 콜백을 주입. **input.js는 카메라 모듈을 직접 import하지 않는다**(의존 역전, 테스트 CW-11로 고정).
- 마우스·터치의 화면 X를 기억(`lastScreenX`)하고, **매 프레임** `input.targetX = clampWorld(s2w(lastScreenX))`로 재계산 → 마우스가 멈춰 있어도 확대 보간 중 목표가 정확히 따라온다(튐 없음).
- 키보드 이동(방향키)은 기존 속도(KEY_SPEED=420)·경계 그대로, 마우스 재계산에 덮이지 않는다.
- 콜백 미주입 시 항등(줌 이전 동작과 100% 동일).

**실측 정확도(줌 1.30, anchor=240, 화면 X=360):** `targetX = 240 + (360−240)/1.30 = 332.31`, 실제 산출 **332.31 → 오차 0.00**.

## 17. 알려진 위험과 후속 제안

**환경 한계(검증 방식 고지)**
- Browser pane은 `document.hidden=true`로 requestAnimationFrame이 얼어 라이브 프레임이 자동으로 안 그려진다. §9 스크린샷은 `__NF.step()`으로 강제 렌더해 캡처했다. **실제 애니메이션의 부드러움(체감 감속감)은 이사님이 실제 브라우저에서 육안 확인**을 권장한다(로직·수렴은 단위 테스트로 보장됨).
- OS reduced-motion 토글을 켠 상태의 라이브 확인은 미수행. 즉시 전환 로직·배선은 테스트로 고정.

**설계상 의도(위험 아님)**
- 배율은 `neonFleet.v1`의 `view.zoom` 단일 키로 **모든 모드가 공유**하는 전역 보기 설정.
- 모바일은 두 손가락 핀치 대신 **일시정지 카메라 버튼**으로 조절(핀치는 §14 제외 범위).

**후속 판단 대상(§14 제외 범위 — 이번에 하지 않음)**
- 기함 승급/보스 진입 시 자동 줌, 카메라 흔들림·좌우 패닝, 모바일 핀치, 줌 연동 스폰/난이도 보정. → 수동 줌 손맛을 이사님이 확인한 뒤 별도 단계로 판단.
