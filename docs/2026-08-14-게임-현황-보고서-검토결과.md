# NEON FLEET 게임 현황 보고서 검토 결과

- 검토일: 2026-08-14
- 원문: `docs/2026-08-13-게임-현황-평가용.md`
- 검토 범위: 문서 사실관계, 저장소·테스트, 공개 게임의 첫 진입 흐름, 콘텐츠/재미 검증 수준, 외부 공개 준비도
- 판정: **조건부 승인 — 기술 현황 보고서로는 우수하나, 게임성·흥행 가능성 평가 보고서로 사용하려면 핵심 수정이 필요함**

## 1. 한 줄 결론

NEON FLEET는 기능과 자산이 상당히 갖춰진 **기술적으로 완성도 높은 베타**다. 그러나 실제 외부 플레이어가 재미, 이해도, 재도전 의사를 검증한 데이터가 없으므로, 현재 문서만으로는 “게임이 완성됐다”거나 “공개 흥행 준비가 됐다”고 결론 내릴 수 없다.

가장 큰 위험은 버그 수가 아니라 다음 네 가지다.

1. 첫 60~90초에 핵심 재미가 충분히 전달되는지 모른다.
2. 영어권에 게시할 공개 링크는 한국어 화면인데 영문 게시문은 바로 플레이 가능한 것처럼 안내한다.
3. 모바일 실기 검증 전인데 게시문에 “Works on phones too”라고 썼다.
4. 배포 크기 대부분이 오디오이며, CrazyGames 권장 초기 용량과 모바일 노출 기준을 크게 웃돈다.

## 2. 검토 방법과 확인한 근거

- 원문 전체 검토
- 현재 작업 브랜치, 원격 브랜치와 커밋 상태 확인
- 전체 자동 테스트 독립 재실행
- 코드·테스트·배포물·3D 모델 수량 대조
- 공개 URL에서 타이틀 → 무기 선택 → 첫 출격 흐름 직접 확인
- 기존 실플레이 소감, 25분 캠페인 결과, Prolific/GA4 준비 문서, 커뮤니티 게시 계획 검토
- CrazyGames 공식 기술·게임플레이·성과 기준 확인
- 유사 핵심 루프를 가진 `Arrow a Row`의 공식 Steam 페이지 확인

주의: 실시간 게임 화면은 `requestAnimationFrame`이 계속 도는 Canvas/Three.js 구조라 자동 캡처가 불안정했다. 이는 원문이 밝힌 “실제 입력·프레임 전체를 자동 검증하기 어렵다”는 한계를 다시 확인한 것이며, 사람의 실기 플레이를 대체하지 않는다.

## 4. 반드시 수정해야 할 사실관계

### [P0] 브랜치와 push 상태가 잘못 기재됨

원문은 `master 126fcf1`, “미커밋 0 · 전부 push 완료”라고 적었다. 검토 시점의 실제 상태는 다음과 같다.

- 현재 작업 브랜치: `claude/neon-fleet-analytics-stage1`
- 현재 HEAD: `386c9df`
- `126fcf1`: 커뮤니티 등록 계획 문서 커밋
- `origin/master`: `d31e687`
- 현재 작업 브랜치: 원격보다 **2커밋 앞섬**
- 작업 디렉터리 미커밋 변경: 0

따라서 정확한 표현은 다음과 같다.

> 게임 코드 커밋 `d31e687`까지 원격 반영 완료. 평가용 현황 문서와 커뮤니티 등록 계획 2개 커밋은 로컬 브랜치에만 있으며 아직 push되지 않음. 미커밋 변경은 0.

게임 실행 코드가 누락된 것은 아니지만, 보고서의 버전 추적 정보가 틀리면 이후 검수 기준점이 흔들리므로 수정이 필요하다.

### [P0] 영어권 게시 링크가 한국어 기본 화면을 연다는 점이 빠짐

현재 공개 URL의 기본 모드는 한국어다. 영어는 Prolific 테스트 또는 CrazyGames 포털 모드에서만 켜진다. 따라서 r/playmygame 영문 글에 일반 공개 URL을 그대로 넣으면 영어 사용자가 한국어 타이틀·선택 화면을 보게 된다.

다음 중 하나가 완료되기 전에는 영어권 게시를 보류해야 한다.

1. 일반 공개 URL에 언어 선택/자동 감지 추가
2. 안전한 `?lang=en` 공개 진입 경로 추가
3. 영어 기본인 별도 배포 페이지 제공

Prolific용 4분 테스트 주소는 실험 전용 흐름이므로 일반 커뮤니티 배포용 대체 주소로 쓰면 안 된다.

### [P0] “Works on phones too”는 검증 전 과장 표현

원문은 실제 모바일 기기 검증을 미완료 항목으로 두었지만, 커뮤니티 게시문은 모바일 동작을 확정적으로 표현한다. 둘은 모순이다.

수정 원칙:

- 실제 iPhone 1종, 보급형 Android 1종, 중급 Android 1종에서 터치·성능·오디오 복귀를 확인하기 전에는 문구 삭제
- 검증 후에는 확인한 기종과 브라우저를 내부 기록에 남기고 다시 표기

### [P1] “튜토리얼이 없다”는 표현은 부정확함

공개 게임에는 첫 출격 전에 한 번 나오는 정적 안내가 있다.

- 좌우 이동과 자동 사격
- 청록/자홍 경로의 의미
- POW·크리스탈 성장
- Space·마우스·모바일 번개 버튼 차지

정확한 표현은 다음과 같다.

> 첫 출격 1회성 정적 안내는 있으나, 플레이 중 행동으로 배우는 단계형 튜토리얼과 이해도 검증은 없음.

### [P1] “게임 플레이 스크린샷이 하나도 없다”는 표현은 너무 넓음

저장소에는 다수의 QA 캡처와 비교 보드가 있다. 다만 커뮤니티·스토어에 바로 쓸 수 있는 홍보용 스크린샷과 GIF가 준비되지 않은 것은 맞다.

권장 표현:

> 개발·QA용 캡처는 있으나, 외부 게시용으로 구도·해상도·문구를 정리한 대표 스크린샷 4~5장과 10초 GIF는 미제작.

### [P1] G39 승인의 범위를 분리해야 함

Codex 재검수 승인은 G39 구현 범위에 대한 기술 승인이다. 게임 전체의 재미, 밸런스, 시장성을 승인한 것이 아니다.

권장 표현:

> G39 기술 구현 재검수 승인 완료. 게임 전체 재미·밸런스·흥행성은 별도 외부 플레이 검증 필요.

### [P2] “보스 30종”처럼 읽힐 수 있는 표현을 명확히 해야 함

30은 시각 스프라이트 정의 수다. 현재 일반 캠페인에서 만나는 섹터 보스는 6종이고, 엔드리스 전용 4종과 B22가 추가된다. 시각 정의 수와 실제 플레이 패턴 수는 같은 개념이 아니다.

권장 표기:

> 보스 시각 정의 30개. 공개 캠페인 고유 보스 6종, 엔드리스 추가 보스 4종, B22 상호작용형 특수 보스 포함.

### [P2] 라이선스 “미확인 0”은 사용 조건을 붙여야 함

현재 무료 공개 범위에서 즉시 확인된 차단 항목이 없다는 뜻으로는 사용할 수 있다. 다만 원문 자체가 수익화 시 ElevenLabs 조건 재확인을 요구하므로 “완전 해결”로 쓰면 안 된다.

권장 표현:

> 현재 무료 공개 기준으로 확인된 차단 항목 0. 플랫폼 제출·수익화 전 생성 서비스별 당시 약관과 증빙을 재확인.

## 5. 보고서 구성상 부족한 부분

### 5.1 기술 지표는 많고 플레이어 지표는 0에 가까움

1,107개 테스트는 회귀 버그를 줄이는 강력한 근거다. 그러나 다음 질문에는 답하지 못한다.

- 첫 30초 안에 조작과 목표를 이해하는가?
- 편대가 커질 때 정말 쾌감이 생기는가?
- 선택지가 의미 있다고 느끼는가?
- 어느 시점에 지루해지는가?
- 죽은 뒤 자발적으로 다시 시작하는가?
- 다음 날 다시 돌아오는가?

기존 Prolific/Stage 1 문서에는 15명 테스트 설계가 있지만 실제 참가 테스트는 진행되지 않았고, GA4 측정도 꺼져 있다. 따라서 현 단계에서 게임성 판정은 “검증 대기”가 정확하다.

### 5.2 이전 내부 실플레이의 위험 신호가 최신 상태에서 재검증되지 않음

2026-07-17 섹터 6 완주 소감에는 H2 이후 차지·집중 효과로 적탄을 지우고, 처치 드론으로 회복해 긴장감이 크게 낮아졌다는 기록이 있다. 이후 POW 드롭과 생존·발사체가 수정됐지만, 최신 빌드에서 사람이 다시 끝까지 플레이해 이 문제가 해소됐다는 증거는 없다.

보고서에 다음을 미해결 가설로 남겨야 한다.

> 중후반 빌드 완성 이후 생존과 탄막 제거가 과도해져 긴장감이 붕괴하는지 최신 빌드 실플레이 재검증 필요.

### 5.3 핵심 차별점인 3D 시점의 발견 경로가 약함

공개 타이틀과 첫 안내는 3D 전환 방법을 알려주지 않는다. 플레이 중 200% 이상 확대하거나 일시정지 화면의 카메라 조작을 찾아야 한다. 외부 게시문에서는 3D를 큰 차별점으로 홍보하지만 게임 안에서는 가장 찾기 어려운 기능 중 하나다.

이는 기능 부족이 아니라 **발견성 문제**다. 첫 기함 등급 상승 직후 한 번만 “3D 함미 시점 체험” 버튼을 보여주는 방식이 적합하다.

### 5.4 배포 용량 위험이 과소평가됨

현재 오디오만 약 46.6MiB이고 전체 배포물은 약 49.5MiB다. BGM은 OGG를 먼저 시도하고 MP3를 대체 형식으로 두는데, 두 형식을 모두 배포하고 있어 용량 중복이 크다.

CrazyGames 공식 기준은 다음과 같다.

- SDK가 없으면 총 파일 크기를 초기 다운로드로 계산
- 초기 다운로드 50MB 이하
- 모바일 홈 노출은 20MB 이하
- 공식 성과 가이드는 상위 전환 게임의 전형으로 20MB 미만, 10초 미만 로딩을 제시

현재 빌드는 50MB 한계에 사실상 여유가 없고 모바일 홈 기준은 초과한다. 단순히 “49.5라서 통과”로 보면 안 되며, 포털용 패키지에서 MP3 중복 제거·BGM 지연 로딩·첫 전투 자산 우선 로딩을 검토해야 한다.

공식 근거:

- [CrazyGames 기술 요구사항](https://docs.crazygames.com/requirements/technical/)
- [CrazyGames Basic Launch 성과 기준](https://docs.crazygames.com/resources/basic-launch-metrics/)
- [CrazyGames 첫 화면 로딩 가이드](https://docs.crazygames.com/resources/getting-to-the-first-frame/)

## 7. 최종 판정과 다음 단계

### 판정

원문은 내부 개발 현황과 기술 검수 이력을 정리하는 문서로는 승인할 수 있다. 다만 외부 평가나 “게임 완성도” 의사결정 자료로 쓰기 전, 위 사실관계를 수정하고 플레이어 검증 상태를 문서 맨 앞에 올려야 한다.

### 다음 단계 우선순위

1. 원문 사실관계 수정: 브랜치·push·튜토리얼·스크린샷·모바일·G39 승인 범위
2. 영문 일반 공개 진입 경로 마련
