# NEON FLEET 콘텐츠·재미·흥행 요소 보완 제안서

- 작성일: 2026-08-14
- 대상 빌드: `d31e687` 게임 코드 기준
- 목적: 기능 추가 중심 개발에서 플레이어 재미 검증과 공개 성과 중심 개발로 전환
- 핵심 원칙: **새 콘텐츠를 더 만들기 전에, 이미 만든 강점이 첫 플레이에서 보이고 반복 플레이로 이어지는지 증명한다.**

---

## 1. 제안 요약

NEON FLEET의 문제는 콘텐츠가 부족한 것이 아니다. 이미 6개 섹터, 3개 기본 무기, 다수의 진화·초진화, 공명·교리·키스톤, 22종 적, 여러 보스 패턴, 2D/3D 시점과 21개 BGM까지 있다.

현재 부족한 것은 다음 세 가지다.

1. **핵심 재미의 전달**: 처음 60~90초에 “수학 게이트로 편대를 키우고 기함이 재조립되는 쾌감”이 확실히 나오지 않는다.
2. **반복 동기**: 영구 강화가 주로 숫자 증가라서 다음 날 다시 올 이유와 새로운 플레이 목표가 약하다.
3. **흥행 준비**: 영어 일반 진입, 모바일 실기, 초기 용량, 홍보 화면, 외부 플레이 데이터가 준비되지 않았다.

따라서 권장 순서는 다음과 같다.

> 외부 검증 기반 마련 → 첫 90초 개선 → 8~10분 첫 원정 완성 → 빌드 정체성 강화 → 일일 도전·공유 기능 → 플랫폼 확대

## 2. 현재 게임의 경쟁력

### 2.1 가장 강한 콘텐츠 자산

| 강점 | 왜 재미와 홍보에 유리한가 |
|---|---|
| 수학 게이트 | 한눈에 이득과 손실이 보이고, 선택 결과가 즉시 편대 크기로 표현됨 |
| 편대 성장과 함선 합체 | 숫자 증가가 단순 UI 수치가 아니라 화면 속 물량과 실루엣 변화로 보임 |
| 기함 물리적 재조립 | 빌드가 외형까지 바꾸므로 성장의 보상이 강함 |
| 자동 사격 + 좌우 회피 + 차지 랜스 | 입문은 쉽고 숙련 행동을 한 가지 더 제공함 |
| 주·보조 무기 공명 | 단순 무기 강화보다 조합을 고민하게 만드는 기반이 있음 |
| FLOW/RUSH | 위험한 근접 회피를 보상해 수동 조작의 긴장감을 만듦 |
| 6섹터 항로 선택 | 한 줄 러너에서 로그라이트 원정으로 확장할 수 있음 |
| 2D와 3D가 같은 전투를 공유 | 보기만 바뀌는 독특한 시각적 차별점이며 홍보 영상에 강함 |
| B22 상호작용형 보스 | 단순 체력 덩어리가 아닌 학습 가능한 보스전 가능성을 보여줌 |

이 중 홍보에서 가장 강하게 보여줘야 할 것은 “테스트 1,107개”가 아니라 **작은 편대가 게이트를 통과해 폭증하고, 기함이 재조립되고, 3D 함미 시점으로 전환되는 10초**다.

### 2.2 시장성 있는 핵심 소재

`Arrow a Row`는 자동 이동·자동 사격, 좌우 선택, 파워업, 조력자, 영구 강화를 가진 유사 핵심 루프로 2026-08-14 확인 시 Steam 전체 17,166개 리뷰 중 16,572개가 긍정적이다. 즉 “광고에서 보던 성장 러너를 실제 게임으로 만든다”는 욕구 자체는 검증된 편이다.

다만 이 성공은 NEON FLEET가 자동으로 성공한다는 뜻이 아니다. 오히려 수학 게이트와 자동 사격만 내세우면 기존 게임의 변형처럼 보일 수 있다는 뜻이다.

NEON FLEET가 전면에 내세울 차별점은 다음 네 가지다.

1. 편대가 곧 생존 자원이자 화력이며 함선으로 합체한다.
2. 무기 조합이 기함의 형태와 공격 방식까지 재조립한다.
3. 탄막 회피와 FLOW/RUSH가 단순 숫자 러너를 실제 슈팅게임으로 만든다.
4. 같은 전투를 전술형 2D와 함미 추적형 3D로 볼 수 있다.

공식 참고: [Arrow a Row Steam 페이지](https://store.steampowered.com/app/2495980/Arrow_a_Row/)

## 3. 현재 재미 구조 진단

### 3.1 순간 재미

현재 조작은 이해하기 쉽다. 자동 사격 덕분에 플레이어는 좌우 이동과 위험 회피에 집중할 수 있고, 차지 랜스가 능동적인 공격 타이밍을 만든다. 수학 게이트와 드론 증가는 즉각적인 보상도 제공한다.

다만 다음 위험이 있다.

- 처음에는 무기 선택, 정적 안내, 항로와 전투 규칙이 연속해 나와 핵심 쾌감 전 도달이 늦어질 수 있다.
- 화면에 드론·탄환·피격 효과·HUD가 동시에 많아지면 무엇이 위험하고 무엇이 보상인지 흐려질 수 있다.
- 3D는 차별점이지만 발견하기 어렵고, 처음부터 강제로 켜면 조준과 공간 이해가 오히려 어려워질 수 있다.

### 3.2 성장과 빌드 재미

3개 기본 무기만 보면 적어 보이지만, 주·보조 무기, 공명, 진화·초진화, 교리·키스톤이 겹치므로 실제 조합 기반은 충분하다. 문제는 “조합 수”보다 **플레이 중 정체성이 얼마나 명확히 느껴지는가**다.

플레이어가 다음처럼 한 문장으로 자기 빌드를 설명할 수 있어야 한다.

- “관통 레이저로 일렬 정리하는 빌드”
- “유도 미사일과 폭발로 큰 적을 녹이는 빌드”
- “발칸 연사와 RUSH로 근접 회피하는 빌드”
- “탄막을 지우는 안전형 빌드”
- “함대 수를 빠르게 불리는 성장형 빌드”
- “차지 랜스에 자원을 몰아 보스를 끊는 빌드”

지금은 시스템이 많아도 초보자에게는 카드 설명과 숫자가 쌓이는 것으로 보일 수 있다. 새 무기 추가보다 6개 대표 빌드의 색·아이콘·전투 결과를 분명히 하는 작업이 우선이다.

### 3.3 난이도와 긴장감

기존 내부 완주 기록에는 H2 이후 적탄 제거와 처치 회복이 겹치면서 위험이 크게 줄었다는 소감이 있다. 이후 여러 수정을 했지만 최신 완주 검증은 없다.

여기서 바로 하향 조정부터 하면 안 된다. 다음 세 가지를 나눠 측정해야 한다.

1. 강해져서 재미있는 구간인가?
2. 아무렇게나 움직여도 이겨서 지루한 구간인가?
3. 화면이 복잡해 위험을 알아보기 어렵지만 실제로는 안전한 구간인가?

2번이 확인될 때만 탄막 제거 자원, 회복량, 보스 패턴과 후반 변주를 조정한다. 플레이어가 만든 강한 빌드의 보상감 자체는 남겨야 한다.

### 3.4 반복 플레이 동기

현재 격납고는 시작 드론, 공격력, 연사력, 코인, 자석, 내구도, 순양함 화력의 7개 수치 강화다. 벽을 넘는 데는 도움이 되지만 새로운 경험을 약속하지는 않는다.

흥행과 재방문을 위해서는 “더 강해진다” 외에 다음 원정이 달라지는 이유가 필요하다.

- 시작 교리 또는 기함 특성 해금
- 대체 시작 프레임/외형과 작은 패시브 해금
- 적·보스·무기 기록을 채우는 도감
- 구체적인 도전 목표와 업적
- 매일 같은 조건으로 겨루는 일일 시드 원정
- 결과 화면의 빌드 코드와 공유 카드

초기에는 계정·멀티플레이 없이 로컬 저장과 고정 시드만으로 구현할 수 있는 항목부터 시작한다.

## 6. 우선순위별 보완안

### P0. 콘텐츠 추가를 잠시 멈추고 검증 기반부터 만든다

#### P0-1. 3명 관찰형 파일럿 + 12명 외부 테스트 실행

기존 Prolific/Stage 1 설계를 활용하되, 먼저 3명에게 화면 공유 상태로 플레이시키고 개발자는 설명하지 않는다.

관찰 항목:

- 출격 버튼과 무기 선택을 망설이는가
- 첫 30초 안에 이동·자동 사격·차지를 이해하는가
- 청록/자홍 또는 성장/손실의 의미를 설명할 수 있는가
- 첫 성장 순간에 반응이 있는가
- 첫 피해 원인을 이해하는가
- 3D 기능을 스스로 발견하는가
- 죽은 뒤 다시 누르는가

치명적인 혼란이나 진행 차단은 한 명에게만 발생해도 수정한다. “세 명 이상 같은 말을 해야 고친다”는 규칙은 취향과 밸런스에만 제한적으로 적용한다. 버그, 진행 차단, 멀미, 글자 판독 불가처럼 심각한 문제는 한 사례도 근거가 된다.

파일럿 수정 후 12명 본 테스트를 실행한다. 12명은 대략적인 마찰 패턴을 찾는 표본이지 흥행성을 통계적으로 증명하는 표본은 아니다.

#### P0-2. 영문 일반 공개 진입을 만든다

요구사항:

- 일반 플레이 전체에 영어 적용
- 한국어/영어 선택을 저장
- 브라우저 언어 또는 배포 플랫폼 locale을 사용하고 영어를 안전한 기본값으로 둠
- Prolific 실험 흐름과 일반 영문 플레이를 분리
- 무기, 공명, 교리, 키스톤, 지도, 결과 화면까지 누락 없이 확인

영문 진입이 완료되기 전에는 영어권 커뮤니티 게시를 하지 않는다.

#### P0-3. 포털용 초기 다운로드를 20MB 미만으로 낮춘다

현재 오디오는 OGG와 MP3 대체본을 함께 포함한다. 포털 빌드에서는 다음 순서로 줄인다.

1. OGG/MP3 중복 배포 정책 재검토
2. 타이틀·첫 전투에 필요한 음원만 초기 묶음에 포함
3. 섹터별 BGM과 후반 3D 모델은 해당 섹터 진입 전 백그라운드 로딩
4. 실제 전투가 가능한 시점에 플랫폼 `gameplayStart` 연결
5. 캐시를 끈 상태에서 첫 플레이 가능 시점과 다운로드 바이트 측정

권장 목표는 초기 15~18MB, 첫 플레이 가능 8초 이하다. CrazyGames의 20MB·10초 기준에 여유를 두기 위한 내부 목표다.

#### P0-4. 모바일 실기 검증 후에만 지원을 홍보한다

최소 기기:

- iPhone/Safari 1대
- 보급형 Android/Chrome 1대
- 중급 Android/Chrome 1대

확인 항목:

- 좌우 드래그와 번개 버튼 홀드가 동시에 되는가
- 화면 회전·주소창 변화·안전 영역에서 버튼이 가려지지 않는가
- 백그라운드 복귀 후 오디오가 재개되는가
- 10분 플레이 중 프레임 급락·발열·강제 종료가 없는가
- 글자와 적탄이 실제 화면에서 구분되는가

### P1. 첫 90초를 하나의 완성된 재미 구간으로 재설계한다

#### 권장 첫 플레이 흐름

| 시간 | 플레이어가 경험해야 할 것 |
|---:|---|
| 0~10초 | 한 번의 선택으로 즉시 이동·자동 사격 시작 |
| 10~25초 | 안전한 크리스탈 획득으로 편대가 눈에 띄게 증가 |
| 25~45초 | 청록 성장/자홍 손실 게이트를 시각 행동으로 학습 |
| 45~65초 | 차지 랜스로 단단한 적이나 탄열을 관통 |
| 65~90초 | 첫 기함 등급 변화 또는 미니 절정, 3D 시점 체험 제안 |

원칙:

- 긴 설명창 대신 화면 위 손짓·아이콘·짧은 문장 사용
- 첫 안내는 건너뛸 수 있게 함
- 플레이어가 행동하면 안내가 즉시 사라짐
- 3D는 자동 강제 전환하지 않고 “한 번 체험” 버튼으로 제안
- 첫 90초에 성장, 위험 선택, 강력한 공격, 외형 변화 중 최소 세 가지를 보여줌

#### 왜 3D 안내는 기함 등급 상승 뒤가 좋은가

타이틀에서 3D를 설명하면 조작 정보가 늘어난다. 반면 첫 외형 변화 직후라면 플레이어는 이미 “내 함선이 달라졌다”는 보상을 느끼고 있어 가까이 보고 싶은 동기가 생긴다.

### P1. 첫 원정을 8~10분짜리 명확한 목표로 만든다

공개 6섹터 전체는 첫 방문자에게 길 수 있다. 첫 플레이에는 별도 “첫 원정”을 제공하는 것이 좋다.

권장 구조:

- 8~10분
- 3개의 짧은 전투 구간
- 1번의 항로 선택
- 주·보조 무기 공명 완성
- 기함 등급 상승 1~2회
- 대표 보스 1종
- 완료 후 정규 6섹터 원정과 격납고 해금

기존 개발용 8분 코어 루프의 검증 자산을 설계 참고로 쓰되, 개발 측정 화면을 그대로 공개하지는 않는다. 첫 원정의 목표는 플랫폼 평균 플레이 시간을 억지로 늘리는 것이 아니라, 한 세션 안에 “시작–성장–빌드–보스–결과”를 완결하는 것이다.

### P1. 6개 대표 빌드를 제품 언어로 정리한다

새 무기보다 먼저 주·보조 조합을 6개 대표 정체성으로 묶는다.

각 빌드에 필요한 것:

- 한 단어 이름
- 고유 색/아이콘
- “무엇을 잘하는가” 한 문장
- 전투에서 바로 보이는 시각 변화
- 약점 한 가지
- 결과 화면에서 해당 빌드 이름 표시

약점이 없는 빌드는 결국 모두 비슷한 만능 빌드가 된다. 예를 들어 안전형 빌드는 보스 화력이 낮고, 강타형 빌드는 연사와 화면 정리가 약해야 선택이 살아난다.

### P1. 중후반 긴장 붕괴 여부를 데이터로 확인한다

최신 빌드에서 섹터 1~6 완주 플레이를 최소 3회 기록한다.

- 무기 조합별 피격 횟수
- 적탄 제거 횟수
- 회복으로 되찾은 드론 수
- 보스별 처치 시간
- 플레이어가 손을 거의 움직이지 않아도 되는 구간
- 사망 또는 위기 원인

긴장 붕괴가 확인되면 일반 적 체력만 올리지 말고 다음을 우선한다.

- 안전지대가 이동하는 패턴
- 랜스를 쓸지 회피에 보존할지 선택하게 하는 자원 압박
- 회복과 탄막 제거가 동시에 극대화되지 않는 빌드 제약
- 엘리트의 짧고 명확한 대응 패턴
- 강한 빌드를 시험하는 선택형 위험 노드

### P2. 다시 하고 싶은 이유를 만든다

권장 순서:

1. 원정 결과 카드: 빌드, 최고 편대, 기함 등급, 보스, 점수
2. 빌드 코드 복사와 이미지 공유
3. 도감과 업적
4. 매일 같은 시드의 8분 도전 원정
5. 로컬 최고 기록과 일일 최고 기록
6. 플랫폼 진입 후 선택형 리더보드

일일 출석 보상보다 일일 도전이 적합하다. 접속만 요구하기보다 플레이 방식과 실력을 바꾸는 이유를 제공하기 때문이다.

### P2. 외부 공개용 10초 장면을 먼저 완성한다

#### GIF/영상 구성안

| 시간 | 장면 |
|---:|---|
| 0~2초 | 작은 편대와 위험한 두 게이트 |
| 2~4초 | 유리한 곱셈 게이트 선택, 편대 폭증 |
| 4~6초 | 순양함 합체와 기함 재조립 |
| 6~8초 | 2D에서 3D 함미 시점으로 부드럽게 전환 |
| 8~10초 | 보스 탄막을 차지 랜스로 관통 |

대표 스크린샷 5장:

1. 수학 게이트와 편대 성장
2. 기함 등급 상승 직후
3. 공명/진화 선택과 실제 무기 효과
4. B22 또는 최종 보스의 읽기 쉬운 탄막
5. 3D 함미 시점의 완성된 함대

## 7. 검증 지표와 통과 기준

아래 수치는 NEON FLEET의 다음 작업을 결정하기 위한 내부 기준이다. 보편적인 업계 합격선으로 단정하지 않는다.

### 7.1 3명 파일럿 통과 조건

- 세 명 모두 개발자 설명 없이 첫 전투 진입
- 세 명 중 두 명 이상이 45초 안에 이동·성장 게이트·차지를 이해
- 진행 차단, 글자 판독 불가, 조작 불능 0건
- 피격 원인을 설명하지 못하는 반복 사례가 없을 것

### 7.2 12명 외부 테스트 목표

- 재미 중앙값 4/5 이상
- 조작·목표 명확성 중앙값 4/5 이상
- 다시 플레이 의향 중앙값 4/5 이상
- 4분 테스트 완료율 80% 이상
- 같은 세션에서 자발적 2회차 시작 30% 이상
- “가장 재미있던 순간이 없음” 응답 10% 이하
- 동일한 치명 마찰이 2회 이상이면 P0 수정

### 7.3 공개 플랫폼 목표

- 첫 플레이 가능 시점 8초 이하 내부 목표
- 초기 다운로드 20MB 미만, 가능하면 15~18MB
- 평균 플레이 시간 10분 이상
- 1분 이상 플레이 전환 80% 이상
- 다음 날 재방문 10% 이상을 1차 목표로 설정
- 모바일 10분 세션 강제 종료 0건

CrazyGames의 실제 Basic Launch 평가는 최소 7일 및 500회 플레이를 요구하므로, 소규모 커뮤니티 반응만으로 흥행성을 확정하지 않는다.

아래 문구를 그대로 후속 작업의 시작 지시로 사용할 수 있다.

> NEON FLEET에 새 적·보스·BGM·3D 모델을 추가하지 말고, 먼저 제품 검증 준비 작업을 진행해라.
>
> 1. `docs/2026-08-14-게임-현황-보고서-검토결과.md`의 사실관계 수정 항목을 원문에 반영한다. 특히 브랜치/push 상태, 튜토리얼, 홍보용 캡처, 모바일 미검증, G39 승인 범위를 바로잡는다.
> 2. 일반 공개 플레이에 한국어/영어 선택 경로를 설계한다. Prolific 전용 모드를 재사용하지 말고 일반 영문 플레이 전체 화면의 번역 누락을 검사한다.
> 3. 현재 약 49.5MiB 배포물에서 오디오가 약 46.6MiB를 차지하는 원인을 파일별로 표로 만들고, 포털 초기 다운로드를 20MB 미만으로 낮추는 설계안을 작성한다. OGG/MP3 중복, 지연 로딩, 섹터별 자산 분리를 포함하되 아직 자산을 삭제하지 않는다.
> 4. 3명 관찰형 파일럿 테스트 시나리오와 기록지를 만든다. 개발자가 설명하지 않는 조건으로 첫 90초 이해도, 성장 쾌감, 피격 원인, 3D 발견, 재시도 행동을 기록한다.
> 5. 첫 90초 개선안과 8~10분 첫 원정 설계를 문서로 작성한다. 기존 개발용 측정 모드를 그대로 공개하지 않는다.
> 6. 위 결과물을 먼저 검수 요청하고, 승인 전에는 밸런스 수치와 게임 코드를 변경하지 않는다.

## 11. 최종 제안

NEON FLEET는 “더 만들어야 게임이 되는 단계”는 이미 지났다. 이제는 **덜 설명해도 이해되고, 짧게 해도 강한 보상이 나오며, 한 번 끝낸 뒤 다른 빌드로 다시 하고 싶은가**를 증명해야 한다.

가장 좋은 다음 버전은 적과 보스가 더 많은 버전이 아니라 다음 조건을 만족하는 버전이다.

- 10초 안에 조작 시작
- 45초 안에 편대 성장의 쾌감 경험
- 90초 안에 기함 변화와 3D 차별점 발견
- 8~10분 안에 첫 완결된 원정 경험
- 결과를 보고 다른 빌드로 한 번 더 시작

이 다섯 가지가 실제 플레이어에게 확인되면, 현재의 풍부한 콘텐츠와 높은 기술 안정성이 비로소 흥행 자산으로 연결된다.
