## 3. P1 네 항목: 원인 · 수정 · 검증

### 3.1 차지 랜스 소실 (P1)
- **원인:** `ChargeLance`는 `x`·`baseY`만 있고 `y`가 없어, 일반 `drawProjected`의 `projectObject({x,y})`가 NaN → draw 0회(RC1 재현: `{baseY:660, drawCalls:0}`).
- **수정:** `ChargeLance.drawProjected`에서 발사구(x,baseY)·빔 종점(x,0)·좌우폭 4모서리를 각각 `projectPoint`로 투영해 원근 quad + 발사구 링을 그림. chase-render가 `obj.drawProjected`로 위임.
- **검증:** RC2-01(실인스턴스+mock ctx: draw ≥1, 좌표 전부 유한), RC2-02(발사구 == 투영 기함 발사점 0px), 브라우저(fireLance로 실제 발사 → 220%에서 흰 빔이 기함에 붙어 렌더, 스크린샷 `rc2-220-charge-lance.png`).

### 3.2 편대 전체 3.3배 통짜 확대 (P1)
- **원인:** `drawWorldProjected`가 `Squad.draw()` 전체를 기함 위치 한 점에서 3.3배로 투영 → 드론·순양함·xN·링까지 전부 동일 확대, 드론별 깊이 없음, 기함 묻힘.
- **수정:** `Squad.draw(ctx, projector)`가 `place()`로 드론·유령순양함·호위함·궤도기·기함을 **각자 월드중심으로 개별 투영**(Y가 위인 드론일수록 작고 중앙 수렴). 기함은 `fitFlagship`으로 화면에 들어오는 최대 배율. xN 라벨은 고정 16px·화면 clamp·기함 위, 충전/파워/실드/무적 링은 캡 배율(≤2.2×).
- **검증:** RC2-03(가까운 드론 > 먼 드론), RC2-04(개체별 projectPoint 배치·배선), RC2-07(xN 고정 14~20px·배율 미적용), 브라우저(스크린샷 `rc2-220-pursuit.png`: 기함·순양함이 하단 중앙 최대, 드론 원근 수렴, x18 작게 기함 안 가림).

### 3.3 기함 하단 잘림·HUD 겹침 (P1)
- **원인:** `nearYFrac=0.83` + 3.3배 조합이 짧은 데스크톱 캔버스에서 기함 하단을 자름.
- **수정:** `fitFlagshipScale(p, proj, halfH, top=8, bot=12)` = `min(투영배율, (H-12-p.y)/halfH, (p.y-8)/halfH)` (단순 축소가 아니라 '들어오는 최대 배율'). halfH=함체반경×1.7. 하단 ≥12px 여백 보장.
- **검증:** 실측 1280×720에서 nearY=642, logicalH=774 → 기함 하단 132px 여유. 6개 해상도 전부 기함 전체 프레임 안(§5). 220%가 100%보다 확실히 큼(스크린샷 대비). 하단 집중게이지·상단 HUD 침범 0.

### 3.4 게이트·긴 광선·긴 탄환 끝점 정합 (P1)
- **원인:** 넓은 개체를 개체 중심 uniform scale로 확대 → 좌우 위치 배율(nearLateral×zoom=2.75)과 크기 배율(nearObjScale×zoom=3.3) 불일치 → 게이트 레인 표시와 판정 위치 ~44px 어긋남.
- **수정:** 게이트(GatePair/TriGate)는 레인 rect의 **네 모서리를 각각 projectPoint**로 투영해 원근 사다리꼴 + 고정 글꼴 라벨. 레이저 탄은 `drawLaserStreak`가 시작(x,prevY)·끝(x,y)을 각각 투영. 표시와 입력/판정이 같은 `projectPoint`를 써 정합.
- **검증:** RC2-05(보이는 3레인이 각 선택 조준점 투영을 포함 ≤2px), RC2-06(레이저 스트릭 끝점 == projectPoint ≤2px), 브라우저(게이트 주입 → `rc2-220-gate-alignment.png`: 원근 3레인 사다리꼴이 함대 근거리 평면에 정합).

### 4번째(P2) 화면 밖 위험 경고 위험도 우선
- **수정:** `collectEdgeWarnings`가 죽음·기함 아래로 지나간·위로 멀어지는(vy≤0) 탄을 제외하고, 접근 탄은 TTC(도달시간)·기함 근접 궤적으로 필터, 보스>충돌임박탄>충돌적 순으로 정렬해 방향당 3개 선택(배열 순서 아님).
- **검증:** RC2-08(멀어지는 탄 경고 제외), RC2-09(접근 탄 방향당 ≤3).

→ 카메라 배율은 월드 진행에 영향을 주지 않는다(§9 중단조건 미해당). **방법 주기:** 두 개의 독립 시드 런 A/B 대신, 카메라 무영향을 직접 증명하는 '시점 변경 시 월드 불변 + 정적 참조 부재'로 검증했다(헤드리스에서 시드 재현이 불확정이라 view-독립성 증명을 택함 — 더 직접적).

## 13. 미완료·알려진 한계

- **성능 FPS 미측정**(§7 허용): 헤드리스 rAF 정지로 실측 불가 → 구조적 추론 + NaN 0로 보고, 실측은 미기록.
- **성장 함대 장면은 개발 훅 구성:** §6.3의 15기+ 드론·순양함 2·큰 티어 장면은 자연 진행으로 도달하지 않고 `squad.tier/count/cruisers`를 직접 설정해 스크린샷을 만들었다(정상 진행 아님). 규칙 불변은 §7에서 별도 검증. 일반 새 출격 초반은 자연 진입으로 확인.
- **같은 시드 A/B 형식 대체:** §6의 "같은 시드·입력 300프레임 A/B"는 헤드리스 시드 재현 불확정이라, 대신 '시점 변경이 월드를 바꾸지 않음(스냅샷 동일) + 로직의 카메라 미참조'로 카메라 무영향을 직접 증명(§7). 요구 취지(배율이 월드에 영향 없음)는 충족.
- **공명 레일(railStorm) 빔:** 표준 레이저 스트릭은 끝점 투영, 공명 레일은 1차 구현에서 중심 투영(연결 유지). 극단 원근서 미세 편차 가능 — 후속 개선 여지.
- **RC2-04/07 헤드리스 제약:** Squad.draw가 `document` 의존이라 Node 유닛에서 실행 불가 → 소스 배선 + 수치 투영 + 브라우저 QA로 보완.
- **§9 즉시 중단 조건:** 전부 미해당 — 차지 랜스/레이저 보임, 게이트 표시==판정, 순양함 표시==피격(투영 동일), 기함 안 잘림, 100% 기존과 동일, 카메라가 월드에 영향 없음, 테스트 감소 없음(749→760), 실행 안 한 해상도/미측정 FPS를 통과로 적지 않음.
