## 2. 채택한 계약과 폐기한 안

### 채택

**(가) 단일 투영 계약** — 한 프레임에 투영은 **한 번만** 확정된다.
`update()` 끝(월드 갱신 완료 후) 1곳에서 만들고, `draw`·3D 수집·HUD·경고가 그 스냅샷을 **공유**한다.
`update()` 시작의 호출은 첫 프레임 부트스트랩 전용으로 남겼다.

**(나) 카메라 중심 가로식**
```
chaseX = centerX + (worldX − cameraWorldX) · lateral(depth) · zoom
C0     = lerp(squadX, centerX + (squadX − cameraWorldX)·nearL, chaseBlend)
slope  = lerp(zoom, nearL, chaseBlend)          // nearL = zoom · nearLateral
```
렌더와 입력 역변환이 **이 하나의 affine**을 쓴다.

**(다) 데드존 카메라** — 목표는 **언제나 기함**이고, 데드존이 가르는 것은 **따라가는 속도**다.
밖이면 빠르게(τ=0.12s), 안이면 느리게(τ=0.9s) 복귀한다.
`deadHalf = max(0, visibleHalfWorld − squadMargin)`,
`squadMargin = BAL.squad.laneMargin(30) + SHIP_DEFS[tier].visualWidth × 0.4`.
히스테리시스 6px · dt 기반 감쇠 · `[visHalf, LW−visHalf]` clamp.

> ⚠️**첫 구현은 틀렸고 이사님 실기로 잡혔다.** 데드존 안에서 카메라를 **완전히 정지**시켰는데,
> 그러면 목표가 "데드존 경계에 걸치는 위치"라 `off` 가 정확히 `deadHalf` 로 수렴하고
> 히스테리시스 해제 조건(`|off| < deadHalf − hys`)을 **영원히 만족하지 못한다** — 밴드에 갇힌다.
> 결과: 기함이 화면 28%/72% 에 붙박이고 3D 카메라 트럭 이동(`followX`)이 ±105.8px 로 커져
> 기함이 화면 구석으로 밀렸다. → 목표를 항상 기함으로 두고 **속도만** 가르도록 고쳤다.

**(라) 유한 상단면(finite top plane)** — world y=0이 화면 **안**에 있다(`horizonYFrac = 0.15 ≥ 0`).
차지빔은 거기서 끝난다. 길이는 발사체 깊이 규칙에서 그대로 나온다: `sqy · SCALE_Z`.

**(마) 발사 원점 보정은 투영 입력에** — 보정량이 월드 px이므로 화면 환산은 투영이 한다.

**(바) 가장자리 스크롤 정책 = B** — 카메라를 트랙 안쪽 한계에서 멈춘다(§6 참조).

### 폐기

| 폐기한 안 | 이유 |
|---|---|
| `followFrac` 부분 추종(0.42) | 실효 카메라 위치가 깊이마다 달라 데드존과 공존 불가 |
| `drawLanceAfterglow` (§G-31) | 전제("world y=0은 소실점 너머")가 finite top plane에서 거짓. 게다가 월드 x를 화면 x로 써 104.4px 어긋나 있었다 |
| `LANCE_LEN = 1400` 고정 | 소실점에 빔을 붙여 "무한히 뻗는" 그림을 만들려던 값. 실제 필요 길이(≈40)의 35배 |

| 그리기 좌표계 translate 보정 | 경로마다 배율이 달리 먹는다(2.5D 11.44px 과보정) |
| 소스 문자열 대조 테스트 | 계약이 멀쩡한데 리팩터링·주석에 4회 깨졌다 → 실행 기반으로 교체 |

## 7. 성능 · 할당 · 모바일

- **로직 프레임 시간**: 0.043ms/frame (200프레임 평균, 480×800). ⚠️**3D 렌더 제외값**이다 —
  pane 숨김에서 WebGL이 돌지 않으므로 GPU 비용이 빠져 있다. 절대 수치로 쓰지 말 것.
- **할당**: 이번 변경에 프레임 내 신규 할당 0.
  - 데드존은 상태 객체 **1개**를 모듈 스코프에서 재사용한다(프레임마다 만들지 않는다).

  - ember 적탄에서 `shadowBlur` 제거 — 보스 탄막에서 GPU 비용이 순감소한다.
- **모바일**: **미검증.** 실제 기기 없이 완료를 주장하지 않는다. 뷰포트 360×800 로직 검증만 했다.

## 9. 남은 위험과 상업 라이선스

### 차단 목록 점검 (지시서 §12)

| 항목 | 상태 |
|---|---|
| 음수 horizon으로만 2D/3D 맞춤 | ✅ 아님 — `horizonYFrac = 0.15 ≥ 0` (`G34-HORIZON-FINITE`) |
| **t=0.5 카메라/기함 bbox 미검증** | ⚠️ **부분** — 카메라는 검증(`G34-CAM-*` 5건), **기함 bbox는 미검증** |
| input inverse와 render가 다른 affine | ✅ 아님 — 단일 affine (`ROUNDTRIP` · `DEADZONE-INVERSE`) |
| constant 144 deadzone | ✅ 아님 — 줌·기함 등급에서 동적 산출 |
| raw world 좌표 차지 잔광 | ✅ 아님 — 잔광 자체를 삭제 |
| 2.5D 레이저 / 3D 탄 포구 보정 누락 | ✅ 아님 — 두 경로 모두 적용(`ORIGIN-LASER`, `shotRenderX`) |
| 동시 저장 2건이 모두 200 | ✅ 아님 — `O_CREAT\|O_EXCL` 원자 예약, 6건 동시 → 1×200 / 5×409 |
| 전체 테스트가 dist 잠금으로 실패 | ✅ 아님 — 944/944 |
| 실제 기기 없이 모바일 완료 주장 | ✅ 주장하지 않음 |

### 잔여 위험

1. **기함 bbox 중심오차(t=0.5) 미측정** — 실제 GLB 바운딩이 있어야 정확히 잰다.
   대신 **원점 기준 세로 차이를 계측해 고정**했다(480×800에서 3D 원점 769.8 vs 근거리선 664.0 = 105.8px 아래).
   `G34-CAM-HARDCUT-GAP`이 이 값이 140px을 넘으면 실패하도록 회귀를 잠갔다.
   ⚠️이 105.8px이 **실제로 눈에 띄는 튐인지**는 이사님 실기 확인이 필요하다.
2. **3D 렌더 육안 검증 불가** — pane 숨김에서 WebGL이 돌지 않는다. 빔 길이(35배 축소)·데드존
   추종 감각(τ=0.12s)·새 마름모 경고 시인성은 모두 실기 확인 대상이다.
3. **모바일 미검증** — 실기기 테스트 필요.
4. **성능 수치가 로직 전용** — GPU 포함 측정은 실제 렌더 환경에서 해야 한다.

### 상업 라이선스

**AI 생성 사운드·이미지의 상업 라이선스 증빙은 미제출 상태다.** 자산별 출처·서비스/요금제·생성일·
약관 버전·상업 사용 근거가 확인되기 전이므로, **CrazyGames 제출을 제안하지 않는다.**
