# 스타포지 러시 — 스토리 스틸컷 설계서 (2026-10-01)

이 문서로 알 수 있는 것: 이사님이 정하신 기본 스토리(도시 탈환전)와 보스 격파 스틸컷 9장의 내용·화면·흐름·저장·그림 규격·검사 방법.

## 1. 이사님 결정(2026-10-01)

1. 스토리 큰 방향 = **가. 도시 탈환전** — 고철 군단에게 빼앗긴 도시를 미니 로봇 부대 '포지 레인저'가 되찾는다. 보스마다 도시 한 구역을 지배하고, 쓰러뜨릴 때마다 '고철 군단은 누가, 왜 만들었나'가 드러나다가 최종 보스에서 반전.
2. 스틸컷 9장 줄거리(아래 2장 표) = **승인**.
3. 나오는 때 = **가. 보스 판을 이겼을 때 결과 화면 바로 앞에 세로 전체 화면 1장**, 누르면 결과 화면. 반복 플레이는 느려지지 않게 한 번만. 오프닝은 처음 한 번.
4. 설계(화면·그림·로딩·저장 표시·확인 방법) = **승인** — 그림 없이 화면부터 만들어 올리고, 그림 9장은 크롬 Gemini 로 이어서 만든다.

**보완(구현 중 판단, 이사님께 보고)**: '처음 깼을 때'를 **'그 장면을 아직 안 봤을 때'** 로 센다(저장 = 본 장면 목록). 새 사용자에게는 같은 뜻이고, 이미 3·6·9번을 깬 사용자(이사님)도 그 보스 판을 다시 이기면 놓친 장면을 한 번 본다. 오프닝도 같은 목록으로 — 아직 안 봤으면 다음에 출격할 때(새 사용자는 1번 판) 한 번.

## 3. 화면(render.drawStory)

- 논리 화면 480 × 800 전체에 그림(비율 유지 · 가운데 맞춤 · 넘치는 쪽 자름 = cover). 0.3초 동안 서서히 나타난다.
- 그림이 없거나 아직 못 불렀으면(폴백) 어두운 남색 바탕 + 아래 대사 띠 그대로 — 대사 화면은 늘 나온다.
- 아래 대사 띠: 반투명 어두운 둥근 사각형(x 16 ~ 464). 대사 두 줄은 테두리 글(굵게), 줄마다 화면에 맞는 크기 — **자동 줄바꿈 없음**(어절 쪼개짐 금지). 가장 긴 줄이 띠 안 폭(408px)을 넘지 않는지 Chromium 으로 잰다.
- 오른쪽 아래 '화면을 누르면 계속 ▶'(천천히 깜빡임). 왼쪽 위 표시 이름.
- 입력: 화면 누르기 · Enter · Space · ESC = 계속. 나타난 뒤 0.5초 동안은 입력을 받지 않는다(게임 중 누르던 손가락·연타로 바로 넘어가지 않게). 키를 누르고 있는 자동 반복은 입력이 아니다(기존 규칙).

## 4. 흐름(main.js — 상태 'story')

- **보스 판 승리**: finishRun 이 결과(result)를 다 만든 뒤, 이긴 판 · 포기 아님 · 개발용 판 아님 · 이 판의 컷이 있음 · 그 컷을 아직 안 봄 → 상태 'story'(다음 = 결과 화면). 계속 → 본 장면 목록에 더하고 상태 'result'. 결과 화면 내용·코인·기록은 그대로(정산은 이미 끝났다).
- **오프닝**: startRun(id) 이 판을 시작하기 직전, S0 를 아직 안 봤고 개발용 판이 아니면 상태 'story'(다음 = 그 판 시작). 계속 → 목록에 더하고 원래 판을 시작.
- 배경 음악은 결과 화면과 같은 타이틀 곡(보스 승리 때 finishRun 이 이미 튼다).
- 개발 도구: `__rush3App.showStory(id)`(?dev=1) — 아무 컷이나 띄워 확인·캡처(저장하지 않는다).

## 5. 저장(save.js — v3 키 그대로)

- 최상위 필드 `seenStory`: 본 컷 id 목록(문자열 배열). 정규화 = 아는 id(S0~S8)만 · 중복 제거 · 배열이 아니면 빈 목록. 빠진 키 = 빈 목록(스키마 v 3 그대로 — seenShutter 와 같은 꼴, 옛 코드 탭이 덮으면 컷이 한 번 더 나올 뿐 해 없음).
- 읽기 전용 탭(복수 탭)은 저장하지 않는다(기존 규칙 그대로 — 그 탭에서는 다음에 또 나올 수 있다).

## 6. 그림 불러오기

- 경로 `assets/rush3/story/S0.webp` … `S8.webp`(960 × 1600). 데이터의 `art: true` 인 컷만 불러온다 — 그림 파일이 생기기 전에는 false(404·콘솔 오류를 내지 않는다).
- 보스 판을 시작할 때 그 판의 컷(아직 안 봤으면) 한 장만 미리 불러온다. 오프닝(S0)은 첫 화면이 뜬 뒤 불러온다. 첫 화면을 느리게 하지 않는다(r4.12).
- DOM 이 없는 환경(Node 검사)은 불러오지 않는다(폴백 화면).

## 7. 그림 규격(Gemini — 3단계)

- 지금 게임 그림체(Gemini v9 스프라이트: 굵은 외곽선 · 셀 채색)와 같은 카툰풍 만화 한 칸. 아군 = 아이보리·청록·금색 둥근 미니 로봇, 적 = 검붉고 날카로운 고철 기계.
- 로봇(M-01 정면)과 그 장면의 보스 그림을 참고 이미지로 붙인다. 세로(9:16) · **글자·말풍선 없음**.
- 처리: 가운데 기준 3:5 로 잘라 960 × 1600 WebP. 원본은 `newmode/sprites/story/raw/` 에 보관.
- 그림을 넣을 때마다 `art: true` 로 바꾸고 파일 존재 검사가 통과해야 한다.

## 8. 검사

- STORY-1 데이터: 9장 · 트리거 = 오프닝 + 게임 줄 보스 판 8개(판 종류 표와 일치) · 대사 2줄 · 금지어('중간 보스' · '대물결') 없음 · art true 이면 파일 있음.
- STORY-2 오프닝: 새 저장 → 출격 → 'story'(S0) → 0.5초 전 입력 무시 → 누르면 그 판 시작 · 다음 출격엔 없음 · 개발용 판엔 없음.
- STORY-3 보스 승리: 3번 승리(검사 도구 weakenBosses) → 여운 뒤 'story'(S1) → Enter → 'result'(컷 없이 끝난 판과 같은 결과) · 목록에 S1 · 다시 이기면 바로 결과.
- STORY-4 없음: 패배 · 포기 · 웨이브·강적 판 승리 · 개발용 판.
- STORY-5 화면: 대사 두 줄·계속 안내·표시 이름을 그린다 · 그림이 없으면 그림을 그리지 않고 대사 화면만.
- STORY-6 저장 정규화: 모르는 id·중복·배열 아님.
- 글 폭: 18줄 모두 Chromium 측정으로 띠 안 폭 이하.
