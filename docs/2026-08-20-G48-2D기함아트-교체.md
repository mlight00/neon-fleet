## 2. 걸렸던 함정 (다음에 아트를 갈 때 반드시 읽을 것)

### ⚠️ ① 진짜 크기표는 `SHIP_DEFS_RAW` 가 아니다

`SHIP_DEFS_RAW` 의 `w`/`h`/`nozzles`/`mounts` 를 고쳤는데 **화면이 하나도 안 바뀌었습니다.**
게임이 실제로 쓰는 값은 그 아래에서 다시 계산됩니다.

```js
const visualWidth = Math.round(visualSize * SHIP_ART_ASPECT[t]);
const mounts  = NORMALIZED_MOUNTS[t].map(...)
const nozzles = NORMALIZED_ENGINES[t].map(...)
```

→ 고칠 곳은 **`SHIP_VISUAL_SIZE` · `SHIP_ART_ASPECT` · `NORMALIZED_MOUNTS` · `NORMALIZED_ENGINES`** 네 개입니다.
`SHIP_DEFS_RAW` 는 그림이 안 뜰 때 쓰는 절차적 폴백일 뿐입니다.

### ⚠️ ② "tight 크롭"이 tight 가 아니었다

납품된 `_tight.png` 를 그대로 webp 로 구웠더니 **최대 20%가 빈 여백**이었습니다(A1 은 좌우 각 10%).
원인은 tight 크롭이 **흐린 발광까지 포함해** 잘렸는데, webp 로 구우면 그 옅은 알파가 0 이 되는 것입니다.

여백이 있으면 배가 선언 크기보다 작게 그려지고, 정규화 좌표가 전부 어긋납니다.
→ **1024 원본에서 α≥8 경계로, 좌우 대칭을 유지한 채 다시 잘라** 구웠습니다.

### ⚠️ ③ T2 만 다른 그림을 쓰고 있었다

`shipSprite()` 가 T2 에서만 `H2_BASE_FRAME`(533×768)을 먼저 찾고 A3 는 폴백이었습니다.
그대로 두면 **새로 그린 ARCLIGHT 가 화면에 영영 안 나옵니다.**
그 특례의 근거였던 오버레이(`HULL_FRAME_OVERLAY`)는 §G-9 에서 이미 꺼져 있었습니다. → 특례 제거.

곁가지로, 선로딩 1순위가 `H2_BASE_FRAME` 이었습니다. 플레이어는 **T0 로 출격**하므로
정작 처음 보이는 배가 아니라 나중에나 쓸 그림을 1번으로 받고 있었습니다. → `A1` 로 교체.

### ⚠️ ④ A1·A2 는 기함인 동시에 호위기 원화다

3D 호위 드론·순양함은 **A1·A2 의 알파를 디지타이즈한 반폭 프로파일**로 형상을 만들고,
그 위에 같은 webp 를 텍스처로 씌웁니다. 그림만 갈면 껍데기와 속이 어긋납니다.
→ `A1_HALF`·`A2_HALF`·`tests/fixtures/allies-planform.json` 을 새 그림에서 다시 떴습니다.

### ⚠️ ⑤ 동기 검사가 아무도 안 보는 표를 지키고 있었다

`G43-NOZZLE-MATCHES-2D` 는 2D 와 3D 분사구가 같은 자리인지 검사하는데,
비교 대상이 **`SHIP_DEFS_RAW`**(폴백용)였습니다. 게임이 그리는 건 `SHIP_DEFS[t].nozzles` 인데 말입니다.
즉 3D 가 진짜 2D 와 어긋나도 통과했습니다. → 실물을 보도록 교체.

### ⚠️ ⑥ 좌표를 못박은 테스트는 아트 교체 하루 만에 깨진다

두 건이 깨졌고 둘 다 **옛 그림의 생김새를 좌표로 적어 둔** 탓이었습니다.

| 테스트 | 못박았던 것 | 고친 방향 |
|---|---|---|
| `⚠️EMBER 분사구가 2개다` | 개수 = 2 | **개수 대신 계약**(최소 1개·좌우 대칭·함미 쪽) |
| `AL-00` 원본 정체성 | "행 ~53 에서 최대폭" | **뾰족→불룩→가늘어짐 순서**만 검사 |

### ⚠️ ⑦ `/eval/` 안에서는 그림이 안 뜬다

`sprites.js` 의 경로는 **문서 기준 상대 경로**(`assets/...`)입니다.
`eval/` 하위 페이지에서 그대로 쓰면 `/eval/assets/...` 를 찾다가 404 →
조용히 **SVG 벡터 폴백**이 그려집니다. 하마터면 "새 아트가 이상하다"고 판단할 뻔했습니다.
게임 본체(`index.html`)는 최상단이라 영향이 없습니다.
