- 기준: 브랜치 `claude/starforge-v3`, HEAD `7e6872e`(코드는 `b43e4d1`과 같음). 코드 파일은 읽기만 했고 고치지 않았습니다.
- 증거 스크립트: `B_gate-removal.mjs`(→ `B_gate-removal.json`), `B_hero-exposure.mjs`(→ `B_hero-exposure.json`). 둘 다 `node <절대경로>`로 다시 돌릴 수 있습니다.
- 이 문서의 '로봇'은 판을 만들 때 처음 생긴 유닛(id 1, 처음에는 배열 0번)을 뜻합니다. 지금 코드에는 규칙상 로봇 표시가 없습니다.

## 한 줄 결론

1. 지금 코드는 음수 게이트에서 **로봇이 앞줄 병사보다 먼저 빠질 수 있습니다.** 검토자 권고 규칙(일반 병사 먼저, 감소량 ≥ 전체 병력이면 전멸)과는 "감소량이 `병력 − 로봇 앞 병사 수` 이상이고 병력보다 작은" 구간에서만 결과가 다릅니다. 5명 −3은 같고, 5명 −4는 다르고, 5명 −5는 같습니다.
2. 지옥과 어려움에서는 **모든 적 피해가 병사 체력 2 이상**이라 한 번 맞으면 바로 쓰러집니다. 보통에서도 돌격체 접촉, 정예·광장 보스 겹침, 20·24번 착지 충격은 한 방입니다.
3. 적의 조준점이 부대 중심(= 로봇 자리)이라서, 지금 코드에서는 **로봇 자리가 균등하게 맞을 때보다 적탄을 약 2.7~5.0배 더 맞습니다**(봇 실측). 그래서 지옥 봇 72판 모두에서 로봇이 판 도중에 쓰러졌고, 71판은 다른 병사가 남아 있는 상태였습니다. 그다음에는 병사가 로봇 그림을 이어받았습니다.
4. 적 피해를 호위에게 넘기는 규칙은 정할 것이 많습니다. 대상 선정, 한 STEP 여러 탄, 착지 충격 중복, 손실 집계, 보호막 표시와 소멸 시점이 그것입니다. 이 가운데 착지 충격 중복을 어떻게 정하느냐에 따라 **한 번의 충격으로 잃는 병력 수가 달라집니다.**

## 3. 검토자 권고 게이트 규칙 vs 지금 코드

권고안(`01_GPT_v4_기획검토.md` L43): "게이트의 제거 대상에서 일반 병사를 먼저 고르되, 감소량이 현재 전체 병력 이상이면 메인 로봇까지 제거되어 패배".

지금 코드: `removeUnits(units, k, 'back')`(`squad.js` L185-196)는 먼저 `min(N, k)`명을 정합니다. 그다음 **dy가 큰 순서(뒤부터)로**, dy가 같으면 index가 큰 쪽부터 뺍니다(L190). 로봇은 dy 0이라서 **dy가 음수인 앞줄 병사보다 먼저 빠집니다.**

### 3-2. 랜덤 길 확정 −10 함정

- 함정 행은 `stages.js` L326-332에서 일반 게이트 행으로 만들어집니다. 그래서 규칙이 1번 경로와 **완전히 같습니다.** 추첨 시드 4가 함정을 고릅니다. 3번·12번 판에서 오른쪽 고정 봇으로 돌리면 실제로 `passGateRow`를 지나 −10이 적용됩니다(3번: 33→23명, 12번 보통: 47→37명).

- 기획서 HERO-2 검사안(L636, "병력보다 큰 음수 게이트·함정 −10을 지나도 메인 로봇 1명이 남음")은 권고 규칙과 **반대 동작을 잠급니다.** 권고를 따르면 이 검사는 "감소량 ≥ 병력이면 전멸 = 패배"로 바꿔야 합니다.

## 4. 적 피해를 "호위 병사에게 한 번만 넘기기"를 명세할 때 정해야 할 것

각 항목은 선택지, 건드리는 함수·줄, 결과가 어떻게 달라지는지 순서로 적었습니다. 구현은 하지 않았습니다.

### 4-A. 어디서 가로채는가

| 선택지 | 건드리는 곳 | 결과 |
|---|---|---|
| ① 한 곳(`damageUnit`)에서 | `combat.js` L676-684 | 피해원 4곳(L585 충격, L698 적탄, L712 접촉, L725 보스 겹침)이 모두 지나갑니다. 가장 단순하지만 착지 충격의 `hits` 목록을 모르므로 중복 방지(4-D)를 여기서 할 수 없습니다 |
| ② 호출하는 곳마다 | L585, L697-698, L710-712, L725 | 피해원별로 다른 규칙이 가능합니다(예: 적탄만 넘기고 접촉은 넘기지 않기). 대신 고칠 곳이 4곳입니다 |

### 4-B. 누구에게 넘기는가(대상 선정)

지금 대형은 배열 순서로 자리를 다시 주므로(`squad.js` L57-61, `combat.js` L741), 누가 죽든 다음 STEP의 대형 모양은 같습니다. 달라지는 것은 **사라지는 폭발 표시가 어디에 뜨는지**(`combat.js` L739 `unitLost` 좌표 → `main.js` L755)와 **남는 유닛의 id·hp·사격 위상**(`makeUnit` fireT, `squad.js` L53)입니다.

| 기준 | 새로 만들 곳 / 참고 함수 | 화면에서 보이는 것 |
|---|---|---|
| 로봇에 가장 가까운 호위 | `squad.js` 새 함수(`frontmostUnit` L175-182 옆). dx·dy 거리 | 1링 병사가 사라짐 → 로봇 바로 옆에서 폭발 → "막아 줬다"로 읽힘 |
| 뒷줄(dy 최대, 게이트와 같은 순서) | `removeUnits` L190 비교식 재사용 | **로봇에서 먼 뒷줄이 사라짐.** 검토자가 경계한 "로봇이 맞았는데 멀리 있는 병사가 사라짐" |
| 앞줄(dy 최소) | `frontmostUnit` L175-182 | 접촉 규칙과 같은 기준. 대형 앞쪽 옆 병사 |
| 탄 경로의 다음 유닛 | `hitUnit`/`overlapHits` L140-172에 로봇 제외 옵션 | 물리적으로 "뒤 병사가 막음". 경로에 다른 유닛이 없으면 null → 대체 규칙 필요 |
| 결정적 '무작위' | `combat.js`는 난수 import 금지(L1). STEP 수·id 해시 같은 순수 함수 필요 | 재현성은 지킴. 위치는 임의 |

- 모든 기준은 **hp > 0인 호위만** 골라야 합니다. 같은 STEP에서 이미 쓰러졌지만 아직 정리되지 않은 유닛이 배열에 남아 있기 때문입니다(`combat.js` L160 이전). 기하 검색(`overlapHits` L148)은 이미 건너뛰지만, 거리·줄 기준의 새 함수는 따로 걸러야 합니다.
- 보통 난이도에서는 체력이 결과를 바꿉니다. 적탄·잡졸 피해 1은 병사 체력 2의 절반이므로, 다친 호위(hp 1)를 고르면 쓰러지고 멀쩡한 호위를 고르면 hp 1로 남습니다. 지옥·어려움에서는 모든 피해가 한 방이라 **"몇 명 잃나"는 지금과 같고 "누가 잃나"만 바뀝니다.** 이 부분은 코드 구조에서 추론한 것이고 측정하지 않았습니다.

### 4-C. '한 번만'의 뜻

| 정할 것 | 선택지 | 건드리는 곳 |
|---|---|---|
| 넘긴 피해가 호위 체력보다 클 때(지옥 9 vs hp 2) | 넘친 몫은 버림(연쇄 없음) / 다음 호위에게 또 넘김 | 호위 선택 함수 + `damageUnit` L677 |
| 살아 있는 호위가 0명일 때 | 로봇이 직접 맞음 → 로봇 hp ≤ 0 → 정리 후 0명 → 패배(`combat.js` L810) | 선택 함수가 null을 돌려줄 때의 분기 |
| 시작 병력 1명 판 | 1번 판은 `startUnits` 1이라 보호막 없이 시작, 2번 판은 호위 1명 | `createRun` L128 |

### 4-D. 한 STEP 여러 탄과 착지 충격 중복

| 상황 | 지금 코드 | 정해야 할 것 |
|---|---|---|
| 한 STEP에 적탄 여러 발 | `moveEshots` L688-699가 탄마다 차례로 `hitUnit`→`damageUnit`. 앞 탄으로 쓰러진 유닛은 다음 탄 대상에서 빠짐(`squad.js` L148). 봇 실측: 한 STEP에 적탄 2발 이상 명중한 STEP은 지옥 69번·보통 36번, 원래 로봇과 다른 병사가 같은 STEP에 함께 적탄을 맞은 경우는 봇·난이도 묶음(24판)마다 0~2번 | 첫 탄으로 넘겨받은 호위가 쓰러지면, 둘째 탄은 다른 호위를 고르는지(hp > 0 필터) 명시. 호위가 STEP 도중에 바닥나면 이후 탄은 로봇이 맞음 |
