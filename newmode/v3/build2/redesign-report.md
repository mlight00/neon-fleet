| 닫힌 셔터에 닿은 탄 | — | **흡수**(통과 아님) · 값·`flashT` 불변 · 이벤트 `gateBlock` |

- **1발 = +1 은 그대로**, **병력 비례 숨은 감쇠는 넣지 않았다**, **전투 전체 정리선(`run.z + 650`)도 그대로**다.

### 1-3. 보급 통 차폐·배제 쌍·`skipped` — `rush3/supply.js` · `stages.js`

| 항목 | 전 | 후 |
|---|---|---|
| 통 필드 | `{ …, opened, missed, locked, pads }` | `+ skipped, coverZ, pairId, hint` |
| run 필드 | `missedSupplies` | `+ skippedSupplies`, `+ lastBadGateId` |
| 차폐 | — | `run.z < s.coverZ` 이면 **탄 흡수·내구 불변**, 이벤트 `supplyBlock` |
| `coverZ` 값 | — | **`ceil(commitZ + (s.z − commitZ) × scroll / vzMin)`**, `commitZ = wall.z0 − 60` · `vzMin = 650` |
| `supplyActive` | `opened&&!chain / missed / locked` 제외 | `+ skipped` 제외 (차폐는 **보지 않는다** — 차폐된 통도 충돌 후보로 남아야 흡수가 성립) |
| `passSupply` 순서 | 조기반환 → z 창 → missed → chain locked | **0 → 0-b z 창 → 1 개봉 chain → 2 구조적 불가면 `skipped` → 3 그 외 `missed` → 공통 chain `locked`** |

`structurallyLost(s, run)` = (a) 벽 배제 (b) 차폐 미개방 (c) 쌍 배제. `skipped` 는 '놓침'으로 세지 않고 제안 문구 후보에서도 빠진다.

> **`coverZ` 를 확정선(`wall.z0 − 60`)에 두면 배제가 닫히지 않는다.** 확정 **직전에 발사돼 비행 중인 탄**이 차폐가 걷힌 뒤 반대편 통에 도착한다. 그래서 비행시간을 더한 선에서 연다. 구현값은 `stages.coverZFor()` 가 계산하고 `PAIR-4c`·`STG-4 ④` 가 공식으로 잠근다.
> **⚠ `vzMin`(650, heavy)보다 느린 무기·투사체를 추가하면 네 지점의 `coverZ` 가 전부 부족해져 배제가 다시 열린다.** 그때 `PAIR-4c` 가 먼저 실패한다.

### 1-4. 결과 피드백 — `rush3/advice.js`(신규) · `main.js` · `render.js`

- 신규 **순수 모듈** `rush3/advice.js` — `adviceLine(run, stage)`. `main.js` 에 두면 검사가 셸을 import 해야 하고, `stages.js` 에 두면 배치 데이터가 run 상태를 읽게 되므로 별도 모듈로 했다. `V3-PURE` 대상에 추가했다.
- 우선순위(결정적): ① 마지막 음수 게이트 행의 `hint` ② 놓친(`missed`) 통 중 z 최소의 `hint` ③ 피격 우세 ④ 접촉 ⑤ 성공 문구 / 실패는 `null`(셸이 `missedLine`).
- 결과 화면은 제안을 **크게**, 놓친 것 요약을 **작게** 그린다. 문구 줄바꿈은 **어절(공백) 경계에서만**.
- `missedLine` 은 그대로 `missedSupplies` 만 센다 — `skipped` 는 '놓침'이 아니다.

## 8. 남은 불확실성

1. **자동 검사 통과 ≠ 재미 검증.** 24판 합격선을 다 넘겼지만 사람이 재미있다고 느끼는지는 별개다. 초보 플레이테스트가 필요하다(검수 Q4).
2. **스마트폰 실기 미실시.** 기종·가독성·터치/회전/중단복귀·후반 병력 성능 **전부 미확인**. 특히 480px 폭에서 **통로 안내 표지 좌·우 두 칸이 읽히는지**는 확인하지 못했다.
3. **사격 개시선과 차폐 개방선이 둘 다 점선이고 색이 가깝다**(행 색 / `chainPad` 둘 다 `#35E5FF` 가 될 수 있다). 확정선(회색 실선)과는 구분되지만, 두 점선이 한 화면에 같이 나오는 S3 z3600~3900 구간에서 헷갈리는지는 실기 확인이 필요하다.
4. **Browser pane 의 rAF throttle 때문에 실제 진행 속도로 플레이를 보지 못했다.** 정지 프레임 렌더만 확인했다(§1-5). `localhost:8779/rush3.html` 에서 이사님 직접 확인이 필요하다.
5. **`armZ 340` 은 여전히 출발값이다.** 실측표(초안 §1-7) 근거일 뿐 재미 기준으로 검증된 값이 아니다.
6. **`coverZ` 공식은 `vzMin` 에 매달려 있다.** 650보다 느린 무기·투사체를 추가하면 네 지점의 배제가 다시 열린다. `PAIR-4c` 가 먼저 실패하도록 걸어 두었지만, 그 상황이 오면 초안 §3-3 의 대안(탄에 발사 시점 `z0` 를 실어 `hitSupply` 에서 흡수)으로 갈아타는 편이 안전하다.
7. **S3 에 벽이 3개가 됐다.** 화면에서 반복 요소로 지루해 보이지 않는지, 표지 3쌍이 각각 다르게 읽히는지는 실기 확인 사항이다.
8. **선택 C 의 저울은 병력 상한 안에서만 성립한다.** 상한을 넘는 대군(실측: `plan` 의 기관총 25명)은 통과 +40 을 둘 다 가져간다. `POL-9` 는 이것을 실패시키지 않고 기록만 한다.
9. **S2 의 성적이 전반적으로 내려갔다**(aim 최고 43 → 23, left 38 → 22). 셔터로 첫 게이트 좌 칸 상한을 3으로 낮추고 두 번째 게이트 우 칸을 도전 칸으로 바꾼 결과다. **`plan` 32 는 aim 23 보다 높아 "계획이 이득"은 성립**하지만, S2 전체가 너무 팍팍해졌는지는 사람이 판단할 몫이다.
10. **S1 `left`·`sway` 는 더 이른 실패가 됐다**(peak 4 → 1). 기준선에서도 실패였고 `center` 는 그대로 성공하지만, 입문 스테이지에서 한쪽에 붙어 있기만 해도 16초 만에 끝나는 것이 적절한 학습 경험인지는 실기 확인 사항이다.
11. **`skipped` 연출(흐려지며 뒤로 빠짐)이 '놓쳤다'로 오독되지 않는지** 확인하지 못했다. 현재는 문구 '다른 길' + α 0.22 로만 구분한다.
12. **기록은 코스 버전 2 칸에 새로 쌓인다.** 옛 버전 1 기록은 저장에 그대로 남지만 스테이지 선택 화면에는 나오지 않는다(계약서 7장 그대로). 이사님이 예전 기록을 화면에서 찾으면 "없어졌다"로 보일 수 있다.
