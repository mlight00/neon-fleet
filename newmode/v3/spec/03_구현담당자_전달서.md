# 구현 담당자 전달서 — 스타포지 러시 v3

이 문서는 2026-09-09 사용자의 영상 기반 재기획 요청에 대한 **구현 설계 전달서**다. 이번 작업에서는 게임 코드를 변경하지 않았다. 실제 개발 시작 시 현재 저장소 상태·AGENTS.md·사용자 최신 지시를 먼저 확인한다.

기준 문서:
- 01_스타포지러시_재기획_v3.md
- 02_영상관찰_전체요소대응표.md

아래의 기존 파일 비교는 **2026-09-03 검토 압축본**에 근거한다. 그 뒤 원본 저장소에 이루어진 변경을 확인하지 않았으므로 현재 최신 코드와 동일하다고 가정하지 않는다.

## 1. 구현의 핵심

핵심은 ‘사격형 게이트 + 내용물이 다른 파괴형 보급 + 구성원별 화력 + 짧은 고정 스테이지’다. 기존 무작위 러너에 보급 몇 개만 추가하고 영상과 유사해졌다고 보고하지 않는다.

첫 제작 범위는 다음 3개 기준 스테이지다.

1. 기본 사격·양수 게이트 성장·병사 통·무기 통.
2. 음수에서 양수로 변하는 게이트·분리벽·다른 내구 보급 선택.
3. 큰 군단·연속 증원 장치·도로 정예·결과·같은 배치 재도전.

각 스테이지는 시작부터 결과·재시작까지 완주 가능해야 한다. 그 다음 아레나와 캠페인을 연결한다.

## 2. 기존 모듈의 처리 방향

| 파일 | 방향 |
|---|---|
| rush/main.js | 상태 전환·입력·화면 결선과 규칙 진행을 분리. 진행 함수를 브라우저와 테스트가 공유 |
| rush/gates.js | HP 0 파괴형을 기본에서 제거. signed value의 피격 증가·통과 적용을 구현 |
| rush/track.js | 무작위 단일 buildTrack에서 스테이지 정의를 읽는 생성기로 변경 |
| rush/combat.js | 단일 count 기반 주 화력에서 unit/hero별 사격·체력·대상 충돌로 변경 |
| rush/squad.js | 영웅·병사 대형, 좁은 길 대응, 실제 판정과 표시의 기준 통합 |
| rush/balance.js | 무기·보급·스테이지·영웅·드론별 수치로 구분. 숨은 상수 최소화 |
| rush/render.js | 도로 원근감·분리벽·보급 내용물·변하는 게이트·개별 체력·아레나 지원 |
| rush/save.js | v3 저장 스키마와 기존 저장 호환. 기존 기록을 임의 삭제하지 않음 |
| rush/upgrades.js | 순수 모드와 캠페인 성장 분리. 기존 업그레이드 처리/보존 방침 명시 |
| rush/audio.js | 사격·게이트·통·무기 획득 이벤트 구분. 풀 재사용·음량 상한 |
| rush/daily.js / rng.js | 일일 코스에 버전 포함. 스테이지와 산개/연출 난수 분리 |

보급물·벽·게이트를 적 종류에 끼워 넣는 방식은 피한다. 목적과 충돌 결과가 다르므로 별도 객체 유형으로 두고 공통 충돌 인터페이스만 공유한다.

## 3. 필수 데이터 구분

### 전투 상태

- mode: 순수/캠페인/특수/일일
- stageId, stageVersion, seed
- phase: 도로/아레나/보너스/결과
- squadUnits: 실제 병사별 위치·체력·무기·사격 상태
- heroes: 고정 ID·편성 슬롯·체력·스킬 상태
- squadWeapon: 해당 판 일반 병사 무기
- drone: 장비 상태·자동 스킬·선택적 액티브 상태
- objective: 적 전멸/구출/보스/목표 도달
- rewardState: 최초 보상·반복 보상·보너스 보상 지급 상태

### 게이트

- signedValue: 통과 시 적용될 값
- hitIncrement: 유효 사격당 증가량
- maxValue: 스테이지별 상한
- lane/width/z, passed

게이트의 증감값과 별도 HP를 혼동하지 않는다. 기본 탄은 게이트에 흡수된다. 관통탄과 범위탄이 게이트를 여러 번 올리는지 명시적으로 정의한다. 중복 판정으로 프레임률에 따라 보상이 달라지면 안 된다.

### 파괴형 보급

- kind: 병사/무기/영웅/연속 증원/구출
- durability: 파괴에 필요한 잔여값
- rewardPayload: 실제 보상 종류와 수량
- worldPosition, opened, rewardGranted

통의 ‘내구 100’과 ‘병사 100명’은 전혀 다른 데이터다. 렌더러도 두 값을 구별한다.

### 스테이지

- 도로 구간 형상·통로·분리벽
- 이벤트별 고유 ID·시점/거리·좌표·내구·내용물
- 시작 병력·무기·허용 영웅·드론 규칙
- 예고 구간·보스/아레나 전환 조건
- 적 전체 생성 계획과 승리 조건
- 최초/반복/보너스 보상

같은 스테이지 재도전은 동일한 위치·보급·적·시점을 사용한다. 플레이어의 사격 횟수나 피해로 이후 적 배치가 바뀌지 않게 한다.

## 4. 프레임 내 처리와 충돌

화면 표시 시간과 전투 판정 시간을 분리한다. 고정 시간 간격으로 규칙을 처리하고, 그림만 실제 화면 갱신에 맞춘다.

입력 → 이동/벽 제약 → 발사/스킬 → 투사체 궤적의 가장 가까운 충돌 → 피해/게이트 변화 → 보급 파괴/보상 → 부대 통과 판정 → 승패/단계 전환 순으로 일관된 정책을 둔다. 같은 순간 보급 획득과 사망이 겹칠 때도 우선순위를 정의하고 테스트한다.

단순히 화면상의 y가 일정 값보다 큰지만 검사하지 않는다. 이전 위치와 현재 위치 사이의 이동 경로 및 실제 도형을 사용해 통과 후 뒤늦게 맞거나 빠른 탄이 물체를 건너뛰는 것을 막는다.

삭제/소각된 탄은 같은 프레임 나머지 처리에서도 제외한다. 9/3 압축본의 버스터 소각 탄 피격 오류를 되살리지 않는다. 파괴된 보급은 정확히 한 번만 보상한다. 적 접촉 소멸과 사격 격파를 통계에서 구분한다.

아레나 진입 전에 도로 전용 목표와 위험물을 정리한다. 전환 연출 중 적은 공격하지 않는다. 보너스 진입 시 본전투 승리와 기본 보상을 먼저 확정한다.

## 5. 저장·캠페인·복귀

기존 best·coins·up 데이터를 폐기하지 말고 레거시 기록으로 보존한다. 신규 캠페인은 별도 버전 키를 사용한다. 마이그레이션을 적용하기 전에 원본 저장의 백업 값을 남긴다.

최초 클리어 보상은 stageId+rewardVersion 기준 한 번만 지급한다. 반복 보상은 별도 표를 사용한다. 결과 화면 새로고침·재진입으로 영웅이나 재화가 중복 지급되지 않게 한다.

기지에서 영웅 강화로 들어갔다면 완료 후 그 기지 위치로, 실패 화면에서 강화로 들어갔다면 해당 스테이지 재도전 화면으로 돌아온다. 원래 화면과 편성 상태를 별도 복귀 정보로 보존한다. 팝업·하위 화면·앱 전환 때문에 저장된 복귀 정보가 중간 단계에서 사라지지 않게 한다.

순수 전투 모드에는 기지 성장·영웅 육성 효과가 유입되지 않는다. 일일 코스에는 stageVersion과 날짜/시드를 함께 넣어 서로 다른 규칙의 기록이 섞이지 않게 한다.

## 6. 실제 필요한 검증

- 게이트 −2에 유효탄 3발 → +1, 통과 후 1명 증가. 통과 뒤 추가 탄으로 다시 보상되지 않음.
- 내구 10·보상 2명의 통을 열면 정확히 2명만 합류. 통 숫자를 병력 수로 더하지 않음.
- 한 발이 앞의 통과 뒤의 게이트를 동시에 처리하지 않음. 관통 무기는 별도 명세와 일치.
- 병사 1/10/30명에서 유효 사격량과 명중 분배가 증가. 큰 숫자 표기만 바뀌지 않음.
- 무기 보급 후 일반 병사 무기 변경. 병력 손실로 무기 강등 없음.
- 연속 증원 장치 활성화·발판 생성·발판당 1회 보상·최대 생성량 검증.
- 벽 충돌·벽 끝 합류·가변 통로에서 부대와 탄이 의도대로 이동.
- 아레나 전환 후 상하좌우 이동·자동 조준·보스 추격·승리·원래 화면 복귀.
- 보너스 종료/실패와 무관하게 본전투 기본 보상 유지. 중복 지급 없음.
- 영웅 앞뒤 위치·스킬·사망·기여도 및 드론 기여도를 실제 전투로 확인.
- 실패→강화→재도전에서 동일한 스테이지와 편성으로 복귀.
- 새 저장/기존 저장/손상 저장/저장 권한 불가 상황 대응.
- 화면 숨김·pointercancel·포커스 상실에서 일시정지와 입력 초기화.
- 동일 코스의 30/60/120Hz 표시 환경에서 동일 규칙 결과 검증.
- 실제 모바일에서 전방 숫자·내용물·적의 범위가 읽히는지 확인. 후반 군단 성능 실측.

기존 테스트에 맞추려고 옛 규칙을 남기지 않는다. 반대로 검사 개수만 늘리지 않는다. 새 규칙의 실패 가능성을 다루는 검사를 만들고 실제 게임 진행 함수를 사용한다.

## 7. 요소별 완료 기록

02 문서의 V01~V54를 작업 목록의 ID로 사용한다. 각 항목에 ‘예정/구현/자동검사/실기확인/완료’를 기록하고 근거 스테이지를 연결한다. ‘원작 UI 관찰만 있음’인 V53~V54를 실제 온라인 기능 구현 완료로 처리하지 않는다.

개발 보고에는 다음을 포함한다.
- 이번 버전에서 사용자가 실제로 할 수 있게 된 행동
- 그 행동이 등장하는 스테이지 번호
- 모바일과 PC 확인 결과
- 남은 차이와 아직 확인하지 못한 원작 규칙

‘영상과 비슷해졌다’는 주관적 문구만으로 완료 처리하지 않는다.
